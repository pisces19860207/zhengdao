# 许可豁免登记表（`licenses/EXCEPTIONS.md`）

> 本文件是 `tools/check-license-policy.py` 的**唯一豁免来源**。表里没有的，不算豁免。
> 门禁在 `.github/workflows/ci.yml` 的 supply-chain job 里跑，红了就合不进去。

## 这个表是干什么的

许可政策写在门禁脚本里（改政策＝改脚本＋过评审，不在这个表里放宽）：

| 类别 | 许可 |
| --- | --- |
| **允许** | Apache-2.0 / MIT / BSD-2-Clause / BSD-3-Clause / ISC / Zlib / 0BSD / Unlicense / MPL-2.0 |
| **禁止** | GPL-2.0 / GPL-3.0 / AGPL / LGPL-2.1 / LGPL-3.0 / SSPL（按家族判，任意版本，含 `-only` / `-or-later` / `+`） |
| **未登记** | 既不在允许表也不在禁止表的（EPL / CDDL / BouncyCastle 这类）、POM 里没有许可声明的、本地缓存里查不到 POM 的 |

第一类直接过；第二类和第三类**默认红**，除非在本表里逐条登记。

## 怎么登记一条

在下面的表格里加一行，五列**缺一不可**（空格子那一行不算登记，门禁会红）：

| 列 | 写什么 | 例子 |
| --- | --- | --- |
| 坐标 | `group:name` 或 `group:name:version` | `net.sourceforge.jexcelapi:jxl` |
| 许可 | 实测到的 SPDX id（家族名也行） | `LGPL-2.1` |
| 谁批 | 拍板的人（写名字，不写「团队」） | `项目所有者` |
| 为什么 | 一句话说清为什么非它不可／为什么风险可接受 | `仅聚合分发，不修改不链接` |
| 复查时间 | `YYYY-MM-DD`，到期即失效（过期＝没登记） | `2027-06-30` |

三条容易被忽略的规矩：

1. **不做通配**。没有 `*:*` 这种写法——豁免是逐条签字，不是一次性开关。
2. **写了许可就必须对得上**。实测许可与表里写的不一致（例如依赖升级换了许可），这一行
   自动失效并判红；要改依赖，先改这一行。
3. **到期不会自动续**。过了复查时间，门禁按「没登记」处理——要不要续期是人的决定。
