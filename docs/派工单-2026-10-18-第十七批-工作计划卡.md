## 1. 规格（四件）

### 1.1 A 段：模型能「报计划」

- 新增工具 `update_plan`（**写类但免确认**：它只改自己的计划态、不碰用户文件；若确认制管道强制 CONFIRM，请在交付报告里写明并给出理由）。
- 参数：`items: [{text: string, status: "todo" | "doing" | "done"}]`，**每次调用都是全量覆盖**（模型每完成一条就重发整张表，简单可靠、不用增量补丁）。
- 约束：**最多 8 条**，超了截断到 8 并记一行日志；`text` 单条 ≤ 60 字，超了截断。
- 提示词：要求「接到任务先列 3–8 条计划，每完成一条调用一次 `update_plan`」；**不许把计划写进正文当文本**（正文只留最终答复）。

### 1.2 B 段：落库

- 计划**必须落库**，并且能与某个会话的某一轮对上（否则重启/回看就没了）。
- 首选：`part` 表新增 `kind='plan'`（`payload` 存完整 JSON）——**不改表结构、只加一种 kind**；若一定要新表，必须在交付报告里给出迁移方案与幂等测试。
- 判据：同一轮多次 `update_plan` ⇒ 库里保留**最后一条**（或保留全部，但 UI 只取最后一条，两种都行，交付报告写明）。

### 1.3 C 段：UI 计划卡

- 位置：该轮**顶部**，在工具卡之上。
- 收起态（默认）：一行 `计划 3/5 完成` ＋ 一个可点区域；**正在跑时展开**，跑完自动收起。
- 展开态：每条一行，`✓ 已完成` / `● 进行中` / `○ 未开始`；`text` 原样显示，超长截断可点开。
- 交互：点收起行 ⇒ 展开；再点 ⇒ 收起。**不需要「全部展开」按钮**（与第十六批口径一致，不加新控件）。
- 历史轮：进页面时全部收起（与步骤卡同口径）。

### 1.4 D 段：与现有卡片的关系

- 计划卡**不许**被第十六批的「轮收成一行」吃掉——它属于这一轮的**摘要行内部**，展开后应该在工具明细**上面**。
- 确认卡、问人卡、记忆候选卡照旧永不被收。

## 3. 判据（JVM，纯函数优先）

| # | 判据 | 断言 |
|---|---|---|
| J1 | 工具注册 | `update_plan` 出现在工具表；参数校验拒绝 `items` 为空 / 超 8 条（截断）/ `text` 超 60 字（截断） |
| J2 | 全量覆盖语义 | 先 5 条、再 3 条 ⇒ 计划表是 3 条（不是 8 条合并） |
| J3 | 勾选只增不减 | 状态序列 done → doing 非法（必须保持 done，或明确报错；二选一，测试写死） |
| J4 | 落库可回读 | 写入后按 sessionId＋轮次读回，内容逐字一致 |
| J5 | 收起/展开 | 正在跑 ⇒ 展开；跑完 ⇒ 收起；点一次翻转一次 |
| J6 | 历史会话 | 重启进程后从库恢复，历史轮默认收起 |
