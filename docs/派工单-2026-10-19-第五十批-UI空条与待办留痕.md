## 1. 任务 A：SessionBar 空态整体不渲染

**改法**：
- 在 `BaopuSessionBar.kt` 抽出纯函数（JVM 可测）：
  ```kotlin
  internal fun sessionBarVisible(
      state: RunState,
      interruptedStep: Int,
      hasSession: Boolean,
      notice: String?,
  ): Boolean = (interruptedStep >= 0 && !busyState(state) && hasSession) || !notice.isNullOrBlank()
  ```
  `busyState` 可保持 private（同文件内调用），或一并 internal。
- 组合函数里：`if (sessionBarVisible(state, interruptedStep, hasSession, notice)) { Surface(...) { ... } }`。**内部两个 if 保留**，行为不变。
- 不加动画、不加占位、不改颜色。

**测试（先红）**：
- `SessionBarVisibilityTest`（纯函数）：全空 ⇒ false；有中断且非 busy 且有会话 ⇒ true；busy 时中断 ⇒ false；无会话时中断 ⇒ false；notice 非空 ⇒ true；notice 全空格 ⇒ false。
- 源码门禁（照项目既有形态门禁写法）：`BaopuSessionBar.kt` 里 `Surface(` 必须出现在 `if (sessionBarVisible(` 之后（证明真的用上了，不是只加了个函数）。
- 负例：把 Surface 改回无条件 ⇒ 门禁红；把谓词改回 `true` ⇒ 谓词用例红。

**验收**：抱朴页在「无中断、无 notice」时，顶条下方不再出现那条 16dp 灰条；有中断/notice 时与改前一模一样。

## 2. 任务 B：pendingNote 留痕（接上现成组件）

**改法**：
- 只删 `pendingNote` 自己的 8 秒 `LaunchedEffect`（`BaopuScreen.kt:254-258`）。**`libraryNote` / `skillNote` 的两个 `LaunchedEffect` 一行不动**（见第 3 节）。
- 把 `BaopuScreen.kt:488-496` 的裸 `Text` 换成已写好的组件：
  ```kotlin
  controller.pendingNote?.let { note ->
      BaopuIntrospectionNote(
          text = note,
          onDismiss = { controller.clearPendingNote() },
      )
  }
  ```
- 不新增字符串；不改控制器；`pendingNote` 的写入点不动。

**测试（先红）**：
- 源码门禁 1：`BaopuScreen.kt` 的 `pendingNote` 分支里不得出现 `delay(8_000)`。
- 源码门禁 2：`BaopuIntrospectionNote(` 调用必须带 `onDismiss`，且 `onDismiss` 里调 `clearPendingNote()`。
- 负例：把 `delay(8_000)` 加回 pendingNote ⇒ 门禁 1 红；把 `onDismiss` 去掉 ⇒ 门禁 2 红。
- 若能做到状态层验证更好（例如把「哪类 note 自动清」抽成纯函数并测），做不到就在报告里写明原因，不能只改代码不验。

**验收**：错误产生后 60 秒仍在；点 `×` 立即消失；新会话仍会清空；成功类提示（libraryNote/skillNote）行为不变。
