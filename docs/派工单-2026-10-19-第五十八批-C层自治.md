## 0. 政策（按蓝总管建议）

| 对象 | 自治？ | 约束 |
|---|---|---|
| 项目技能正文 `技能/<名>/SKILL.md`（C 层） | ✅ 自动写/改/归档 | 写前备份、每次改动**追加一条变更记录**、可回滚上一版；不再出提案卡 |
| 项目技能索引行 `【技能】…`（在 C 人设文件里） | ✅ 自动增删 | **只许改索引行**，同文件其他条款一个字节不动 |
| C 人设正文（非索引的行为规则） | ⚠️ **追加-only** | 只许在末尾追加新条款；改/删既有条款仍走提案＋确认 |
| B 全局人设 / A 内核 | ❌ | 保持只读/设置页，现有拒写文案不变 |

## 1. 实现要点

1. **PersonaGuard 分级**：项目技能文件与 C 层「索引行编辑」放行；C 人设正文的**修改/删除**仍拒；全局层一切不变。拒绝文案要区分「全局/人设正文不允许」与「允许但需要追加」。
2. **SkillStore**：项目技能自动写入路径（写前 `.baopu-bak` 备份，沿用现有 backup 机制）；写入后更新索引行（复用现有 `SkillRules` 的索引编辑，不要另写一套）。
3. **变更记录**：每次自动改动写一条 `技能/_变更.jsonl`（或等价旁挂文件）：`ts / scope / skill / action(write|update|archive) / beforeSha / afterSha / reason`。坏了当空表，不许让设置页崩。
4. **回滚**：设置页技能行已有「恢复上一版」——确认它能覆盖本批自动写入的备份；C 人设追加的 diff 至少能在设置页看到（只读展示即可）。
5. **提案卡**：C 层技能类提案不再产生（或产生但自动采纳并标注「自动」——二选一，报告写清）；**记忆提案保持原样**。

## 2. 验收

- 行为（JVM，假根目录）：项目技能自动写成功且备份在；全局技能写入仍被拒；C 人设追加成功、改/删既有行被拒（文案含「只能追加」）；索引行增删后其他字节不变（逐字节比对）。
- 源码门禁：`PersonaGuard` 的放行集合只含项目技能与 C 索引编辑；A/B 路径零变化；自动写入必须走备份。
- 变更记录：一条写入 ⇒ `_变更.jsonl` 多一行且字段齐全；坏 JSON 不影响技能列表。
- 全量单测 0 失败 0 错误；lint 预算不升。
- 真机（可选）：抱朴写一条项目技能 → 不再弹提案卡、索引出现、设置页能恢复上一版。
