## 一、用户交办（逐字）

> 「hermes 自己下载的那个浏览器工具也是要保留的，虽然没有也可以用，但是有的话hermes是可以用的，我试过了。环境环境就绪检测动态卡又回到了之前的那个依赖环境是好的但是还是会出现红叉的情况。」

拆成两件：① 修首页「环境就绪」动态卡里 `Hermes 依赖环境` 的红叉误报；② 任何清理都**不许删** hermes 自己下载的浏览器工具。

## 二、① 依赖环境红叉误报

### 2.1 怎么定案的（App 自证）

宿主侧判定在 `app/src/main/java/com/example/zhengdao/terminal/HermesEnv.kt` 的 `inspect(root: File)`；
真机那套目录布局单测造不出来，所以临时在 `inspect()` 里加了一行「只在 `!ok` 时打」的 `RunLog.log`，
把每条判据的原始读数写进 `Download/证道/logs/zhengdao-log.txt`。真机回读（2026-10-11 23:05:05）：

### 2.2 改了什么

| 文件 | 改动 |
|---|---|
| `app/src/main/java/com/example/zhengdao/terminal/HermesEnv.kt` | `venvUsable(env: String?, root: File)`：**去掉锁文件要求**，只留「guest 视角 + `venv/pyvenv.cfg` 在」；`ok = anyRecord && !brokenRecord && !sourceLockMissing`（去掉 `stale == 0`）；`stale > 0` 改成 detail 里的提示「依赖环境记录有效（另有 N 个更新中断留下的标记文件，可一键清理）」；`canRepairOnHost` 的 `stale > 0 -> true` 不动；**诊断日志保留**（只在 `!ok` 时打） |
| `app/src/main/java/com/example/zhengdao/ui/SettingsEnvActivity.kt` | 按钮条件由 `st != null && !st.ok && st.canRepairOnHost` 放宽到 `st != null && st.canRepairOnHost`，文案按情形切「一键修正记录」（坏了）/「清理更新标记」（只是残渣） |
| `app/src/test/java/com/example/zhengdao/terminal/HermesEnvTest.kt` | 新增 `新版布局的代目录没有 uv_lock 也算好环境`、`venv 里没有 pyvenv_cfg 才算坏环境`；`更新中断留下的标记可一键清理_记录本身不动` 里 `assertFalse(before.ok)` → `assertTrue(before.ok)`（并写明理由） |

### 2.4 没验的

- **没有点「清理更新标记」**：那会真的删掉用户 guest 里那条 `.hermes-update-in-progress.lock`。改动本身有单测
  `更新中断留下的标记可一键清理_记录本身不动` 钉住（只删标记、`facts.json` 逐字不动）。
- **「在终端里修复」这条路没重跑**：本轮不涉及修脚本正文（`app/src/main/res/raw/hermes_env_repair.sh` 未改）。
- 首页那 11 项里其余各项**只是顺带看到 11/11**，未逐项复核。

## 三、② 浏览器工具保留

### 3.1 它在哪（同一行真机诊断日志）

`~/.hermes/tools/` 下：**`agent-browser-0.26.0-linux-arm64`（驱动）＋ `chromium-1208`（浏览器本体）**；
`~/.cache` 里只有 `pip` ⇒ 浏览器不在 cache 里，确实归 hermes 工具目录管。

### 3.2 改了什么

| 文件 | 改动 |
|---|---|
| `app/src/main/java/com/example/zhengdao/terminal/StorageAudit.kt` | 新增 `PINNED_TOOL_NAMES = listOf("chromium", "agent-browser")` 与 `ToolKind.PINNED`（`note` =「hermes 的浏览器工具（agent-browser + chromium 一套）：用户点名保留，不提供清理」）；`OPTIONAL_TOOL_NAMES` 由三个收窄为 `listOf("cua-driver")`；`removable = kind == ToolKind.OPTIONAL` 不变 ⇒ 浏览器工具**不再进任何可清项** |
| `app/src/main/java/com/example/zhengdao/ui/SettingsStorageActivity.kt` | 清理弹窗文案改写：只删 `cua-driver`，并写明「浏览器工具（agent-browser / chromium）不在删除范围内——有它 hermes 才能开网页，保留」 |
| `app/src/test/java/com/example/zhengdao/terminal/StorageAuditTest.kt` | 四条用例改口径（分类断言 → `ToolKind.PINNED`；可清项改用 cua-driver；`清理只删可选工具，浏览器工具与 ffmpeg 原样留在原地`；幂等用例样品目录换成 cua-driver） |

### 3.3 真机读数（设置 → 存储与缓存明细）

| 目录 | 修前 | 修后 |
|---|---|---|
| `chromium-1208` | 600 MB · **可清** | 600 MB · **保留** |
| `agent-browser-0.26.0-linux-arm64` | 9 MB · **可清** | 9 MB · **保留** |
| `cua-driver-0.21.0-linux-arm64` | 80 MB · 可清 | 80 MB · **可清**（桌面自动化仍可清，**待用户点头**） |
| `ffmpeg-9.0.1-linux-arm64` | 328 MB · 保留 | 328 MB · 保留（E-092 起就是必需包） |

### 3.4 没验的

- **没有点「清理可选工具」**：点了会真删 `cua-driver`（80 MB）。分类与删除范围由单测钉住
  （七目录现场：只删 cua-driver 1 项、1 MB，chromium / agent-browser / ffmpeg / python / uv / 未归类目录全在）。
- **`cua-driver` 要不要也留**：这一条是我自己的判断（桌面自动化能力，删了要用时得 `hermes pm install`），
  **用户没表态** ⇒ 已写进汇报里问。
