## ① 首启权限合并成一页

**改了什么**：新增 `app/src/main/java/com/example/zhengdao/ui/PermissionSetupScreen.kt`（`object PermissionSetup` `:60-147`，
判据 `shouldGuide = !guided && !storageGranted` `:146`）；`app/src/main/java/com/example/zhengdao/MainActivity.kt`
（`permissionSetupPending` `:112-117`、原系统请求包进 `if (!permissionSetupPending)` `:119-154`、
删掉 `MANAGE_EXTERNAL_STORAGE` 的 AlertDialog `:143-169`、导航 `:331-341`、路由 `:425-440`）。

**怎么验的**：`adb shell pm revoke com.example.zhengdao android.permission.{READ,WRITE}_EXTERNAL_STORAGE`（`granted=false` 已核）
→ `am force-stop` → `am start`，取证用 `uiautomator dump`（文本逐字）：

- 首启进「权限」页：标题**权限**；正文「证道要读写你的文件、在清理完成时给你提示，需要下面几项权限。可以逐项点开授权；也可以稍后再设（设置 → 权限里随时能改）。」
  - `存储读写（共享存储 /sdcard）` → **未授权** ›
  - `所有文件访问（可选 · 主路径）` → **已开启** ›（本机系统返回 true；即使 false 也不参与就绪判定）
  - `通知` → **已授权** ›
  - `网络访问` → **自动授予**（无 ›，符合"`onClick=null` 的行不画箭头"）
  - 底部按钮 = **稍后再说**，下方小字「『存储读写』是必需项，现在也可以先进去。」
- 点「存储读写」**整行** ⇒ 起系统对话框（前台 = `com.android.permissioncontroller/.permission.ui.GrantPermissionsActivity`）：
  「是否允许"证道"访问此设备上的照片、视频、音乐、音频和其他文件？」/「禁止后不再提示」/「始终允许」。
- 点「**始终允许**」⇒ 系统侧 `READ_/WRITE_EXTERNAL_STORAGE: granted=true`，**页面就地刷新**：该行变 **已授权**、底部按钮变 **完成，进入证道**（回执里重读系统状态这条路径为真）。
- 点「完成，进入证道」⇒ 落到首页（`环境就绪` / `Android 16 · arm64-v8a · Debian 13.7 已安装`）。
- **边界（只引导一次）**：再撤权限 + 冷启动 ⇒ **引导页不再出现**，而是直接弹系统对话框
  （走的是本次保留的"已引导过仍缺权限"冷启动补漏分支）⇒ `KEY_GUIDED` 已落盘、"只引导一次"为真。

**没验的**：本机是**升级**场景（靠 `pm revoke` 造出"未授权"态），没有在从未安装过的新机上跑首启流程；
`guided` 标记是**间接**验证的（行为符合，release 包不可 `run-as`、读不到 prefs 原件）。

## ② 终端长按「更多」菜单

**改了什么**：`app/src/main/java/com/example/zhengdao/TerminalActivity.kt` —— ID 103「重载字号」整块删除并注释写明 ID 不复用（`:920-922`）；
菜单文案「浏览器搜索选中文字」→「**搜索选中文字**」（`:933-935`）；选中文字搜索改走 `openWebSearch()`（`:984` 起，先 `Intent.ACTION_WEB_SEARCH` + `SearchManager.QUERY`，
`runCatching{startActivity}.isSuccess` 才返回，否则回落原 bing URL）。

**验到的**：
- **代码复核**：菜单三项 = `搜索选中文字` / `清屏` / `重置终端`（`TerminalActivity.kt:935-938`），**没有**「重载字号」。
- **构建门禁**：`assembleDebug` + `assembleRelease` 均成功；单测 **66 suite / 602 例 / 0 失败 / 0 错误 / 1 跳过**。
- **系统侧（真机实测）**：`adb shell am start -a android.intent.action.WEB_SEARCH --es query zhengdao`
  能解析（落到 `com.hihonor.android.internal.app/.HwResolverActivity`）⇒ 这个 action 在本机可用；
  ⚠️ 本机**没设默认搜索 App**，所以会先弹一个选择器（勾"始终"即可固定）；`openWebSearch()` 发的正是同一个 action，
  `startActivity` 不抛异常 ⇒ **不会**回落到写死的 bing URL。

**没验的（诚实标注）**：**菜单本体没截到图**。该菜单的入口是 Termux 文本选择工具条的「⋮ MORE」，
而 adb 合成手势（`input swipe` 原地长按 1–2 s、`input motionevent DOWN/UP`、拖动选择）在本机都没能唤起选择模式；
真实手指长按应可复现。复现步骤：终端里长按选中任意文字 → 选择工具条点「⋮」→ 出现「终端操作」菜单。
另：**回落分支（设备上没有 App 能处理 `ACTION_WEB_SEARCH`）本次没有触发条件，未验**。

**验到的（真机）**：

- 点该行 ⇒ 前台 Activity = `com.example.zhengdao/.ui.KeepaliveLogActivity`，标题「**保活记录**」，内容与改前逐字一致：
