## 1. 根因（一句话，照报告）

玄览里所有页面的**首次排版都发生在一个 0×0、未挂载的 WebView 上**（「空态不挂 WebView」＋「newTab 即 loadUrl」两条既有设计叠加）⇒ Chromium 把视口度量更新了，但渲染器侧 **CSS 布局的根包含块高度楔死在 0** ⇒ `html{height:100%}` 整条链塌成 0，内容全在 DOM 里但被压成 0 高；只有 `position: fixed/absolute` 的元素（汉堡、客服头像）看得见。之后 reload／resize／旋转都不自愈。

已排除（不要重复验证）：UA、网络、JS 异常、CSS 未加载、第三方 cookie／DOM storage。

## 2. 本单要交什么（三件）

### A 段 · 修高度楔死（必交，主目标）

按报告「方案 A」落地：

1. **活跃标签的 AndroidView 始终挂载**（含 `everLoaded` 之前）；`BrowserScreen` 里那份「`everLoaded==true` 才挂」的守卫去掉。
2. **起始页（空态）改成盖在 WebView 之上的不透明覆盖层**——空态的视觉与交互不变（第 ㊱刀 要解决的「深色模式白底冲图腾」也一并由覆盖层兜住），只是**实现方式**从「不挂 WebView」换成「盖住 WebView」。
3. `BrowserTabManager.newTab()` 的 url 改为 **pending**：先存起来，等该 WebView 首次 `onLayout` 且 `measuredHeight > 0` 之后才 `loadUrl`；若拿到的是已挂载且已布局的实例则立即加载（标签切换、前进后退不受影响）。
4. **红线**：底栏 106dp 几何一个数都不许动；标签语义、Cookie／localStorage 共享方式不变；不许出现两份 WebView 同时挂载。

### B 段 · destroyed-WebView 警告（必交）

logcat 现在反复刷 `Application attempted to call on a destroyed WebView`（`reload`／`canGoBack`／`canGoForward`）。根因三处：

1. `WebViewEngine` 没有 destroyed 标志，`BrowserHolder.releaseIfIdle()`（TRIM_MEMORY_COMPLETE 档）销毁后，`main` Handler 里已入队的 runnable 照常执行；
2. `canGoBack()`／`canGoForward()`（`WebViewEngine.kt:94-96`）**连主线程投递都没有**，是裸调；
3. `BrowserScreen` 的 `remember { BrowserHolder.obtain(context) }` 在标签被 TRIM 清空后成为死引用。

修法（报告 §五）：

- `WebViewEngine` 加 `@Volatile private var destroyed`；所有入口（`loadUrl`／`reload`／`stopLoading`／`canGoBack`／`canGoForward`／`goBack`／`goForward`／JS 执行）先查该标志，命中即安全返回；
- `canGoBack/canGoForward` 补 `main.post`；
- 销毁只走一个出口：摘挂载 → `removeCallbacksAndMessages(null)` → `loadUrl("about:blank")` → `destroy()`，全部 `runCatching`；
- `BrowserScreen` 拿引擎时判空：已销毁则重新 `obtain`（仅主线程）。

### C 段 · 环回地址豁免强升 https（必交，小）

`BrowserScreen.normalizeInput` 现在把 `127.0.0.1` 也强升 https ⇒ 本地联调页直接 ERR，挡住「抱朴／脚本用玄览验本地页」。判据：`localhost`／`127.0.0.1`／`[::1]`／`*.local` **保留 http**，其余照旧升 https。
