# 事故回流表（903）

> 管什么：把「素材覆盖不到、只能靠约束拦」的实测写崩事故逐条入账。
> 表只管账：症状、归类、根因、落点、状态、日期；拦不拦得住由落点单的检查负责。
> 结构由 `app/src/test/java/com/example/zhengdao/IncidentLedgerGateTest.kt` 门禁看守：
> 七列、八类、四档、首批五例，删行、改类、去理由都会红。
> 903 只入账不做自动化、不改任何 check 函数（自动生成归 904，红分支归 905）。

## 类型（固定 8 类，不许增删）

<!-- INCIDENT-TYPES-BEGIN -->
| 类型 | 判据 |
| --- | --- |
| 几何不可能 | 现实几何上不可能发生（如自体不可达的接触） |
| 穿模 | 两件应互斥的形体相互贯穿 |
| 机制错 | 机制方向或施受写反、因果颠倒 |
| 场景失真 | 场景要素与设定或常识不符 |
| 能量档错 | 力度、速率、幅度档位与情境不符 |
| 词表误写 | 用了 669 词表的禁写词或误写词 |
| 时序错 | 先后顺序颠倒或缺失 |
| 其他 | 以上七类装不下、且判据写得清的 |
<!-- INCIDENT-TYPES-END -->

## 状态（固定 4 档）

- 待归类：还没找到落点单，每周清一次，不许过周；落点单栏写「待派」。
- 已派单：落点单已承接，检查尚未拦到。
- 已拦截：对应检查已入库生效。
- 不修：裁定不修，必须留理由，写法「不修（理由：……）」。

## 流程（三条）

1. 写崩一次入账一条：实测到一起，当天入账，不许攒批。
2. 每周清「待归类」：清完要么挂上落点单转「已派单」，要么转「不修」留理由。
3. 「不修」必须留理由：没有理由的不许标「不修」。
