## 2. 规格

### 2.1 A 段：计划卡本体

- 新建 `ui/baopu/BaopuPlanCard.kt`（Composable ＋ 纯判据），**不要**塞进 `BaopuMessageList.kt`（那文件已 389 行，超 400 线）。
- 收起态：一行 —— `计划 %1$d/%2$d 完成`（中英各一条 strings），左边一个小三角/箭头示意可点。
- 展开态：每条一行
  - `✓` 已完成（`done`）
  - `●` 进行中（`doing`）
  - `○` 未开始（`todo`）
  - 文本按 `text` 原样显示，超长单行省略号（点击不做全文弹窗，本期不加）。
- 交互：点收起行 ⇄ 展开；**不新增"全部展开"按钮**。

### 2.2 B 段：放在哪儿（与第十六批的轮收纳共存——本段的真正难点）

第十六批把"有工具卡的轮"收成一行摘要。计划卡**不允许**因此消失：

1. **展开的轮**：计划卡在该轮顶部（工具卡之上）。
2. **收起的轮**：摘要行下面**仍要显示计划卡（收起态那一行）**——用户一眼能看到"这轮的计划 3/5 完成"。
3. **正在跑**（`running=true`）：计划卡自动展开。
4. **跑完**：计划卡自动收起（跟轮一起），但用户点它能单独再展开（`remember(轮键)`，不落库）。

### 2.3 C 段：摘掉临时过滤

A+B 段为了不让裸 JSON 露出来，在 `BaopuChatController.readMessages` 里**过滤了 `kind='plan'`**。C 段必须：

1. 改读侧：`readMessages` 不过滤 plan part，而是把 plan payload **解析成** `BaopuUiPlan`（纯数据：`items: List<{text,status}>`）挂到消息上，**绝不当文本渲染**。
2. 判据钉死：`BaopuChatController` 里那条 `kind == "plan"` 的过滤行**必须消失**，且 UI 不会把 plan JSON 当正文画出来（源码级门禁：`BaopuMessageList`/`BaopuPlanCard` 不许把 `part.text` 直接喂给 Text 渲染 plan part）。

### 2.4 D 段：历史会话

进页面时从库读**最后一条** plan（`SessionPlanStore.latest`），挂到对应轮上；重启后仍在。
