## ⚠️ 前置对齐（必读，2026-10-07 归档注记）

1. **"WebView"≠本计划的技术前提。** 本计划原文多处写"WebView 加载 `localhost` 的 OpenCode Web UI"。但项目已于 2026-10-06 裁定改用 **Compose 原生 UI 直连 OpenCode HTTP + SSE API**（见上列裁定/设计方案）。WebView 路径因自建转发层 `LocalProxy` 的三处结构性缺陷（逐字节解析 + 强制 `Connection: close` + SSE 占线程）将被淘汰。
   → **本计划中一切"WebView"应读作"太极 Tab 的 OpenCode 客户端（Compose 实现）"**；"WebView 加载 localhost"应读作"Compose 客户端经 OkHttp 直连 `opencode serve`"。
2. **架构冻结红线与 Compose 方案一致**：本计划"不许动"的 PRoot/tmux/Agent 安装器/OcClient·OcRepository 接口，与 `证道-太极Tab-Compose设计方案.md` §7 红线同源。
3. **API 路径写法待核实**：本计划示例写 `GET /api/session?directory=<path>`，而裁定报告核实的端点为 `GET /session`（无 `/api` 前缀）。**以实际打包版本（`OcManager.VERSION`）的 `openapi.json` 为准**（裁定 §6.3）。
4. **cleartext 待澄清**：裁定 §6.1 称项目已配 `usesCleartextTraffic="true"`（Manifest:27）、从未被拦；`文档审核报告-2026-10-06.md` P0-1 称 targetSdk 28 下会被拦。二者需以 Manifest 实况裁决——落地 WebView/OkHttp localhost 链路前先确认（若确需 `network_security_config.xml`，`127.0.0.1` 与 `localhost` 要写两条）。

## 核心目标

让一个完全不懂终端的人，第一次打开太极，就知道怎么开始、怎么回来、怎么继续昨天的工作。

从「能用」升级为「好用」。

## 架构冻结原则（红线，两个 Agent 都遵守）

| 不许动 | 原因 |
|---|---|
| PRoot 启动逻辑 | 刚跑通，动了就崩 |
| SSE / REST 客户端 | 刚修完鉴权和权限链路 |
| tmux 会话管理 | 终端和太极共用的地基 |
| Agent 安装器 | Hermes 刚打通 |
| OcClient / OcRepository 接口 | 两个 Agent 共用，改接口 = 双倍返工 |

只加 UI 层和消息渲染层。发现架构真的限制发展，单独开一次重构，不混在 v1.1 里做。

## 技术资源

**Markdown 渲染库**：
- `jeziellago/compose-markdown`（780★，活跃）——单 composable，支持表格、任务列表、代码块
- `mikepenz/multiplatform-markdown-renderer`（1k★，KMP）——跨平台，有独立的 code 模块

**代码语法高亮**：
- `komodgn/compose-codeview`（KMP，支持 Kotlin/Java/Python 等）
- 或直接用 Markdown 库自带的代码块渲染 + 复制按钮

**OpenCode 会话 API**：
- `GET /api/session?directory=<path>` 列会话，支持搜索、分页、directory 过滤
- `GET /api/session/{id}/message` 取历史，返回 `next_cursor` 支持加载更早消息
- 会话有 `title` 字段

**输入框键盘处理**：
- `android:windowSoftInputMode="adjustResize"` 放 `<activity>`（不是 `<application>`）
- `WindowCompat.setDecorFitsSystemWindows(window, false)` + `Modifier.imePadding()`

## 分阶段执行

### 第一阶段：会话完整化（Agent A，最高优先级）

**1. 新建会话**
- 入口：太极 Tab 顶部「＋ 新会话」
- 首次进入：显示空会话界面 + 输入框 + 引导文案
- `POST /api/session` 创建，自动取第一条用户消息前 N 字作为标题

**2. 历史会话列表**
- 入口：顶部「☰ 历史」
- 按日期分组：今天 / 昨天 / 更早
- 显示标题 + 时间 + 消息条数
- 数据源：`GET /api/session?directory=<path>`

**3. 恢复旧会话**
- 点击历史条目 → 进入聊天界面
- 从 `GET /api/session/{id}/message` 拉消息，UI 层重建视图
- 不重造 session 系统，用 API 返回的 message 列表渲染

**4. 自动标题**
- 确认 `POST /api/session` 返回的 `title` 字段
- 如果没有 title，UI 层用第一条用户消息前 20 字生成
- 不要调模型生成标题

**5. 删除 / 重命名（P2，可延后）**
- 长按历史条目 → 删除 / 重命名
- 删除调 `DELETE /api/session/{id}`
- 重命名写 DataStore

### 第二阶段：消息视觉层级（Agent B）

**6. 最终回答突出**
- 最终回答是主角：大字号、高对比度、无折叠
- 思考过程是辅助：小字号、默认折叠、灰色
- 工具调用是过程：卡片式、折叠、图标 + 工具名 + 状态

**7. 思考过程默认折叠**
- 头部：`💭 思考过程 · N 步　展开 ▼`
- 展开后显示 reasoning 内容

**8. 工具调用卡片**
- 格式：`🔧 shell · 已完成`
- 点击展开：入参 + 结果
- 状态图标：运行中 ● / 完成 ✓ / 失败 ✗

### 第三阶段：输入框与手机体验

**9. 输入框**
- `android:windowSoftInputMode="adjustResize"` 放 `<activity>`
- `WindowCompat.setDecorFitsSystemWindows(window, false)` + `Modifier.imePadding()`
- Enter 提交 / Shift+Enter 换行
- 生成中：发送按钮变「■ 停止」

**10. 停止按钮状态位**
- `session.execution.started` → 生成中
- `session.execution.succeeded` → 可发送
- 防漏接：加超时兜底

### 第四阶段：Markdown 与代码（P1）

**11. Markdown 渲染**
- 引入 `jeziellago/compose-markdown` 或 `mikepenz/multiplatform-markdown-renderer`
- 引依赖前先报用户批准

**12. 代码块**
- 独立背景 + 等宽字体 + 横向滚动
- 一键复制按钮（优先级最高）

## Agent 分工

| Agent | 负责 | 不碰 |
|---|---|---|
| **Agent A** | 新建会话、历史列表、恢复会话、自动标题、删除、重命名 | 消息渲染层 |
| **Agent B** | 视觉层级、折叠、工具卡片、Markdown、代码块、复制、输入框 | session 生命周期 |

## 你的角色（真机验收）

每完成一个阶段，用手机实际点一遍：

```
新建 → 发消息 → Agent 工作 → shell → 最终回答 → 返回 → 历史 → 恢复 → 再发一句
```

发现不好用 → 告诉 Agent「这里不好用」→ 它改。

## v1.1 验收标准

一个完全不懂 Linux 的人拿到手机，你不在旁边解释，他能完成：

```
打开证道 → 点太极 → 新建会话 → 输入一句话 → Agent 工作
→ 看懂最终结果 → 退出 → 第二天重新打开 → 找到昨天的会话 → 继续聊天
```
