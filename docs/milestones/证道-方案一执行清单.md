# 方案一执行清单：国内对象存储主下载源

> 前置文档：证道-rootfs下载优化方案.md（选型对比与裁定）
> 总工作量：半天。R2 起步（零成本）→ 用户量上来加阿里云 OSS（同款步骤复制）。
> 回退总原则：`RootfsDownloader` 多源列表**删掉新源即回现状**，App 无感知。

---

## 阶段〇：决策（开始前必须拍板）

- [ ] **D1 桶选型**：Cloudflare R2（零流出费，国内速度中等）或 阿里云 OSS（快，~0.16 元/次下载）
- [ ] **D2 暴露方式**：
  - R2 → 自定义域名挂 Cloudflare（推荐，走 CDN）或 r2.dev 开发 URL（**有限速，仅验证用**）
  - OSS → 桶默认域名（公共读）或 CDN
  - ⚠️ 若走 CDN/代理层，必须设 `Cache-Control: no-store` 或用**版本化文件名**——
    CI 每次构建字节都不同，缓存命中旧包 = SHA 必失败
- [ ] **D3 App 端 URL 形态**：固定桶域名 + 固定文件名（覆盖式上传），
  `RootfsDownloader` 加一个 `withObjectStorage(url)` 变换（仿现有 `withGhProxy`）

## 阶段一：Cloudflare R2 起步（零成本）

### 1. 云侧准备（网页操作，约 20 分钟）

- [ ] 1.1 注册/登录 Cloudflare，开通 R2（需绑一张卡；免费额度 10GB 存储/月，出口免费）
- [ ] 1.2 创建桶：名 `zhengdao-rootfs`，位置自动
- [ ] 1.3 生成 API Token：R2 → Manage API Tokens → 仅授权该桶 Object Read & Write；
      记下 Access Key / Secret Key / Endpoint（`https://<account_id>.r2.cloudflarestorage.com`）
- [ ] 1.4 **暴露方式落地（D2 决策执行）**：
  - 验证期：开启 r2.dev 公开访问（快，但限速）
  - 正式：自定义域名（域名 DNS 托管到 Cloudflare → 桶 → 设置自定义域），
    并给对象/桶设默认 `Cache-Control: no-store`（或接受覆盖式更新短暂旧缓存）
- [ ] 1.5 手动上传测试：`debian-13.7-base-arm64.tar.zst` + `.sha256` 各传一份
      （AWS CLI S3 兼容：`aws s3 cp --endpoint-url <endpoint> ...`，或 rclone）
- [ ] 1.6 **验证 1**：手机浏览器/`curl` 直下该 URL，记录速度（预期 ≥1MB/s 即优于 GitHub 直链）；
      `sha256sum` 与 .sha256 一致

### 2. GitHub 侧（Secrets + CI，约 30 分钟）

- [ ] 2.1 仓库 Settings → Secrets → Actions 添加：
      `R2_ACCESS_KEY` / `R2_SECRET` / `R2_ENDPOINT` / `R2_BUCKET`
- [ ] 2.2 `build.yml` 的 RootFS 构建成功后（proot 步骤前后皆可）加同步步骤：
      ```yaml
      - name: 同步 rootfs 到 R2（主下载源）
        if: github.ref == 'refs/heads/main'
        env: { AWS_ACCESS_KEY_ID: ..., AWS_SECRET_ACCESS_KEY: ..., R2_ENDPOINT: ..., R2_BUCKET: ... }
        run: |
          aws s3 cp --endpoint-url "$R2_ENDPOINT" \
            rootfs-out/debian-13.7-base-arm64.tar.zst "s3://$R2_BUCKET/" \
            --metadata-directive REPLACE --cache-control "no-store"
          aws s3 cp --endpoint-url "$R2_ENDPOINT" \
            rootfs-out/debian-13.7-base-arm64.tar.zst.sha256 "s3://$R2_BUCKET/" \
            --cache-control "no-store"
      ```
      （aws cli 走 S3 兼容 API；CI 需 `pip install awscli` 或用 rclone 二进制）
- [ ] 2.3 **验证 2**：手动触发 workflow → 桶内文件更新 → URL 直下 OK

### 3. App 端（RootfsDownloader 插源，约 30 分钟）

- [ ] 3.1 `RootfsDownloader.kt`：新增桶公开域常量 + `withObjectStorage(url)` 变换
      （文件名与 GitHub 侧同名——覆盖式上传，URL 恒定）
- [ ] 3.2 下载入口把源列表改为：`[对象存储, GitHub直链, gh-proxy]`
      （sha 边车候选源同步加对象存储 URL，github 仍优先）
- [ ] 3.3 **验证 3**：真机清环境标记 → 触发下载 → 日志确认首个源即对象存储
      + 计时（预期 311MB ≤ 1 分钟）
- [ ] 3.4 **验证 4（关键）**：下载完 SHA 校验通过（确认覆盖式更新未引入缓存旧包）

### 4. 回退演练（强制，防"以为能回退"）

- [ ] 4.1 临时在 CI/桶侧禁用对象存储（或 URL 改错模拟 404）
- [ ] 4.2 真机重下 → 确认自动回落 GitHub → gh-proxy → 完成（现有逻辑）
- [ ] 4.3 恢复对象存储配置

### 5. 文档收尾

- [ ] 5.1 README「当前状态」补一句下载源说明
- [ ] 5.2 评估文档 P1 行标 ✅ + 实测速度数据
- [ ] 5.3 commit：`feat(v1.2+): 对象存储主下载源（R2）——装环境 4min → <1min`

## 阶段二：用户量上来后 → 阿里云 OSS（复制阶段一同款步骤）

触发条件：月活跃安装 > 50，或 R2 速度投诉。
差异仅三处：桶在 OSS 控制台建、Secrets 换 OSS 密钥、URL 换 OSS 域名。
（费用备忘：流出 ~0.5 元/GB → 100 用户/月 ≈ 16 元；账单月度巡检。）

## 已知坑（写代码/配置前再看一遍）

1. **CI 每次构建字节不同**（debootstrap 熵）→ 覆盖式上传后，任何缓存层命中
   旧包 = SHA 必失败——全链路 `no-store`，勿用 CDN 默认缓存
2. **.sha256 必须与包同批上传**——v1.2 起校验值取不到是硬错误（5cf218e），不同步会直接断
3. **R2 r2.dev 域名限速**——验证可用，正式必须自定义域
4. **App 端纯逻辑测试**：URL 变换函数加单测（文件名拼接/转义），仿 OcModelTest 风格
5. **卸载 App 不影响桶**——桶是云侧资产，无用户数据（只有 rootfs 公共包），无隐私风险
