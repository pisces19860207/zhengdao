## 一、核心结论：不要整体 Rust 重写，要逐步替换「发动机」

Kotlin = Android 外壳 + UI
Rust = 证道真正的底层运行核心
Debian = Agent 的 Linux 世界
Agent（Hermes/OpenCode/Claude Code 等）= 上层插件

## 二、哪些模块适合 Rust，哪些不适合

**🟢 强烈推荐 Rust 化（发动机）**

| 模块 | 为什么适合 |
|---|---|
| Agent 生命周期管理 | 长期运行的小型进程管理器 |
| 进程管理 | 启动/停止/监控/重启，Rust 原生进程控制强 |
| Session 管理 | 会话状态、恢复、销毁 |
| 事件总线 | 统一 stdout/stderr 转结构化事件 |
| Manifest 验签 | Ed25519 + SHA256，边界明确的安全核心 |
| 后台任务调度 | Tokio 任务模型轻量 |

**🟡 看情况（可以但现在别动）**

| 模块 | 建议 |
|---|---|
| 下载器 | 现在 Kotlin 够用；管理多类下载时再考虑 |
| 解压/校验 | 有性能瓶颈时再 Rust |
| SSE/网络 | 刚跑通，别动 |

**🔴 绝对不要 Rust 化**

| 模块 | 原因 |
|---|---|
| Compose UI | Android 官方已宣布 Compose-first 战略 |
| TerminalView | 刚切过来，且是 Android 原生方向 |
| proot 本体 | 整个证道能成立的基础 |
| Debian RootFS / Hermes / OpenCode / Claude Code | 它们是客人，不是发动机 |

## 三、为什么要搞一个「zhengdao-core」

证道现在的底层逻辑散落在 Kotlin、Shell、tmux 和 Android Service 里，需要把它们收拢成一个独立的核心。

`zhengdao-core` 是一个 ARM64 Rust 程序，负责：

> ⚠️ **消歧（2026-10-07）：`zhengdao-core` ≠ `libzhengdao_core.so`。**
> 本文的 `zhengdao-core` 指**尚未存在的独立 ARM64 进程**（进程/Session/事件总线/验签/调度，见下）；
> 而 `证道-v2.0架构设计.md:143`（§4 R1 行）里的 **`libzhengdao_core.so` 是 R1 收编后的嵌入式 JNI 解压/摘要库**
> （`rust/core`，分支 `feat/v2.0-r1-rust-core-16kb` 的 `008d554`，**尚未进 main**）。
> 两者名字撞车、**不是同一个东西**——一个是进程、一个是 App 进程内的 `.so`。
- 启动/停止/监控/重启 Agent
- 创建/恢复/销毁 Session
- 管理 proot、tmux、PTY
- 把 Agent 输出转成统一事件
- 后台任务调度、超时、取消、重试

Android 通过 IPC / Unix Socket 调用它。这样 Android UI 和底层核心解耦——UI 死了，Agent 不一定死。

## 五、最重要的原则

不要为了 Rust 而 Rust。

现在开始为 Rust 留接口，而不是现在开始写 Rust。先把 Kotlin 层的模块边界拆清楚，等某个模块真的成为瓶颈时，再替换成 Rust——替换一个模块，比替换整个 App 稳得多。

> ⚠️ **更正（2026-10-07）**：这句话写于 R2 之前，**"而不是现在开始写 Rust"已被事实越过**——
> main 上已经写了 Rust 且已在生产路径上（`rust/sha256poc` + `rust/extract`，
> `rootfs/RootfsInstaller.kt:76-95`）。
> **但原则本身仍然适用，只是适用范围要限定**：越过的只是"**解压 / SHA256 这类工具链层**"，
> 而且**理由不是性能**（Rust 3611ms vs Java 3668ms，同一量级）而是**架构验证**；
> 本文 Phase 0-5 真正要谈的**进程 / Session / 事件总线核心层，Rust 代码量仍为 0**。

## 六、事实核验（社区实践）

- **Codex CLI 官方数据**：TypeScript 重写为 Rust 后，冷启动从 800-1200ms 降至 35-50ms，内存占用降低约 90%。
- **COSMIC Connect**：Rust 负责协议和加密核心，Kotlin 负责 UI 和 Android 服务，70%+ 代码跨平台共享。
- **Gobley**：专门提供工具帮助在 Kotlin Multiplatform 项目中嵌入 Rust。
- **Android 官方**：AOSP 已支持 Rust 与 Kotlin 的互操作，提供 `rust_bindgen` 等工具链。

> 📌 **注记（WorkBuddy）**：§六 数据为上游社区公开数据，用于说明"Rust 核心 + Kotlin UI"这条路有先例；**不构成对证道收益的承诺**。证道是否引入 Rust，仍以裁定/实据为准（见顶部对齐注记第 3 条）。
