# 已知限制：targetSdk 28 结构性边界

> **记录时间**：2026-10-06（第 0 步真机诊断后）
> **性质**：架构级不可改约束。本文件是「为什么证道钉死 targetSdk 28、为什么 /sdcard 直连不可用、为什么必须走 SAF 镜像同步」的唯一权威说明。实现方（Zcode / 任何协作者）改代码前先读本文件。
> **关联文档**：`安卓AgentApp-设计方案-v3.md`（架构前提）、`PROVENANCE.md`（合规底线）、`M1.1-开发任务书.md`（proot 接入约束）

---

## 1. 一句话结论

**证道依赖 targetSdk 28 才能从 App 数据目录 exec proot 二进制（W^X 豁免）。这个约束是架构级的、不可修改的；抬高 targetSdk 会导致整个 Linux 环境变成一堆无法执行的死文件。**

## 2. 实测结论清单（2026-10-06，荣耀 Magic 5 Pro / MagicOS 11 / Android 16 真机）

第 0 步「sdcard 读缺陷诊断」完成，逐项实测结论如下：

| # | 诊断项 | 实测结论 |
|---|---|---|
| 1 | guest readdir | guest 内 `ls /storage/emulated/0/...` **全部被拒** |
| 2 | 写己文件读回 | 自己写的文件可以读回（写路径通） |
| 3 | **读用户拷入的已有文件（关键判别）** | **被拒**。FUSE / MediaProvider 不认 targetSdk 28 的传统存储视图 |
| 4 | 宿主 run-as 对照 | 宿主侧 `run-as` 可正常访问——问题出在 guest/proot 的存储视图，不是 App 权限 |
| 5 | manifest `READ_EXTERNAL_STORAGE` 带 `maxSdkVersion="32"` | 头号嫌疑成立：Android 13+ 永远无法持有 READ 权限。已摘帽（commit `d414dca`） |

**核心判别**：`requestLegacyExternalStorage="true"` 在 Android 16 上被平台无视；`pm grant READ` 授权成功但访问仍拒。**这不是权限配置问题，而是平台存储视图的结构性变化——targetSdk 28 的传统存储视图在 Android 16 上已失效。**

## 3. 根因

- Android 10 起 SELinux 禁止 targetSdk ≥ 29 的应用从**可写数据目录**执行文件（W^X）。
- 证道的整个 rootfs（`/usr/bin` 下成千上万个二进制）都在 App 数据目录里，必须靠 targetSdk 28 豁免才能 exec。
- **抬高 targetSdk = proot 执行链崩溃 = 整个 Linux 环境不可用。这是不可谈判的架构前提。**
- 连锁影响：Android 16 上，targetSdk 28 应用不再被 MediaProvider 认作可访问共享存储的传统视图——即使权限全部授予，FUSE 层仍然拒绝 guest 读取用户文件。

## 4. 为什么不可修复

| 尝试方向 | 结果 |
|---|---|
| `requestLegacyExternalStorage="true"` | Android 16 平台无视 |
| `pm grant READ` 手动授权 | 授权成功，访问仍拒 |
| 去掉 manifest `maxSdkVersion="32"` | 已做（`d414dca`），解决"永远无法持有 READ"的权限问题，但**不解决** FUSE 存储视图失效 |
| 抬高 targetSdk | **绝对禁止**——W^X 豁免丢失，proot 无法 exec |

**结论**：在 targetSdk 28 前提下，`/sdcard` 直连此路不通。这不是 bug，是平台政策与架构约束的碰撞。

## 5. 替代方案：SAF 镜像同步（项目官方存储方案）

**Plan B 已从"备选"升级为"项目官方存储方案"**。这不是临时绕路，而是 Android 16 后 targetSdk 28 环境下**唯一可行的共享存储路径**。

### 方案要点

- **SAF 选文件夹** → 镜像到 `~/mnt/phone/`（guest 内路径）
- **双向同步**（启动 + 手动，不做实时监听）
- 冲突较新者胜或提示
- **镜像目标不是工作区**——工作区仍是 `/workspace`（= 手机 `Download/证道`）
- 第一版做**最小可用**：不递归、不删同步、文件数量上限 1000，跑通再扩

### 实现参考（Zcode 已落地，未提交代码）

- `app/src/main/java/com/example/zhengdao/mirror/PhoneMirror.kt` —— 镜像同步核心（复制语义，非挂载；镜像落点 guest `/mnt/phone`）
- `ProotLauncher.kt` —— 启动时绑定 `phoneMirror: /mnt/phone`
- `SettingsScreen.kt` —— 「手机文件夹同步」设置入口（SAF 选文件夹）

## 6. 长期风险与跟踪机制

### 政策方向

- **最低安装门槛**：Android 14+ 仅禁止安装 targetSdk < 23 的应用，28 有安全边际，但需持续关注是否上调。
- **Play 侧强制 target API 36**：只约束 Play 上架，与 GitHub 直发无关，但为门槛上抬信号。
- **AOSP 对 untrusted_app 域的策略动向**：proot 依赖的 exec 豁免是否被进一步收紧。
- **侧载身份验证政策**：GMS 认证设备上 APK 须来自已验证身份开发者，2026-09-30 起首批执法，2027 全球推行。本项目主要人群（国行无 GMS 设备）不受影响，但需每月核对。

### 每季度核对机制

- [ ] 每季度复查一次：Android 新版本是否上调最低安装 targetSdk 门槛
- [ ] 每季度复查一次：AOSP untrusted_app 域策略是否有变化
- [ ] 每季度复查一次：侧载身份验证政策的地区推进与豁免细则
- [ ] 每季度在真机上重跑一次第 0 步诊断矩阵（读用户拷入文件），确认 SAF 镜像路径仍可用

## 7. 备选形态（长期）

- **`system_linker_exec` 灰区方案**：只做技术储备评估，**不实现**（Termux 官方自述违反 Play 政策可能下架，不走这条路）。
- **云机瘦客户端**：复用终端渲染层做 SSH/Mosh 瘦客户端连云机（见设计方案 §10 v2 路线）。作为 targetSdk 28 彻底失效时的终极备选。
