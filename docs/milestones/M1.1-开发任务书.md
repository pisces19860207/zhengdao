# M1.1 开发任务书：下载器 / 解压 / proot 接入

> **本里程碑工程约束与验收标准；实现以代码为准，约束与红线以本文档为准。**

> 项目：证道（安卓轻量级 AI Agent App） · 文档：`安卓AgentApp-设计方案-v3.md`
> 目标里程碑：**M1.1**（rootfs 下载/解压[含原子性] + proot 接入，替换系统 shell 为 Debian 13.7 bash）→ M1.2（旗舰 Agent 装跑通）
> 前置已就绪：切片 2（自研 JNI 伪终端 Pty.kt）已跑通系统 shell。**v3.9 定案：终端渲染层由 xterm.js/WebView 切换为 Termux TerminalView（原生，Apache-2.0）**，Pty.kt 保留、输出改喂 TerminalEmulator——本任务书的终端对接以 TerminalView 为准。proot 技术路线已定：**Termux proot fork**（自编译上游 proot 在 App 域静默退出 255，仅 run-as 域正常；切 fork 后正常，GPL 聚合分发需登记 PROVENANCE）。
> 关键约束（v3 定案）：targetSdk 28；单 ABI arm64；proot 用 **Termux 官方发行二进制**，以 **assets 内置 → 释放到 `files/termux-proot/` → execve** 方式分发（**jniLibs / `libproot.so` 方案已废弃留档**，勿再照旧实现）；rootfs 为 Debian 13.7 tar.zst（约 100–150MB，落盘 1.5–2GB）。

> 🧱 **`libtermux.so` 的 16KB 对齐要求（v3.9 补，终端渲染层必读）**
> 终端渲染层切换为 Termux TerminalView 后，会引入 `terminal-emulator` 模块自带的原生库 **`libtermux.so`**。它同样受 **Android 15 的 16KB 页大小约束**——未对齐的 .so 在 16KB 页设备上**加载直接失败**（表现为终端一打开就崩）。两条路：
> - **用 JitPack 等预编译版本**：**必须先确认它是否已按 16KB 对齐编译**。验证：`readelf -l libtermux.so | grep -A1 LOAD` 看 p_align 是否 ≥ 16384；或用 Android Studio 的 APK Analyzer / `check_elf_alignment.sh` 过一遍。**没对齐就换版本或自己编译**。
> - **自行从源码编译**：必须 **NDK r28+** 并加链接参数 `-Wl,-z,max-page-size=16384`（r28 起对 16KB 支持才完善）。
> 这一条与 proot 本体的 16KB 对齐是**同一类要求**（v3 §4），**别只对齐 proot 而漏掉 libtermux.so**。

## 模块 1：ResumableDownloader（断点续传下载器）

**位置**：`core/download/` · 网络库：OkHttp

**接口骨架（Kotlin）**：

```kotlin
data class DownloadSpec(
    val urlGithub: String,          // 主通道
    val urlCdn: String,             // 备用通道（Cloudflare R2/自建域名）
    val sha256: String,             // 校验值，来自 manifest
    val expectedSize: Long,         // 字节数，来自 manifest
    val destFile: File,             // 最终落盘路径
    val partFile: File,             // 断点文件（.part），同目录
)

sealed class DownloadState {
    data object Idle : DownloadState()
    data class Probing(val channel: String) : DownloadState()   // Range 测速选源
    data class Downloading(val bytes: Long, val total: Long) : DownloadState()  // 进度
    data class Verifying(val bytes: Long) : DownloadState()     // SHA256 校验中
    data class Done(val file: File) : DownloadState()
    data class Failed(val reason: String, val recoverable: Boolean) : DownloadState()
}

interface ResumableDownloader {
    /** 启动下载；返回一个可取消的 Job。进度经回调/StateFlow 上报。 */
    fun download(spec: DownloadSpec, listener: (DownloadState) -> Unit): Job

    /** 续传：读取 partFile 已有字节数，从 Range 继续；校验失败则清空重下。 */
    fun resume(spec: DownloadSpec): Boolean

    /** 完整性校验：边下边算 SHA256，避免二次全读。 */
    suspend fun verify(spec: DownloadSpec): Boolean
}
```

**验收要点**：
- [ ] 主通道失败自动切备用通道（含 Range 中断后切换）
- [ ] 中断后续传：手动杀进程 → 重启后从 `.part` 继续，不重下已完成部分
- [ ] SHA256 不匹配 → 自动清空重下（最多 1 次，再失败报错）
- [ ] 下载完成前 `.part` 与最终文件分离，避免半成品被误用

## 模块 2：TarZstExtractor（zstd 解压 + 原子性）

**位置**：`core/rootfs/` · 库：zstd-jni（或 commons-compress）

**接口骨架（Kotlin）**：

```kotlin
interface TarZstExtractor {
    /**
     * 解压 tar.zst 到 tmpDir → 写完成标记 → 原子 rename 到 finalDir。
     * 任一步失败：清理 tmpDir，下次启动重来。
     */
    suspend fun extractAtomic(
        archive: File,
        tmpDir: File,
        finalDir: File,
        onProgress: (Long) -> Unit,     // 已解压字节数（进度 UI「解压中」阶段）
    ): Result<File>

    /** 启动时检测上次残留的半成品 tmpDir，清理。 */
    fun cleanupStale(tmpDir: File)
}
```

**验收要点**：
- [ ] 解压中途杀进程 → 下次启动自动清理残留、重新解压成功
- [ ] 完成标记写入后再 rename；rename 前不出现可被当作"已装好"的目录
- [ ] 解压进度独立于下载进度（UI 两个阶段：下载中 / 解压中）
- [ ] 解压后 rootfs 内可执行文件权限正确（proot 需要 `--link2symlink` 与默认 bind）

## 模块 3：ProotSessionLauncher（proot 会话接入）

**位置**：`core/runtime/` · 核心：Termux proot fork（**assets 内置 → 释放到 `files/termux-proot/` → execve**；jniLibs / `libproot.so` 方案为历史留档，勿再实现）

**proot 分发方式（v3.9 校正：以代码实现为准）**

> ⚠️ 本节早期版本写的是"jniLibs 内嵌 `libproot.so`"，**该方案已废弃**（代码中标注"留档"）。以下是**现行实现**，改代码前务必核对 `ProotLauncher.kt`。

1. **用什么**：**Termux 官方发行二进制**（Termux proot 5.1.107.96 aarch64 官方构建产物），共 4 个文件——`proot`、`loader`、`libtalloc.so`、`libandroid-shmem.so`。**未修改其源码**，属聚合分发（PROVENANCE.md 已登记）。
2. **放哪**：以**重命名后的 asset** 内置于 `app/src/main/assets/proot/`（现用名 `tproot`、`tloader`、`libtalloc.so`、`libandroid-shmem.so`），随 APK 分发，**不进按需下载**（体积仅数百 KB；且换 APK 即换 proot，避免与 rootfs 版本错配）。
3. **怎么跑**：首启时释放到 **`files/termux-proot/`** 并补执行位，随后 **execve** 执行。每个文件带 **SHA256 固定清单**（asset 名 → 释放名 → SHA256）：已释放且校验通过则跳过（修环境/重装不重复释放），缺失或损坏则从 assets 重新释放。
   ```kotlin
   val tpDir = File(files, "termux-proot").apply { mkdirs() }
   val prootBin = File(tpDir, "proot")   // 释放后的可执行路径 -> 交给 execve，不是 loadLibrary
   ```
4. **为什么 `files/` 下能执行**：targetSdk 28 下 App 的 `files/` 目录**允许 exec**——这正是 targetSdk 28 的意义（Android 10+ 禁止的是"从 App 可写目录执行"，而 targetSdk < 29 被豁免）。**若将来 targetSdk 抬高，这条路会断**，因此 targetSdk 28 是硬前提。
5. **🚨 绝对不能做的事**：**禁止 `System.loadLibrary("proot")` / dlopen**。proot 只能作为**独立进程 exec**——一旦动态链接进 App 进程，极可能被认定为衍生作品，**整个 App 被 GPL 传染必须开源**。注意 `libzstd-jni` 与 `libtermux.so` 是**真 JNI 库、必须 `loadLibrary`**，与 proot 的调用方式相反，不要照抄。

**接口骨架（Kotlin）**：

```kotlin
data class ProotConfig(
    val rootfsDir: File,          // 解压后的 Debian rootfs
    val homeDir: File,              // /root 独立目录（与系统层分离，§8）
    val resolvConf: String,        // 公共 DNS，如 1.1.1.1 / 8.8.8.8
    val extraEnv: Map<String, String>,   // http_proxy 等注入
)
// ⚠️ 刻意不提供 noSeccomp 字段：PROOT_NO_SECCOMP=1 在本机实测致命（与社区通行建议
// 相反），字段不提供 = 代码层面不可能被设置，从源头杜绝后来者照抄社区方案误加回去。
// 启动命令由 ProotLauncher 构造，环境变量固定清单里不含该项（见 v3 §4 红线）。

interface ProotSessionLauncher {
    /** 启动 proot 进程，返回 PtySession（接终端 UI）。 */
    fun launch(config: ProotConfig, terminal: TerminalView): ProotSession

    /** 落 /etc/resolv.conf 与 /etc/hosts（proot 里无 systemd-resolved，不写则 DNS 全挂）。 */
    fun prepareNetwork(rootfsDir: File, resolvConf: String)
}

interface ProotSession {
    val pid: Long
    fun attach(): Unit          // 终端 UI attach（UI 死 ≠ 会话死）
    fun detach(): Unit
    fun kill(): Unit            // 仅「修复环境」等显式操作调用
}
```

**验收要点（M1.1 门禁，真机）**：
- [ ] `uname -a` 输出 `aarch64 GNU/Linux`（Debian 13.7 内核视角）
- [ ] `curl -I https://example.com` 解析成功（DNS 落盘生效）
- [ ] `python3 --version` = 3.13.x、`node --version` = v26.x（CI 断言一致）
- [ ] 后台 30 分钟存活、被杀后重进自动 attach 恢复（配合 §5 保活）
- [ ] **禁用 PROOT_NO_SECCOMP=1**——本机实测反而致命（v3 记录）
- [ ] **TerminalView 最小验证（v3.9 新增，先于 proot 接入跑）**：用**系统 shell**（不进 proot）验证终端渲染层四件事——① 输入命令能看到输出；② 中文 IME 组合输入正常（输入/删改/连续输入）；③ 快捷键条（ESC/CTRL 粘滞/TAB/PGUP）可用；④ 大输出滚动不卡顿（如 `cat` 一个大文件）。此项不通过则 proot 接入无从验收
