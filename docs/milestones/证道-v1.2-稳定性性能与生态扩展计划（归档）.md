# 《证道 v1.2：稳定性、性能与生态扩展计划》

> 基于 v1.0.0 已发布、v1.1（太极 UI 完整化）在途的现状制定。
> v1.2 的核心目标：**让证道从"能用"变成"敢用"——稳定、快、可扩展。**

## 一、版本定位

| 版本 | 定位 | 状态 |
|---|---|---|
| **v1.0.0** | 首个正式版（核心功能闭环） | ✅ 已发布（5.5MB release APK） |
| **v1.1** | 太极 UI 完整化（会话、Markdown、输入体验） | 🔄 在途 |
| **v1.2** | **稳定性加固 + 性能优化 + 生态扩展** | 📋 本计划 |
| **v2.0** | Rust Core 起步（zhengdao-core 第一版） | 🔭 远期 |

## 二、v1.2 三大主线

### 主线一：稳定性加固（P0，最高优先级）

**目标**：v1.0 是"功能跑通"，v1.2 要做到"连续用一周不出问题"。

**1. 崩溃率归零**
- 接入崩溃收集（可选：自托管 Sentry 或本地日志聚合）
- 对已知崩溃点（主线程网络、NullPointer、OOM）做全面审计
- 目标：连续 7 天真机使用，零非预期崩溃

**2. 会话生命周期加固**
- 验证：切后台 30 分钟 → 回来会话还在
- 验证：进程被杀 → 重进 App 自动恢复
- 验证：tmux 会话与 OpenCode serve 的存活关系清晰
- 补全：SessionRecovery 的边界场景（多次重启、并发操作、server 崩溃）

**3. 网络韧性**
- SSE 断线重连退避策略（指数退避 + 上限）
- REST 轮询的失败重试与降级
- 代理切换后的自动恢复（VPN 断开→重连→请求恢复）

**4. 权限与存储的边界测试**
- `MANAGE_EXTERNAL_STORAGE` 被撤销后的降级行为
- 存储空间不足时的优雅处理
- 低内存设备的 OOM 防护

### 主线二：性能优化（P1）

**目标**：让证道在手机上"不卡、不热、不耗电"。

**1. Compose 重组优化**
- 使用 `derivedStateOf` 减少不必要的重组
- 对 LazyColumn 的消息项加 `key`，避免全列表刷新
- 检查 `remember` 缓存是否到位
- 参考 R8 对协程的优化（AGP 9.2.0+ 可将 `Atomic*FieldUpdater` 优化为 Unsafe 变量，性能提升 2-4 倍）

**2. OpenCode 运行时优化**
- 流式输出时的 Markdown 重解析节流（v1.1 已引入 mikepenz 库，v1.2 验证实际性能）
- 如果流式 Markdown 卡顿：流式中纯文本，完成后 Markdown 化
- 长会话的消息列表虚拟化（LazyColumn 已内置，验证是否够用）

**3. 后台资源控制**
- 内存监控：guest RSS 超阈值告警（M2 §6 已设计，v1.2 落地）
- CPU 监控：OpenCode serve 空闲时的 CPU 占用
- 电池优化：确认 WakeLock 策略合理，不空耗

**4. 启动速度优化**
- 冷启动时间测量（目标 < 2 秒到首页）
- 延迟初始化：非关键模块（如环境体检）移到后台

### 主线三：生态扩展（P2）

**目标**：让证道支持更多 Agent，且每种 Agent 的接入成本最低。

**1. Agent 接入标准化**
- 定义 `AgentAdapter` 接口：每个 Agent 实现 install / launch / status / uninstall
- 新 Agent 接入 = 写一个 Adapter + 在 manifest 注册，不改核心代码
- 首批适配：Hermes（已有）、OpenCode（已有）、Claude Code、Codex CLI

**2. Agent 运行时统一**
- 参考 Google 的 ADK for Kotlin 1.0（2026-09 发布，达到与 ADK Core 1.0 功能对等，提供 Android-first 的端侧扩展）
- 设计统一的 `AgentEvent` 流：无论底层是 Hermes 还是 Claude Code，UI 层只认识 `AgentEvent`（thinking / text / tool_call / final）
- 这是 v2.0 Rust Core 事件总线的"接口预演"

**3. 任务中心雏形**
- 从"一个会话一个任务"升级为"多任务并行视图"
- 显示：正在运行的 Agent、任务状态、工作目录
- **注意**：这是 v2.0 多 Agent 调度的前置设计，v1.2 只做 UI 雏形，不做底层调度
