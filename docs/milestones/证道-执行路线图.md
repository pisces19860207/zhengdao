### 🔴 P1：存储权限落地（最紧要）

**目标**：把实测的 `MANAGE_EXTERNAL_STORAGE` + `--bind` 正式落地到代码。

**内容**：
1. Manifest 声明 `<uses-permission android:name="android.permission.MANAGE_EXTERNAL_STORAGE" />`（已声明）
2. 加权限引导流程：
   - `Environment.isExternalStorageManager()` 检查
   - 未授权 → `ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION`（带包名）
   - 失败 → 回退 `ACTION_MANAGE_ALL_FILES_ACCESS_PERMISSION`
   - 不做机型分叉
3. PRoot 启动参数加 `--bind /storage/emulated/0:/sdcard`（已在 `ProotLauncher.kt:373`）
4. 未授权不阻塞 → 降级到私有工作区，设置页保留入口
5. **跑通完整链路后再删 SAF 相关代码**（镜像同步、FD 代理全部作废）

**验收**：真机装 App → 引导授权 → 终端 `ls /sdcard` 通、`echo > /sdcard/Download/xxx` 通、手机文件管理器可见。

> 进度：P1 的 1/3/4 已落地（`cac93b2` 落首启 MANAGE 引导 + `--bind` 早已在）；第 5 项（删 SAF）待真机验证后执行。

### 🔴 P2：OpenCode 内置 + 按需下载

**目标**：把 OpenCode 作为证道默认 Agent，按需下载，不进 APK、不进 rootfs。

**内容**：
1. **bionic 版**（跑在 Android 宿主，非 PRoot）：零依赖，~66MB
2. 首次启动后台并行下载（与 rootfs 下载并行，进度合并显示）
3. 存储到 `Download/证道/opencode/`（用户可见，卸载重装不丢）
4. SHA256 校验，通过后释放到 `/data/data/证道/files/opencode/`
5. 设置页加「检查 OpenCode 更新」按钮（用户主动点，不打扰启动）
6. 更新策略：默认不检查、不下载，用户主动触发才检查

**验收**：首次启动后台下载完成 → 太极 Tab 能启动 OpenCode → 卸载重装不重新下载。

### 🔴 P3：太极 Tab（OpenCode Web UI 唯一入口）

**目标**：底部新增太极 Tab，作为 OpenCode 的家。

**内容**：
1. **WebView 加载 `localhost`** 的 OpenCode Web UI
2. 启动流程：
   - 检测 `opencode serve` 是否在跑
   - 没跑 → tmux 静默拉起 → 自动进对话页
   - 在跑 → 秒进
3. **左侧边栏结构**：
   - 顶部：模型选择器（当前模型 + 下拉切换）
   - 中部上：会话列表（新建 / 切换 / 删除）
   - 中部下：插件面板（显性化，带开关，默认启用 `opencode-mem`）
   - 底部：设置入口
4. **数据隔离**：太极 Tab 强制用独立 XDG 目录
   - `XDG_DATA_HOME=/root/.zhengdao/taiji/data`
   - `XDG_CACHE_HOME=/root/.zhengdao/taiji/cache`
   - `XDG_CONFIG_HOME=/root/.zhengdao/taiji/config`
   - `XDG_STATE_HOME=/root/.zhengdao/taiji/state`
5. **首次进入引导**：免费模型（`/models` 带 `-free` 后缀）+ 明示"免费模型数据可能用于改进模型，勿提交机密"
6. 状态卡含「停止服务」「历史」

**前置验证**：
- bionic 版 OpenCode 在 `targetSdk 28` 下 App 域能跑
- WebView 加载 localhost 可达
- `opencode serve` 的 API 端点（会话列表 / 删除）

**验收**：太极 Tab 能真聊一轮、能删一条历史、能切换模型。

### 🟡 P6：Agent 卸载 + 清理缓存

**目标**：丹房加卸载功能，设置页加清理缓存。

**A. Agent 卸载**
- 丹房卡片右侧"更多菜单"加「卸载」
- 二次确认弹窗（卸载 / 彻底清除 / 取消）
- 默认保留用户数据（`~/.hermes`、`~/.claude`）
- 「彻底清除」才全删
- 通过 manifest 的 `uninstall` 命令执行

**B. 清理缓存**
- 三档白名单写死：
  - 一档（安全清）：npm / uv / apt cache + Hermes 升级残留 + 旧版本 rootfs
  - 二档（谨慎清）：rootfs/tmp 的 V8 JIT 缓存
  - 三档（永不清）：`.hermes/tools/` / rootfs 系统层 / home 用户数据
- 优先用官方命令：`npm cache clean --force`、`uv cache prune`、`hermes cache clean --force`
- 自动清理：启动时 > 500MB 才清，检测安装进程跳过

**C. 下载缓存复用**
- 缓存目录：`getExternalCacheDir()`
- 下载前检查同名 + SHA256 通过 → 跳过下载
- 安装成功后清缓存，`Download/证道/` 成品保留
- rootfs 最多保留 2 个版本

**验收**：卸载 Hermes 后卡片回 [安装]；清理缓存后释放 > 1GB。

## 4. 存储方案权威结论（防再误读）

> 详见 `docs/ERRATA.md` E-005（含 2026-10-06 晚修订段）与 `已知限制.md`。此处仅摘要，避免再被 P1 的归因误导。

- **方法论（不可改）**：存储类探针禁止用 `run-as` 结论替代 App 真身验证——SELinux 域不同（`runas_app` ≠ `untrusted_app`），行为可能完全不同。
- **技术事实（不可改）**：App 真身下 `/sdcard` 读写均可用；`MANAGE_EXTERNAL_STORAGE` 与基础 `/sdcard` 访问**无关**（真身读写都通，不依赖它）。让 `/sdcard` 通的是"摘 READ 帽子（`d414dca`）+ READ/WRITE 运行时授权 + `--bind`"。
- **产品决策（可随新指令调整）**：2026-10-06 晚用户定——MANAGE 升为**主路径引导**（非阻塞首启引导，已落 `cac93b2`）；SAF 镜像同步待真机验证后**删除**（P1.5）。
