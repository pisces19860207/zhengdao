### 🔴 P2：OpenCode 内置 + 按需下载

**目标**：把 OpenCode 作为证道默认 Agent，按需下载，不进 APK、不进 rootfs。

**内容**：
1. **bionic 版**（跑在 Android 宿主，非 PRoot）：零依赖，~66MB
2. 首次启动后台并行下载（与 rootfs 下载并行，进度合并显示）
3. **副本**存到 `Download/证道/opencode/`（用户可见，卸载重装不丢）
4. SHA256 校验，通过后**释放到 `/data/data/证道/files/opencode/`**（真正可执行的真身）
5. 设置页加「检查 OpenCode 更新」按钮（用户主动点，不打扰启动）
6. 更新策略：默认不检查、不下载，用户主动触发才检查

> ⚠️ **两份文件各有角色，别放错（2026-10-06 审核补）**：
> - `Download/证道/opencode/` = **下载副本**。作用是"卸载 App 后仍在，重装免下载"。
>   `/sdcard` **不可 exec**（W^X +外部存储 noexec），所以它**不能直接运行**。
> - `files/opencode/`（即 `filesDir`）= **可执行真身**。App 每次启动从这里 exec。
>   但 `filesDir` **卸载即丢**——这就是"卸载重装不重新下载"能成立的原因：**副本还在，真身重新拷一份即可**。
> - 因此安装流程是「下载到副本 → 校验 → 拷进 `filesDir` → exec」，**每次重装都重拷一次**（66MB 拷贝，可接受）。
> - 实现时别图省事直接从 `Download/` exec，会失败；也别把真身放在 `Download/` 后卸载清理逻辑把它删了。

**验收**：首次启动后台下载完成 → 太极 Tab 能启动 OpenCode → 卸载重装 App 后**不重新下载**、但 `filesDir` 内真身被重新释放且能启动。

> 3. 下面第 3 条"WebView 侧边栏"等 UI 细节未实现，属v2 储备。

**目标**：底部新增太极 Tab，作为 OpenCode 的家。

**内容**：
1. **WebView 加载 `localhost`** 的 OpenCode Web UI
2. 启动流程：
   - 检测 `opencode serve` 是否在跑
   - 没跑 → tmux 静默拉起 → 自动进对话页
   - 在跑 → 秒进
3. **左侧边栏结构**：
   - 顶部：模型选择器（当前模型 + 下拉切换）
   - 中部上：会话列表（新建 / 切换 / 删除）
   - 中部下：插件面板（显性化，带开关，默认启用 `opencode-mem`）
   - 底部：设置入口
4. **数据隔离（XDG 四目录）——本节最容易做错的一环**：
   - **太极 Tab 必须带独立 XDG 启动，洞天 Tab 保持默认路径、不得注入任何 `XDG_*`**。
   - **机制：`/usr/local/bin/taiji` wrapper 脚本**（`ProotLauncher.kt` 启动前自动预置）。**隔离由 wrapper 承担，不是由 tmux 命令行承担**——pane 主程序必须是 `/usr/local/bin/taiji`，直接写 `opencode` 会绕过 wrapper、四个变量全不注入，两边共用 `/root/.local/share/opencode` 正是要防的打架。
     ```sh
     # /usr/local/bin/taiji（由 App 写入 rootfs，勿手改）
     #!/bin/sh
     export XDG_CONFIG_HOME=/root/.zhengdao/taiji/config
     export XDG_DATA_HOME=/root/.zhengdao/taiji/data
     export XDG_CACHE_HOME=/root/.zhengdao/taiji/cache
     export XDG_STATE_HOME=/root/.zhengdao/taiji/state
     mkdir -p /root/.zhengdao/taiji/{config,data,cache,state}
     exec /usr/local/bin/opencode
     ```
   - **对应的tmux 会话命令**（由 `ProotLauncher` 构造，**不要在别处再写一遍**）：
     ```bash
     # 太极：pane 主程序 = taiji wrapper，XDG 由 wrapper 注入
     exec tmux new-session -A -s taiji /usr/local/bin/taiji
     # 洞天：pane 主程序 = 登录 shell，不注入任何 XDG_*
     exec tmux new-session -A -s zhengdao
     ```
   - ⚠️ **不要把 `XDG_*=` 直接写在 `tmux new-session` 的命令行前置环境里**：`tmux new-session` 不接受 `VAR=val` 前缀语法（会被当成命令名），且 tmux server 的环境继承自**首个**创建它的进程——server 先由哪个 Tab 拉起，就继承谁的环境。wrapper + 独立会话名是唯一可靠解法。
   - **洞天的"默认 XDG"不是空值**：guest 默认 `HOME=/root` ⇒ `XDG_DATA_HOME=/root/.local/share`、`XDG_CONFIG_HOME=/root/.config`。验收时洞天进程读到的应是这两个路径，而非"变量不存在"。
   - **宿主 bionic 版的 XDG 是另一套**：`TaijiScreen.kt` 走宿主环境不经 PRoot，XDG 落在 `filesDir/taiji/{config,data,cache,state}`、`HOME=filesDir/oc/home`。**太极 Tab 因此存在两套 XDG 路径**（宿主 `files/taiji/*` + guest `/root/.zhengdao/taiji/*`），排障时先确认查的是哪一套。
   - **会话隔离**：`zhengdao`（洞天，主会话，可 kill-server）与 `taiji`（太极，副会话）共存于同一 tmux server。**只有 `zhengdao` 允许 `tmux kill-server`**，太极 kill 会连带杀掉太极会话（`ProotLauncher.kt` 已加此注释与分支）。
5. **首次进入引导**：免费模型（`/models` 带 `-free` 后缀）+ 明示"免费模型数据可能用于改进模型，勿提交机密"
6. 状态卡含「停止服务」「历史」

> 🔺 **v3.12 技术选型裁定（2026-10-06）：太极 Tab 长期方案 = Compose 原生 UI 直连 OpenCode HTTP API**
>
> **根因**：bionic 版 OpenCode 的 **TUI 模式启动即退出**——OpenTUI 渲染库被 Bun 嵌在虚拟文件系统（`$bunfs`）里，Android linker 无法 `dlopen` 虚拟路径。这是**上游已知问题**（opencode#12515 / #8620），社区解法是给 bunfs 做 dlopen 拦截（等于给别人的运行时打补丁），成本与不确定性都高。**serve 模式不受影响**。
>
> **裁定**：用 **Compose 原生 UI 直连 `opencode serve` 的 HTTP + SSE API**，替代 WebView。完整裁定见 `证道-太极Tab技术选型裁定.md`。
>
> **为什么这条路更好**（不只是换渲染层）：
> - 不需要 TUI 渲染库，绕开上游 bunfs 问题
> - API 面够用且是一等公民：REST + SSE + OpenAPI 3.1 spec + 官方 SDK（会话列表 / 发消息 / 流式收 / 权限批准 / todo / diff 全有）
> - 顺带解掉三个既有问题：**WebView 常驻内存**、**中文 IME 输入**（v3 §3 列为"高风险持续投入项"，Compose `TextField` 走标准输入通道，风险大幅下降）、**cleartext**（实测 `AndroidManifest.xml:27` 已配 `usesCleartextTraffic="true"`，从未被拦）
> - **额外收益**：SSE 给的是**结构化事件**（`message.part.updated` 带 `delta`、`permission.asked`、`todo.updated`），比 TUI 的"终端画面"信息更丰富——可做工具调用折叠、todo 内嵌、diff 高亮
>
> **🔴 前置门槛（阶段 0 先验证，不过则方案要重设计）**：OkHttp 直连 `127.0.0.1:14000` + Basic auth header 能否过鉴权拿到 `GET /global/health` 200。
> 现有 `LocalProxy`（`oc/LocalProxy.kt`）是为 WebView 造的（因为 WebView 的 401 不触发 `onReceivedHttpAuthRequest`）；**Compose 方案应在 OkHttp `Interceptor` 里直接注入 auth，不必再走本地代理**。
>
> **必须提前定的三个取舍**（不定会中途返工）：
> 1. **`directory` 参数**——建议太极 Tab **只绑 `/workspace` 单会话**，不做目录选择器（与会话/文件/权限三类接口全部相关）
> 2. **SSE 长连接**——切后台降级为长轮询，回前台重连后先 `GET /session/{id}/message` 补齐断线期间消息（复用现有 2 秒 `serveRunning()` 轮询）
> 3. **权限批准 UI**——`permission.asked` **不可省**，不实现则 Agent 要改文件时卡死。建议底部抽屉 + 显示工具名与目标（不能盲批）
>
> **别用官方 JS SDK**（`@opencode-ai/sdk` 是 JS/TS 的，引入要塞 JS 运行时，本末倒置）。用 `packages/sdk/openapi.json` 生成 Kotlin/OkHttp 客户端，或先手写 5 个核心端点验证。⚠️ 事件字段名要按**实际打包版本**（当前 `VERSION = "2.0.22"`）的 spec 核实，文档横跨 v1/v2/v3 会变。
>
> **实施顺序**：阶段 0（鉴权验证，不写 UI）→ 阶段 1（消息收发最小可用）→ 阶段 2（权限批准 / 工具调用 / todo / diff）→ 阶段 3（WebView 下线，删 `LocalProxy`）。TerminalView 在太极 Tab 不再使用，**洞天继续用**（职责分离）。

**WebView + localhost 方案为何废弃**（保留结论，避免后来者照旧实现）：
`targetSdk 28` 恰落在「API 28 起默认禁止明文 HTTP」的行为变更线上（`usesCleartextTraffic` 默认 false），WebView 加载 `http://localhost:PORT` 会被系统直接拦掉（`net::ERR_CLEARTEXT_NOT_PERMITTED`）。若将来仍要回到 WebView 方案，必须先加 `network_security_config.xml` 且**仅**对 `localhost` / `127.0.0.1` 开cleartext（`localhost` 与 `127.0.0.1` 在 `<domain>` 里是两条，不通配），其余域名保持禁止明文。

## 4. 存储方案权威结论（防再误读）

> 详见 `docs/ERRATA.md` E-005（含 2026-10-06 晚修订段）与 `已知限制.md`。此处仅摘要，避免再被 P1 的归因误导。

- **方法论（不可改）**：存储类探针禁止用 `run-as` 结论替代 App 真身验证——SELinux 域不同（`runas_app` ≠ `untrusted_app`），行为可能完全不同。
- **技术事实（不可改）**：App 真身下 `/sdcard` 读写均可用；`MANAGE_EXTERNAL_STORAGE` 与基础 `/sdcard` 访问**无关**（真身读写都通，不依赖它）。让 `/sdcard` 通的是"摘 READ 帽子（`d414dca`）+ READ/WRITE 运行时授权 + `--bind`"。
- **产品决策（可随新指令调整）**：2026-10-06 晚用户定——MANAGE 升为**主路径引导**（非阻塞首启引导，已落 `cac93b2`）；SAF 镜像同步待真机验证后**删除**（P1.5）。
