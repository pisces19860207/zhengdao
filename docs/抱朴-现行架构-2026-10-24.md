## 4. 引擎形态（harness）与自进化闭环

### 4.1 harness：一套引擎 + 三个薄管子 + 一个可选的编排模式

- **默认仍是经典 function calling 循环**（模型一次调一个工具、回结果、再下一步）；
- **协议差异只活在「管子」里**：引擎只认 `ToolCall{id, name, arguments}`；三家差异在 `LlmClient` 的 encode 侧（188 收成 `OpenAiWire/GeminiWire/AnthropicWire`）与 `ToolCallCodec` 的 decode 侧（已有）；
- **历史是纯文本**（`HistoryMessage(id, role, text)`＋图片），从不落 provider 原生 `tool_use/tool_result` ⇒ 换模型/换家不会撞结构性 400；代价是模型看不到原生工具配对（188 的门禁钉住这条，183 回答要不要在编排模式里改回原生配对）；
- **编排模式（183，设计单）**：不是"跑模型给的代码"，而是**一次请求多条 tool_calls ＋ 分段预算 ＋ 批边界确认**，省的是"每步一问"的往返与打扰；
- **开闸前置**：189（分段预算＋无进展熔断）与 171（范围授权）先落地；没有熔断就开编排 = 把烧钱放大一个数量级。

### 4.2 自进化闭环（四环，缺一环就退化成"瞎改"）

```
196 学习器/执行器  示教一次 → 技能（JSON 数据，不是代码）→ 可靠回放（自愈只修坏步、技能不自动改）
        ↓
162 反思提炼       从日记/失败轨迹/重复劳动里提候选（每批 ≤3 条，每条带可点开的证据）
        ↓
163 评估           候选 vs 基线，证"行为真的变好"（离线双跑，ADOPT/DEFER/REJECT，不自动晋升）
        ↓
192 免批判据       五条全满足才 AUTO（只写项目技能／纯流程／≤2KB／先落草稿／留痕可撤销）
        ↓
落地 或 退役        用满 3 次没效果 ⇒ 降级/退役；每次改技能是一个 diff，可回滚
        ↓
173 L3（队尾）     把同一套 decide() 扩展到读/写/删/外发，配审计·回滚·急停·额度
```

**四条硬边界**（越了就不是自进化，是事故）：

1. 技能**永远不许改 A 内核、不许改确认行为、不许扩大工具权限**；
2. 任何自改必须有**证据行**（哪天的日记、哪次失败、哪几条产物）；
3. 改完必须过**评估**（163），过不了就回滚，不许"觉得更好"；
4. 全程**审计**（谁改的、改前改后、为什么），可一键停。

### 4.2b 幻觉不是 bug，是前提（2026-10-26 用户定）

> 用户原话：「模型永远有幻觉，就像人一样也会。如果多了可见的预测和审计结果，人才能做出更好的判断再去实施某个行为」；
> 「要是某个决定或者行为可以预见，人也会斟酌一下的；再加上审计和审核的后果，人也会自己规避的」。

harness 的全部意义，就是在"模型会编"这个前提下，**把错误挡在三个位置**：

| 位置 | 干什么 | 我们的落点 |
|---|---|---|
| **事前** | 让模型和人都**看见会发生什么**，以及**这一步该不该问** | 219 风险矩阵（R0–R3＋reasonCode）／220 影响提示（覆盖几个文件、涉几条台账） |
| **事中** | 不可逆的不许自己动手；慢/卡了要能降级 | 确认卡（171 范围授权）／硬拦（原件区·密码框·内网 URL）／300ms 超时降级／停止与插话（189/176） |
| **事后** | 错了能看见、能撤、能变成规则 | 208 决策中心（六类＋自治四类留痕、分组卡、回滚）／抽检转回归样本／173 的额度与急停 |

**三位置烙进四个"器"里（2026-10-26 用户：让它们各自带着这个烙印）**

| 器 | 事前的烙印 | 事中的烙印 | 事后的烙印 |
|---|---|---|---|
| **学习器**（196 录制） | 落盘前先出"将写哪几个文件、几条草稿" | 危险文本按钮一律拒点、密码框拒填 | 草稿标"未验证"＋来源 `seed/teach`，可删 |
| **执行器**（196 回放） | 每步 expect 断言＋结构指纹（不符就停） | 命中多个/低置信即停，不硬点 | 每步截图取证、失败即停、可回放重试 |
| **分类器**（219） | 给 R 档＋`reasonCode`（可解释） | 未分类即按 R2 必问（fail-closed） | `matrixVersion` 留档；抽检标错→回归样本 |
| **反思器**（205） | 候选必须带 ≥2 条证据才出 | 确认前零写盘（不自己动手） | 决定与效果写回进化档案，可回滚/退役 |

**它们共用一个原则**：**模型负责"想"，器负责"看得见、拦得住、记得下"**。

**准入规则（以后谁要加"自治"能力，先回答这三问）**：
1. 事前：用户/模型能不能看见后果？看不见就补影响提示；
2. 事中：出现不可逆动作时，谁拦住？拦不住就不许自动；
3. 事后：做错了怎么发现、怎么撤、怎么变成规则？答不上来就别上。

**没有这三层，模型再强也只是"更会编的脑子"**：编的时候没人拦，编错了没人记。
用户补充的那条很重要——**可预见性本身就是一种约束**：能预见 ⇒ 人会斟酌；有审计后果 ⇒ 人会自己规避。

### 4.2d 行业现状：同构产品极少 ⇒ 判据自己定（2026-10-26）

用户让外部检索核过：**"手机端本地 agent ＋ 学习/执行/反思/评测闭环 ＋ 分类器 ＋ 影响提示 ＋ 审计回滚"这类产品极少极少**。
这与我们此前的判断一致：零件各有先例（技能、录制回放、反思、评测、分类器、审计日志），**拼成闭环的几乎没有**。

**因此两条工作方式（写给以后接手的人）**：

1. **不找"别人怎么做"当依据**——没有参照物时，"大家都这么做"这句话本身不成立；判据要落在**我们自己的场景**上（物流表、司机电话、日记、台账），并且**写成可测的负例**；
2. **但也不把"少见"当护城河**——少见可能因为"需求不硬"或"成本过高"。我们的价值在**琐碎真实场景的贴合度**，不在技术炫技。

### 4.2c 两种模式：玩要尽兴，活要零错（2026-10-26 用户定）

> 用户原话：「该玩的时候就好好玩（文学类），该认真的时候就认真仔细的工作（不能出错的）」。

**领域决定"标准"，档位决定"问不问"**——两者正交，别混：

| 维度 | **创作模式**（小说/微头条/角色卡/风月制卡） | **工作模式**（物流查单/对账/报表/客户/涉钱涉货） |
|---|---|---|
| 态度 | 放开玩，允许发挥、允许发散 | 严谨、可核对、**不许猜** |
| 影响提示 | 弱提醒（不阻断、不用警示色） | **硬**：未完成不许进下一步，或必须填原因 |
| 数字与字段 | 允许模糊表述 | **必须来自表/证据**；缺字段写"未填"，禁推算 |
| 拒答 | 尽量给东西 | **查不到就说查不到**，宁缺毋滥 |
| 确认 | R1 可连做；R2/R3 仍问 | R2/R3 **逐项问**；批量必问 |
| 失败处理 | 可重试、可换风格 | 停手报错，**不许绕过** |

**判定**：按工作区/会话所选模式；**判不出按工作模式**（从严）。两模式都不改 R3/原件区/真删的硬拦。

### 4.3 与 Google Harness² 的关系（只抄结构，不引运行时）

Google Research 2026-10 开源了 [Harness²](https://github.com/google-research/harness2)（[报告](https://arxiv.org/pdf/2610.14224)，Apache 2.0）：**不动模型权重，改「执行环境」**——系统提示、行为准则、记忆、工具使用指南、子 Agent、技能、脚本、插件八件；机制是**双层递归**（任务级 `Propose → Probe → Compose`；harness 级把经验攒成档案复用）。

我们与它的异同：

| 维度 | Harness² | 我们 |
|---|---|---|
| 不改权重、改环境 | ✅ | ✅（技能是文件＋索引＋审计） |
| 技能/流程是可改件 | ✅ | ✅（196 学、184 写、192 放行） |
| 提案 | 自动 | **人批**（162 提候选，带证据行） |
| 对比 | Probe：同任务不同配置比行为 | 163：离线双跑＋**对比表**（行为列＋结果列，两步不许合并） |
| 组合有效改动（Compose） | 自动 | 暂不做（等 162/163 跑稳） |
| 经验档案 | `EXPERIENCE.md` | `<工作区>/产物/进化档案.md`（append-only，162 §1.5） |
| 运行时 | Python 3.12+、OpenCode/Codex、迭代预算 | **不引**：手机端不搬 |

**抄什么**：经验外置成档案、行为对比与结果验证分两步、改动要有证据。
**不抄什么**：自动 Compose 迭代（预算不可控）、执行器形态、把权限扩大当"能力提升"。

**为什么这条闭环在手机上是安全的**：技能是文件＋索引＋审计，不是权重；回滚是删一个文件、退役是改一行索引。


### 4.4 治理形态：三权分治 ＋ 调解（2026-10-26 定）

> 对外只讲**角色与边界**；判据、阈值、额度算法、调解策略属**私有细则**（未随公开仓发布）。

```
分类器（判档） → 推演（给意见） → 审计（自报的账） → 勘验（独立复核） → 执行
                                                        ↘ 人（御批：重要节点）
```

| 角色 | 谁 | 边界（一句话） |
|---|---|---|
| **行政** | 模型 | 低风险直行，改外部/不可逆要人点头 |
| **立法** | 分类器＋技能契约 | 契约不可被模型自行放宽 |
| **司法** | 勘验（只读） | **只查不判**，不替人裁决 |
| **终审** | 人 | 只看被挑出来的重要节点 |
| **调解** | `HarmonyMediator` | 在刚性制度下管理人机协作的体验：把"拒绝"变成可接受的建设性反馈，并在"办事"与"学习"两种状态间切换 |

**与常见做法的一个方向差异**：业界的中介层多是把关式——`ALLOW / DENY / ESCALATE`，本质是**强制拦截**（谁能过、谁不能过）。
这里的**调解**管的是**关系**：把拒绝讲成能接受的话、避免双方互相点火、在"办事"与"学习"之间换挡。**机制细节不公开**。

**三条对外可讲的原则**：①判据高于隐喻；②一切副作用留痕且可回滚；③不可逆必须人批。

## 5. 选型原则：先用现成的，别重造

| 需求 | 现成方案 | 怎么用 |
|---|---|---|
| 跨会话搜索 | **仓库现成的 `tokensOf` 分词 ＋ `KbRetriever` 打分 ＋ `scanTree` 扫描**，落私有 `search.db` 倒排普通表 | 系统 SQLite **没有 FTS5**（真机实测 `fts5` 串 0 次、AOSP 只编 FTS3/4；且无 Robolectric ⇒ 虚拟表在 JVM 不可测）⇒ 不用虚拟表，用普通表＋纯 Kotlin 判据，能进全量单测 |
| 定时任务 | WorkManager＋按需精确闹钟 | 默认非精确；不常驻 |
| 相册/文件 | MediaStore / SAF | 用户图进相册（`ContentResolver`＋`IS_PENDING`）；自身文件走归属清单 |
| 长文渲染 | Markwon / CommonMark | 不自己写 Markdown 解析 |
| 函数 schema | JSON Schema 校验器 | 不手写 provider 规则 |
| MCP | 官方 SDK / Streamable HTTP | 不自造传输 |
| 图表 | Chart.js / Mermaid（可选沙箱） | 先 artifact；需要再 bundle |
| 记忆反思 | mem0/Letta 的“提炼＋检索”模式 | 抄模式，不引服务端 |
| 评测 | Promptfoo/Braintrust 的 fixture/对拍模式 | 离线跑，不接云 |
| durable/编排 | Temporal/LangGraph 的 checkpoint/事件日志模式 | **不引运行时**，只抄结构 |
| 浏览器自动化 | Playwright/Puppeteer 不适用 Android | 自己接 WebView/截图/操作；**定位走十级语义优先级＋置信度门控**（196） |

**硬原则**：边缘能力尽量用库；核心闭环（A/B/C、确认、决策中心、证据链、中文 UI）自研；云服务/重运行时（Temporal/LangGraph/Playwright/React）不硬搬，报告写“为什么不用”。
