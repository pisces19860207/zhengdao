# 小说库 · 零 token 工作规程

> **给 AI 看的**（可直接并入 `Download/小说/AGENTS.md`，或系统提示）。
> **目标**：读这份 6664 本 / 2.1 GB 的书库，**别再烧 token**。
> 全部手段都是 **纯文本命令**（grep / sed），**不调用任何模型**。

---

## 一、铁律：**绝不整本读**

一本《永生》全本 = **15.8 MB ≈ 500 万字**。
**整本读进来 = 一次烧爆上下文**，这正是过去"AI 干到冒烟"的根因。

**唯一正确姿势：先挑书 → 再挑章 → 只读那一章（几千字）。**

---

## 二、三步走（每次都照这个来）

### 第 1 步：**挑书** —— 看总目录，不要看正文

```bash
# 直接看总目录（每本书一行：路径 / 大小 / 行数 / 首行线索）
sed -n '1,120p' "/sdcard/Download/小说/_总目录.md"

# 或者按关键词在总目录里找书
grep -n "关键词" "/sdcard/Download/小说/_总目录.md"
```

> 总目录由 `gen_novel_index.py` 生成（零模型）。**过期了就重跑一次**，别手工维护。

### 第 2 步：**挑章** —— 章节列表**当场生成**，不用预存

```bash
# 列出这本书的章节标题 + 行号（只扫标题行，秒出）
grep -n "^第.\{1,10\}[章回节]" "那本书.txt" | head -80
```

> ⭐ **关键**：章节目录**不需要预先切分落盘**（否则 6664 本 × 几十章 = 几十万个文件，反而更乱）。
> `grep -n` **当场**就能把章节和行号列出来，**零成本、零落盘、永不过期**。

### 第 3 步：**只读那一章**

```bash
# 按第 2 步拿到的行号，只把那一章读出来（几千字）
sed -n '1234,1290p' "那本书.txt"
```

---

## 三、找不到词的时候：全文搜（**不要逐个开文件**）

```bash
# 一轮扫 2.1GB，通常几秒
grep -rn --include="*.txt" "关键词" /sdcard/Download/小说/藏书/ | head -20
```

- **一个词搜不到，就换近义词再搜一两轮**（这是"换个说法也能找到"最便宜的替代品）。
- **不要**一上来就逐个打开文件"过目一遍"——那正是费时间、费 token 的老毛病。

---

## 四、⛔ 绝不碰的地方（噪音 + 隐私）

| 路径 | 为什么 |
|---|---|
| `/sdcard/Download/小说/hermes备份/` | 几百 MB 的 `state.db` 备份 + `tar.gz`；**里面可能有会话记录**，且与书无关 |
| `/sdcard/Download/小说/.trash/` | 回收站 |
| `_backup_*` 之类以 `_` 开头的目录 | 历史备份快照 |

**搜书时把上面这些排除掉**，否则"越搜越乱"。

---

## 五、这套规程"省"在哪（对一下账）

| 做法 | 一次要读进来的量 | token |
|---|---|---|
| ❌ 整本读 | 最多 500 万字 | **爆** |
| ❌ 逐个开文件过目 | 几十本 × 整本 | **大** |
| ✅ 查总目录 | 几十行 | 极小 |
| ✅ `grep -n` 列章节 | 几十行 | 极小 |
| ✅ `sed -n` 读那一章 | 几千字 | 小 |
| ✅ `grep -rn` 全文搜 | 命中的那几行 | 小 |

> **一句话**：**让"纯规则"的活干在前面，"模型"只在最后一小步出手。**
> 这就是"白嫖 token"场景下唯一划算的打法。
