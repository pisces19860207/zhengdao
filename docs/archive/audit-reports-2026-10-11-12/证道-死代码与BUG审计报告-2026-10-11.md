## 一、人话版结论（先看这段）

把 App 想象成一间收拾过的屋子：

- **死代码** ≈ 柜子里从没穿过、还占地方的旧衣服。这屋子大概有 **690 行**这样的代码，其中 **536 行**是 8 个"设置页"从同一个模板复制粘贴时，顺手带来的"没用上的引用"——删起来最省事、最安全，等于直接扔掉。
- **BUG** ≈ 衣服扣子缝歪了，看着能穿，一用力就崩，或者穿反了。**没有"一打开必闪退"的硬伤**（作者防御写得挺好），但有若干"特定时机才会炸/功能悄悄失效"的真问题，以及一堆"迟早要出事"的隐患。
- 值得高兴的是：**之前记的两大老 BUG 已经修好了**——Rust 解包空归档兜底已就位；启动重算 SHA256 也加了"戳"机制（首装/升级还会算，平时不卡了）。

现在最该先动手的，是那几个**你用的时候会直接感觉到的**（误杀终端里的 AI、一开 App 弹一串框、切一下 Tab 聊天记录没了、黄点分屏会乱打字）。

## 三、BUG 与实现问题（按严重程度）

### 🔴 A 类：功能错误（你用的时候会直接感觉到）

**A1. 关掉"太极 serve"会顺手杀掉终端里你自己装的 AI【②代码原文】**
- 位置：`oc/OcManager.kt:459-468`
- 现象：匹配串是宽泛的 `"usr/bin/opencode"`。你在终端的 Debian 里自己装的 opencode（同 UID）会被一并 `kill` → 终端里的 agent 莫名其妙死掉。
- 修法：匹配加上 proot 进程树/路径过滤，或只杀由本 App 直接 `exec` 起来的那个进程（用 `Process.myPid()`/子进程 PID 记录），不要把整个 UID 下叫这名字的都杀了。

**A2. 一打开 App 弹一串框（权限框 + 版本更新框 + 提示）【②代码原文】**
- 位置：`MainActivity.kt:117-154`、`210-242`
- 现象：已经引导过、但还缺权限的"回程冷启动"，会连弹系统权限框 + 后台线程的"发现新版本"对话框，容易误点"拒绝"。
- 修法：把这条补漏路径也收进 `PermissionSetupScreen` 一页；版本更新框只在"当前没有别的对话框在显示"时才弹（加一个"是否已有对话框"的判断）。

**A3. 切一下底部 Tab / 转屏，太极聊天记录偶尔没了【②代码原文 + ③推断】**
- 位置：`ui/taiji/TaijiScreen.kt:110,127-130,241-264`
- 现象：`savedSession` 靠 `rememberSaveable` 存，切 Tab 时组合被整体卸载重建，万一某次没恢复成功拿到 null，`repo.open(null)` 就会**新建会话**，历史短暂丢失。
- 修法：把 `savedSession` 移到进程级的 `OcRuntime` 单例里，彻底脱离界面生命周期。

**A4. 黄点"关分屏"会乱打字、分屏数算错【②代码原文】**
- 位置：`TerminalActivity.kt:149-162`
- 现象：发 `C-b x` 杀分屏后立刻把计数 −1，并在 250ms 后无条件补发 `y`。若当时 pane 不在确认提示（比如程序正读输入），`y` 会被当普通输入打进活动程序；计数和真实分屏数对不上。
- 修法：`y` 只在确认提示出现时才发；`paneCount` 只增不减（或每次用 `tmux display -p '#{window_panes}'` 真实查询）。

**A5. 工具卡诊断日志刷屏，每次流式更新都重写一遍【②代码原文】**
- 位置：`ui/taiji/TaijiComponents.kt:766-772`
- 现象：`LaunchedEffect(part)` 的 `part` 是每次 SSE 事件后新建的对象，所以每次重组都重新执行、把同一工具卡的日志反复写进 `RunLog`，还附带着字符串拼接 + 落盘。
- 修法：key 改成稳定标识（如 `part.toolName + messageId`），或只在首次解码时打一次。

**A6. 安装/更新结果提示可能显示"null"【②代码原文】**
- 位置：`ui/taiji/TaijiScreen.kt:715,766`
- 现象：若 `r.message` 为 null，`Toast.makeText(ctx, r.message, …)` 会显示字面的 `null`。
- 修法：`r.message ?: "完成"` 兜底。

### 🟠 B 类：稳定性 / 并发隐患（特定时机才炸，但真会炸）

**B1. 会话对象跨线程读写没加可见性保护，可能闪退【②代码原文】**
- 位置：`terminal/SessionManager.kt:67`（`session`/`startedAtMs`/`isFallback` 非 `volatile`）+ `TerminalActivity.kt:1356-1361`
- 现象：安装后台线程 `kill` 置 null，主线程 `start` 置新对象，两者交错时主线程可能读到半初始化会话，交给 `termView.attachSession` → Termux 内部抛异常闪退。
- 修法：这三个字段加 `@Volatile`，或用 `Mutex` / 统一到主线程串行化"创建/销毁会话"。

**B2. 资料库自动附词的行缓冲跨线程无同步，偶尔错乱【②代码原文】**
- 位置：`terminal/KnowledgeBaseHints.kt:117,145-167,193-195,132-135`
- 现象：引擎读取线程（会话结束清缓冲）和主线程（输入/退格/粘贴追加）并发读写同一个 `StringBuilder`，极端情况出乱码/丢字。
- 修法：`line` 换成 `AtomicReference<String>` 或加 `@Synchronized`。

**B3. 开会话时在"安装锁"之外写活的 rootfs，可能污染环境【②代码原文】**
- 位置：`terminal/ProotLauncher.kt:185-361`
- 现象：`buildLaunchPlan` 每次开会话都会写 `/etc/profile.d/*`、`zzclean`、`home/.*` 等，但 `RootfsInstaller.withInstallLock` 只保护"安装与替换"。安装过程中开终端，两边并发改写同一棵 rootfs 树，可能丢配置或瞬时不一致。
- 修法：把会话启动的写操作也纳入安装锁，或串行化（安装时拒绝开新会话/排队）。

**B4. 体检/资源监控可能在主线程做重 I/O，会卡甚至 ANR【②代码原文 + ③推断】**
- 位置：`terminal/ResMonitor.kt:61-82`、`terminal/AgentProcesses.kt:60-76`
- 现象：里面有 `Thread.sleep(700ms)` + 全量扫 `/proc`。当前走 `Thread{}` 调用尚安全，但若哪天被 UI 路径误调到主线程，就 ANR。
- 修法：给这两个函数加"必须在后台线程调用"的硬约束（封装进 `Dispatchers.IO` 或在入口 `check(Looper.getMainLooper()!=Looper.myLooper())` 断言）。

**B5. 解包 OpenCode 时 chmod 打在 `.part` 上，兜底 copy 会丢可执行位【②代码原文】**
- 位置：`oc/OcManager.kt:643-663`
- 现象：正常 `renameTo` 保留 0755；但 rename 失败时走 `copyTo` 兜底，`java.io.File.copyTo` **不复制 POSIX 权限位** → 二进制丢执行位 → `startServe` exec 时 `EACCES`。（当前靠 `startServe` 里的 `Os.chmod` 自愈兜底，不致命，但是隐患路径。）
- 修法：`renameTo` 成功或 `copyTo` 之后，**统一再 chmod 一次目标文件**。

**B6. 两处"RSS 告警阈值"差 4 倍，维护会乱【②代码原文】**
- 位置：`terminal/SessionService.kt:51`（`RSS_WARN_MB=3072`）vs `terminal/ResMonitor.kt:49`（`RSS_WARN_MB=800`）
- 现象：前台服务通知和体检卡用同名常量却差近 4 倍，改一边另一边不跟着变。
- 修法：抽到一处公共常量。

### 🟡 C 类：隐患 / UX 小瑕疵（不急，但建议清）

- **C1 裸线程不纳入生命周期**：`TerminalActivity.kt:600-619` 网络预检、`KnowledgeBaseSummarizerRunner.kt`、`KnowledgeBase.kt` 多处起裸 `Thread`，Activity 销毁后还跑满 5s 才回调（不崩但是泄漏）。改法：用 `viewModelScope`/`lifecycleScope` 或记引用在 `onDestroy` 取消。
- **C2 线程池从不关闭**：`KnowledgeBaseHints.kt:119-121` 的 `worker` 单例线程池进程级常驻、永不 `shutdown()`。可随进程级清理显式关。
- **C3 强耦合 Termux 私有字段**：`TerminalActivity.kt:515,651-653`、`TerminalPrefs.kt:320` 直接读写 `mTermSession`/`mColors` 等 vendored 内部字段，升级 Termux 版本会静默失效。建议封一层兼容访问。
- **C4 粘滞 Ctrl 时回车/退格缓冲被跳过**：`TerminalActivity.kt:793` 整个回车拦截与硬件退格缓冲都包在 `!stickyCtrl` 内 → 点亮粘滞 Ctrl 时输入缓冲"半失联"。
- **C5 双指缩放越界**：`TerminalActivity.kt:761` 字号若被写成 `SIZE_OPTIONS` 之外的值，`indexOf` 返回 −1 会跳回默认档、少一档。
- **C6 `pressClickable` 用了已废弃的 `composed`**，且每次点击都触发"长按级"震动（`Press.kt:44,64`）。改法：迁移到 `Modifier.Node` API；震动改用 `HapticFeedbackType.KeyboardTap`（轻反馈）。
- **C7 权限抽屉返回键无反应**：`TaijiComponents.kt:1198` `onDismissRequest={}` 是有意设计（必须显式选），但用户在里面按返回键像卡死。建议加"稍后"按钮明确退出。
- **C8 `cleanupDelta` 用字符串前缀判越界**：`rootfs/RootfsCache.kt:266` 正是被 `PathGuard` 否定的旧写法（同前缀兄弟目录会误判）。改用 `PathGuard.isInside`。
- **C9 SHA256 实现重复三份**：`ProotLauncher.sha256Of` / `RootfsDownloader.platformSha256Of` / `CoreNative.platformSha256`，收到一个工具函数。
- **C10 手写 JSON 解析器**：`rootfs/RootfsIndex.kt:205-353` 为避开单测 `org.json not mocked` 而自造，维护风险高，建议加覆盖测试或换回成熟库。

## 五、给 DSH / 你的核对清单

- ☐ 上述 BUG 多为【②代码原文】，**但都没真机复现**——合入前建议在真机各点一遍对应场景（尤其 A1 关太极后看终端 agent、A3 切 Tab 看聊天记录、A4 黄点关分屏）。
