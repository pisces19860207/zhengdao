## 发现

### P1 — 未启动的终端会话可能向 PID 0 发信号

- **位置：** `app/src/main/java/com/termux/terminal/TerminalSession.java:63,241-244,269`；调用路径 `app/src/main/java/com/example/zhengdao/terminal/SessionManager.kt:122-126,175-190`
- **证据：** `mShellPid` 的未启动初始值为 `0`，而运行状态/结束逻辑可能把该状态当作可结束会话，并传入 `Os.kill`。
- **触发条件：** `SessionManager.start()` 已构造并保存 `TerminalSession`，但首次视图尺寸更新尚未触发 spawn 时，Activity 被关闭、重路由或执行 kill。
- **影响：** POSIX 对 PID 0 的信号语义作用于调用进程组，风险是杀掉 App 进程组，而非仅结束目标子进程。尚未真机复现。
- **建议：** 只有 PID 严格大于 0 才允许发送信号；区分“未启动、运行中、已结束”状态。增加未 spawn 后关闭/重路由的单测。

### P1/P2 — 解包器未约束硬链接源路径

- **位置：** Kotlin：`app/src/main/java/com/example/zhengdao/rootfs/RootfsInstaller.kt:361-367,488-496`；Rust：`rust/core/src/extract.rs:212-226,246-250`
- **证据：** 归档成员的目标路径有 rootfs 内部检查，但硬链接的 `linkname` 被拼接为源文件路径后直接检查/复制，未确认源仍位于解包根目录。
- **触发条件：** 可控归档含 `../` 或绝对路径的硬链接源，且 App 进程对源文件有读权限。
- **影响：** App 私有目录中可读文件可能被复制进 Debian rootfs，之后可被 guest 读取。官方签名索引和摘要可限制部分远程输入，但不能假设所有离线/无期望摘要安装路径都只接受可信归档。
- **建议：** Rust 与 Java 两条路径统一校验源路径 canonical path 必须位于解包根目录内；覆盖正向/反向硬链接、绝对路径、`..` 和软链交互的测试。最终严重度取决于所有归档入口的信任边界；在确认入口均受可信摘要保护前按安全问题处理。

### P2 — 太极消息轮询可能提前清除生成状态

- **位置：** `app/src/main/java/com/example/zhengdao/oc/OcRepository.kt:238-255`；UI 状态消费在 `app/src/main/java/com/example/zhengdao/ui/taiji/TaijiComponents.kt:1058-1126`
- **证据：** 某轮消息列表无变化时，代码把 `isStreaming` 设为 `false`；消息后续变化分支没有明确恢复为 `true`。
- **触发条件：** 服务端仍在生成，但一次轮询取回的消息列表与上一轮相同。
- **影响：** UI 可能提前显示生成结束、允许重复发送；未发现覆盖该状态转换的测试。
- **建议：** 以服务端明确的运行/终态判定完成，而不是仅以消息列表是否变化；添加轮询相同、工具执行中、完成、失败等状态机测试。

### P2 — 模型选择的本地状态与服务端状态可能分叉

- **位置：** `app/src/main/java/com/example/zhengdao/ui/taiji/TaijiScreen.kt:495-503`；`app/src/main/java/com/example/zhengdao/ui/taiji/ModelSheet.kt:140-149`；`app/src/main/java/com/example/zhengdao/oc/OcRepository.kt:571-585`
- **证据：** 选择“默认”只清除本地 override；选择具体模型时先持久化本地选择，再异步请求服务端，未处理请求失败。
- **触发条件：** 当前会话已有模型覆盖后选择默认，或选择模型时服务端请求失败。
- **影响：** 服务端仍可能沿用旧模型，或 UI/持久化显示未成功应用的模型。
- **建议：** 明确“默认”是否需要服务端重置；让 UI 状态在请求成功后提交，失败时给出错误并回滚/允许重试。为成功、失败与重进页面补测试。

### P2 — 停止太极服务的孤儿进程扫描范围过宽

- **位置：** `app/src/main/java/com/example/zhengdao/oc/OcManager.kt:455-468`
- **证据：** 除销毁应用持有的 `serveProcess` 外，还扫描 `/proc/*/cmdline`，命令行只要包含 `usr/bin/opencode` 即调用 `killProcess`。
- **触发条件：** 同 UID 下其他进程（例如终端 guest 进程）呈现匹配命令行。
- **影响：** 可能误杀用户在终端中启动的 OpenCode。匹配范围过宽可由源码确认；具体 guest 命令行表现需真机核验。
- **建议：** 只管理本 App 启动并记录的 PID/进程句柄；若必须清理孤儿，采用严格的父子关系及可验证身份，不只按子串匹配。

### P3 — 存储操作异常会被当作正常的“零结果”

- **位置：** `app/src/main/java/com/example/zhengdao/ui/SettingsDataActivity.kt:213-219`；`app/src/main/java/com/example/zhengdao/ui/SettingsStorageActivity.kt:175-181`
- **证据：** 操作结果通过 `getOrElse { 0 to 0L }` 把异常转换成零计数，随后走正常完成反馈。
- **触发条件：** 权限或文件 I/O 失败。
- **影响：** 用户收到“没有内容/零项”一类成功形态反馈，而不知道实际操作失败。
- **建议：** 区分失败与零结果；错误应明确通知并记录异常。
