## 一、它是什么（一句话）

用户在终端里按回车的那一刻，App 先在本机把 `资料库/原始/` 扫一遍，把「**文件名＋行号**」写成**一行**，
追加在他这句话后面一起送进终端 —— 让 agent **不用自己摸索**就能拿到线索。

对应的是 R15-1 那条结论：目录 / `AGENTS.md` 依赖 agent 自觉；要"不依赖它配合"，只能**App 自己查、直接送进去**。
**这不是向量检索**（只是子串匹配），也**不联网**。

## 四、⚠️ 没验的（**请你真机看**）

这正是你当初坚持"先让用户亲眼见一眼再写代码"的那部分，我**没有真机验**：

1. **回车会不会被"吞"一下** —— 检索是异步的（后台线程，上限 1500ms；小库通常几十毫秒）。库很大时，
   用户按回车到出结果之间会有可见延迟。
2. **这块字在三种 TUI 里长什么样** —— Claude Code / Hermes / OpenCode 各自的输入组件，
   对"一行长文本 + 紧接着回车"的反应可能不同。
3. **tmux 历史** —— 注入块随消息进了历史，恢复会话时会不会重复出现（我的实现里**不会重新注入**，
   但历史里那一条是有的）。

## 五、一个**留给你和用户拍板**的形状问题

我给用户看过的样例是「**块在上、用户原话在下**」；**实现是"块追加在用户原话后面"**。

原因（写进 ERRATA 了）：终端是**逐字符**送进 AI 的，用户打字的同时字符已经进了 pty，
AI 那侧的输入行里已经有他打的字；App 唯一能插手的时机是**回车按下的那一刻**，而那时只能往后追加。
要做成"块在前"只有两条路：
- ① 扣住用户输入不发 ⇒ **他就看不到自己打的字**；
- ② 发退格把已送出的字符抹掉 ⇒ raw 模式 TUI 里不可控，**抹错就是把用户的话改烂**。

**两条我都没走。** 如果用户看了真机效果后坚持"块在前"，那就得回到方案①（代价：输入回显消失），
需要他当场确认接受，届时另开一支线。
