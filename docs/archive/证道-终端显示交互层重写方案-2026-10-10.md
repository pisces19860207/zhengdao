# 证道终端「显示与交互层」重写方案（Compose 化，保留 Termux 状态层）

**日期**：2026-10-10
**触发**：用户原话「我不喜欢 termux 的会话层、终端状态层、渲染层，很丑很臃肿」「就不能把显示和交互什么的换了吗？」
**状态**：**待拍板的方案**，未动一行代码
**性质**：本方案只换**显示+交互层**，**保留 Termux 的状态层与会话层** —— 这是与「三层全换」的根本区别

## 3. 技术地基（① 已验证可行）

### 3.1 Compose 能不能画等宽终端？能，且不用重写绘制逻辑

Compose 没有内置 `drawText`，但有**逃生口** `drawIntoCanvas { it.nativeCanvas }`（① 多篇官方/社区文档一致）。

⇒ **Termux 现有的 `TerminalRenderer.java:238` 的 `canvas.drawTextRun(...)` 可以原样搬进 Compose 的绘制 lambda。**

```kotlin
Canvas(Modifier.fillMaxSize()) {
    drawIntoCanvas { canvas ->
        val native = canvas.nativeCanvas   // ← 就是 android.graphics.Canvas
        native.drawTextRun(text, start, len, start, len, x, y, false, paint)
    }
}
```

**含义**：渲染质量与性能**与现在持平**（同一个 `Paint`、同一条 `drawTextRun` 路径）。**这一步没有性能风险。**

### 3.2 证道本来就在用 Compose

- `build.gradle.kts:207` `compose = true`
- `MainActivity.kt:180` `setContent { ... }`
- `TerminalActivity` 本身就是 `ComponentActivity`

⇒ **没有"引入新技术栈"这一步**。只是把终端页从 XML 挪进已有的 Compose 体系。

⚠️ 但要注意：`TerminalActivity` 现在是 `setContentView(activity_main)` 的 XML 路线，**改成 `setContent` 就等于换掉整页布局**（含三个交通灯圆点、快捷键条、横幅）。这是本方案最大的一处工作量，也是最容易被低估的一处。

### 3.3 快捷键条：18 个 id，两份已一致

`res/layout/term_keys.xml` 与 `res/layout-w600dp/term_keys.xml` **各 18 个 id，集合完全一致**（② 实测，满足记忆里那条约束）。

18 个 id：`key_backspace` / `key_bar` / `key_ctrl` / `key_down` / `key_end` / `key_esc` / `key_home` / `key_interrupt` / `key_left` / `key_minus` / `key_pgdn` / `key_pgup` / `key_pipe` / `key_right` / `key_shift` / `key_slash` / `key_tab` / `key_up`

⇒ Compose 化时**逐 id 一一对应，行为可核对**。这是可验证的等价改写，不是重设计。

```
│   termux.c 218（保留，CMake 构建）        │
└───────────────┬─────────────────────────┘
                │ 接缝：4 个方法
                │   getEmulator / updateSize / write / writeCodePoint
┌───────────────▼─────────────────────────┐
│ 状态层  TerminalEmulator 2662（保留）    │
│   TerminalBuffer 501 / TerminalRow 283    │
│   WcWidth 566 / KeyHandler 373（保留）    │
└───────────────┬─────────────────────────┘
                │ 接缝：15 个方法
                │   getScreen / getTopRow / setTopRow / isMouseTrackingActive
                │   isCursorEnabled / sendMouseEvent / paste / mRows / mColumns …
┌───────────────▼─────────────────────────┐
│ 显示交互层  ★ 全部新写（Compose）★        │
│  TerminalCanvas        绘制（复用 drawTextRun）│
│  GestureController     滑动/缩放/双击/长按     │
│  SelectionController   选区/手柄/复制          │
│  ImeBridge             输入法/硬件键/两种回车   │
│  CursorBlinker         光标闪烁（带生命周期）   │
│  TermKeyBar            18 个快捷键（Compose）   │
│  TermTopBar            三个交通灯圆点          │
│  TermBanner            状态横幅                │
└─────────────────────────────────────────┘
```

**注意 `ImeBridge` 收的是本项目记忆里那条硬约束**：

- 唯一汇合点是 `inputCodePoint()`，**本就会**回调 `mClient.onCodePoint(...)`，**返回 true 可吞码点** ⇒ 截获输入**不必改 Termux 代码**
- 软键盘回车有两种长相（`13` 或 `109+ctrlDown`）
- 硬件回车不经过 `onCodePoint` ⇒ 要在 `onKeyDown` 接
- 快捷键条退格直写 `0x7F`、粘贴走 `SessionManager.write`
- 终端里 `\n` 就是回车 ⇒ 注入文本必须是一行

**这 5 条是本项目踩过的坑，重写时必须原样继承，否则会重新踩一遍。**

## 6. 风险与红线

| 风险 | 级别 | 说明与对策 |
|---|---|---|
| **Compose 文本测量性能** | 🟡 | `TerminalRenderer.java:111` 只有 ASCII 走缓存，中文每码点每帧一次 `measureText`。Compose 侧**沿用同一套 `Paint` + 加宽度缓存**即可（`SparseArray<Float>`，十几行）。**P0 先量再决定要不要优化。** |
| **整页布局从 XML 换 Compose** | 🟡 | `activity_main.xml` 里三个圆点、横幅、快捷键条、画布留白容器全在同页。工作量比"换个画布"大。**P2 一次性做完，别分两次改这一页。** |
| **IME 组合输入回归** | 🟡 | 记忆里有专门的中文输入丢字/重复上屏问题。⇒ **P4 必须真机验中文输入、两种回车、软硬键盘**。 |
| **tmux 触摸滚动语义** | 🟢 | 鼠标跟踪开启时，本地回滚缓冲不可用（`TerminalView.java:186` 注释已写明是取舍）。重写时**保持同样语义**，别以为是 bug 去"修"。 |
| **快捷键条 18 个 id 行为漂移** | 🟢 | 逐 id 一一对应，**顺序不能变**。P2 后用 id 清单逐个核。 |
| **撞 targetSdk 28 生死线** | ✅ | **不撞** —— 本方案不新增任何 native 库、不改 `libtermux.so`、不碰 proot 启动链。（**这与"三层全换"最本质的区别。**） |
| **CI 构建链** | ✅ | **不动** —— 无新增 `.so`、无 cargo-ndk、无 Zig。（同上） |
| **GPU / wgpu** | ✅ | **本方案不涉及**。渲染仍是 `android.graphics.Canvas`（硬件加速）。若日后单独要 GPU，那是**另一次决策**，按当时的三层分析重新评估。 |

| | 本方案（换显示交互层） | 三层全换（含 wgpu GPU） |
|---|---|---|
| 撞 targetSdk 28 生死线 | ✅ **不撞** | 🔴 **撞**（新增 GPU native 库） |

| 新增 native 库 | 0 | wgpu + 字体栈（+ 体积） |
| **解决"丑"** | ✅ **对症** | 换了个语言，**照样丑**（照现在写法重写） |

**一句话**：本方案解决的是你真正说的那个问题（显示与交互），且**零撞线、零新工具链**；三层全换解决不了「丑」，却要付全部代价。
