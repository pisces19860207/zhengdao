## 0. 一句话

把 L2.5 的「提案落盘后自动跑 eval 10 例 ＋ 红线 diff，不过自动回滚」从**目标**变成**真运行时**。v1 只覆盖**文本层提案**（人设 B/C、技能索引）；**技能正文本身不在 v1 的 eval 覆盖内**（现 10 例不测技能正文，见 §2 边界）。

> **一条不许含糊的硬约束**：eval 必须用**落盘后的有效人设**（A 内核 ＋ B/C 当前文件内容）拼系统提示。现有 `EvalHarness` 只用 `BaopuPreset.personaText`（A 内核），拿它直接跑＝测的是旧人设，**自检就是演戏**。做不到这一点就停下来报告，不要交一个「跑了但没测到」的版本。

## 2. v1 范围（只做这些，别扩）

**做**：
1. **运行时 eval 核心**：把 `EvalHarness` / `EvalCase` 从 test 抽到 main（或 main 里新写一个 `RuntimeEval` 并让测试复用同一实现），保持 10 例语义不变；配当前 provider（baseUrl/model/key 来自 `ProviderPrefs`）；无 key / 通道不可用 ⇒ **明确报「自检未跑（无可用通道）」**，不许假装通过、不许回滚。
2. **用落盘后的人设跑**：eval 的系统提示 = `PersonaRules.assemble(BaopuPreset.personaText(dir), 当前 B, 当前 C)` 拼接结果（提案已落盘，读到的就是新版）。为此给 harness 增加「systemPrompt 由调用方注入」的口子，不要复制第二套拼装。
3. **绑定到「模型提案被用户采纳」这一条路**：
   - 人设 B/C 提案：`BaopuChatController` 采纳后（`:1459` 附近）跑自检；
   - 技能正文/索引：走 `SkillStore.apply` 后，若**索引（B/C 人设）被改**，跑同一套自检；技能正文本身不在 eval 覆盖内，报告里必须写明；
   - **不**在 `PersonaFiles.applyProposal` 里无脑挂 eval（它也被设置页、索引写入调用）；不挂在「生成提案」阶段；**不**改手动编辑页面（`BaopuSettingsScreen` / `BaopuSkillCard` 的手写保存）——那是用户自己的编辑，不是模型提案。
4. **红线 diff（路径级）**：提案落盘前记录将改的文件，落盘后核对：路径必须落在允许集合（人设 B/C 文件、技能目录）；命中 L2.5 禁改前缀（`terminal/`、`rootfs/`、`browser/`、`baopu/agent/`、`eval/`、`清单/`）⇒ 视为红线命中，**先回滚再报**。App 里没有 git，不要假装跑 `git diff`。
5. **自动回滚**：落盘前对**所有将改文件**记 sha256 ＋ 走既有备份原语；自检失败或红线命中 ⇒ 用 `PersonaBackup.restore` / `SkillStore.restore` 恢复到落盘前，**逐文件核对 sha256 与落盘前一致**；任一文件回滚失败 ⇒ 明确报「回滚失败」＋ 路径，不许说「已回滚」。
6. **界面提示**：复用现有便签/通知位（不新造大组件），至少四种状态：`自检中…` / `自检 10/10 通过（Xs，约 ¥Y）` / `自检失败，已回滚（sha256 一致）` / `自检未跑（无可用通道）`。**单飞**（同一时刻只跑一个自检），不阻塞主线程，不挡用户继续聊。
7. **用例打包**：`eval/cases.json` ＋ `eval/baseline.json` 走构建期复制进 `assets/eval/`（照 `stageLicenseAssets` 的房型），仓库 `eval/` 是唯一真源；加一条门禁/断言：assets 副本与 `eval/` 逐字节一致，防漂移。

**明确不做（v1）**：
- 不用 eval 验证技能正文（10 例不测技能；要测得先加技能用例，另单）；
- 不做自动采纳/自动改提示词（用户仍要点确认；自检只在落盘后）；
- 不做 L3、不改 A 内核/工具权限/路径红线/评测基线；
- 不引新依赖、不重写 UI。

## 3. 实现约束

- `EvalHarness` 的 10 例语义、判据、容差不变；只是入口从 test 变成 main 可调。
- 临时工作区用 App `cacheDir/eval-<uuid>`，跑完删除；不写 `filesDir` 业务目录。
- 单次成本/时长：10 例约 27–40 秒、约 ¥0.09（以实测为准）；提示里要报真实读数，不写死。
- 并发：`AtomicBoolean`/Mutex 单飞；App 退后台/被杀不要求补偿，但下次启动不能把「自检中」永远显示（按时间/重启清理）。
- 超时：总上限（建议 120s）＋单例超时；超时按失败处理并回滚，不允许挂死。
- 日志：自检开始/结束/回滚结果落 RunLog（不含 key、不含人设正文）。

## 4. 测试（先红；不许只测纯函数）

- **假 eval 注入**：让 harness 接受一个 `runEval: suspend () -> EvalReport` 或等价 seam；JVM 里用假实现，不联网、不烧额度。
- 用例：
  1. 假 eval 10/10 ⇒ 文件保留、提示「通过」；
  2. 假 eval 9/10 ⇒ 文件恢复到落盘前 sha256、提示「已回滚」、索引未更新；
  3. 假红线命中（构造一次越界写）⇒ 回滚且报红线；
  4. 无 key/无通道 ⇒ 保留、提示「未跑」，**不**回滚、**不**报通过；
  5. 回滚原语自身失败（只读文件/故意让 restore 失败）⇒ 明确报「回滚失败」＋路径，不谎报；
  6. 单飞：并发两次采纳，第二次不并行跑、不互相回滚。
- **负例**：把「用落盘后人设」改回 `BaopuPreset.personaText` ⇒ 至少一条用例红（证明它真的测到了人设）；去掉回滚 ⇒ 红；去掉红线检查 ⇒ 红。逐字节复原并附 sha256/`git status`。
- 全量单测 0 失败/0 错误，跳过数不恶化；lint 预算不升；真实 10 例若本机有 key 就跑一次并附读数（没有就写「未跑真实 eval」）。
