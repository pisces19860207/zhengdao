## 0. 四步是什么，为什么要按这个顺序

| 步 | 做什么 | 不改会怎样 |
|---|---|---|
| ① B/C 保护闸 | 写类工具撞人设文件/技能索引文件 ⇒ **直接拒** | C 层 `人设-本项目.md` 就在工作区里，`write_file` 能直接覆盖 ⇒ **绕过提案、绕过备份、绕过留痕**（当前真实漏洞） |
| ② 「这次学到」提案卡 | 任务收尾自动出一张卡：这轮学到什么、建议怎么记 | 它现在悄悄写草稿技能，你看不到它学了什么 |
| ③ 提案落盘前过门禁 | 采纳前自动校验：危险指令、未实测没标、与既有技能冲突 | 长本事没有验收口，越用越脏 |
| ④ 人设回滚入口 | B/C 改坏了能恢复上一版 | 技能有备份能恢复，人设没有 |

**边界（不许动摇）**：A 内核 `baopu/BaopuPreset.kt` **永远只读**，任何一步都不许让它可写——这套叫半自进化。

## 2. B 段（必做）· 「这次学到」提案卡

- **触发**：一次 run 正常收尾（`settle(DONE)`）时，若本轮存在「可提炼信号」——写过/改过工作区文件、用过浏览器、改过或新建过技能、用户说过「记住／记下来／以后都这样」——就生成提案（**最多 3 条**，`SkillRefine` 已有 ≤3 的口径可直接参考）。
- **卡片内容**：每条一行「学到 X（来源：哪个工具/哪个页面/哪个文件）｜ 建议：写成草稿技能 / 转正式 / 不记」；底部两个动作：`采纳`／`不记`。
- **位置**：沿用 18 批 D 段的口径——**输入栏上方**，与 `ask_user` 那张卡同一区域（别堆到消息列表上方）。
- **没信号就不出卡**（不许每轮都弹，那是骚扰）。
- **采纳＝唯一落盘路径**：走 `SkillStore.apply`（草稿，带备份），写完进索引并标「草稿·未验证」；**不采纳一个字节都不写**。

## 3. C 段（必做）· 提案落盘前过门禁

- 先读 `eval/` 现有的闸门实现与 23B 的 CI 步，**能复用纯函数就复用**，不许另起一套判据。
- 采纳前必须过三道最小校验（不通过 ⇒ 卡片标红、**禁止采纳**、并说清哪条不过）：
  1. **危险指令**：技能正文里出现删库/外发凭据/`rm -rf`/把工具结果当指令执行这类模式；
  2. **未实测没标**：正文断言了平台事实（字段名/下拉值）却没标「未实测」或没写实测日期；
  3. **与既有技能冲突**：同名技能已存在时，必须走「改自己那份」而不是新建第二个。
- **零网络**：这一步不许联网，全部本地纯函数。

## 4. D 段（必做）· 人设回滚入口

- B/C 层人设写入前**自动备份**（`人设-本项目.md.bak-<stamp>`，沿用 `SkillStore.BACKUP_MARK` 同款命名习惯）。
- 设置页（技能卡附近即可）加一行「人设：恢复到上一版」，显示最近备份的时间戳；点它 ⇒ 恢复并**先备份当前版**（可反悔）。
- 没有备份时该行灰掉，**但不许消失**。
