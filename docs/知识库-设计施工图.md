# 知识库接入 · 设计施工图

> **状态**：草案（等用户过目）　**日期**：2026-10-09　**作者**：WorkBuddy
> **主线一句话**：**用户把文件丢进去 → 就能用**（零操作、零格式要求）

---

## 一、目标与非目标

### 目标

1. 用户把**任意格式、任意数量**的文件丢进工作区（或他自选的文件夹），终端里的 agent **自动能用**
2. 用户**不需要**知道 `AGENTS.md` 是什么、**不需要**进设置页、**不需要**开任何开关
3. 一次投入，覆盖**用户以后自己装的任意 agent**（走 `AGENTS.md` 开放标准，25+ 工具通用）

### 非目标（明确不做）

- ❌ 不做知识库的浏览／搜索界面 —— agent 自己会搜
- ❌ 不引入数据库（SQLite 等）—— agent 读文件是本能，读库要先装工具
- ❌ **不改太极侧现有行为**（太极定位是"能用就行"）
- ❌ 不做后台常驻服务（耗电、被杀、用户反感）

---

## 二、用户路径（小白视角）

```
① 把一堆乱七八糟的文件丢进工作区
② 下载自己喜欢的 agent
③ 在终端里和 agent 聊起来
        ↓
   （中间全部由 App 完成，用户一次都不进设置）
```

---

## 三、分工：三层，各管一段

| 层 | 谁做 | 做什么 | 成本 |
|---|---|---|---|
| **① 机械层** | **App** | 扫描资料库 → 生成清单 → 写说明书 → **分发**到各 agent 原生路径 | 零 AI、零费用、纯逻辑 |
| **② 预编译层**（可选加速） | **太极的免费模型** | 读长文档 → 写摘要 → 更新目录 | **不花用户的钱**（用免费模型） |
| **③ 实时层** | **终端 agent** | 需要细节时，自己读原文 | 用户自己的额度 |

> **关键分工理由**：App 自己是本地 agent 宿主，**不接 LLM API**。所以"读懂长文档"必须有模型 ——
> 要么借**太极的免费模型**（②），要么让**终端 agent 顺手做**（③）。App 只负责让它一定**找得到、看得懂入口**。

## 四、详细设计

### 4.1 资料库的位置与结构（**原始只读**）

**默认位置**：工作区内的 `资料库/`（guest 内为 `/workspace/资料库/`）

```
工作区/
└── 资料库/
    ├── 原始/                  ← ⭐ 用户把文件丢这里。**只读区**
    ├── 整理/                  ← AI 产出的目录／摘要
    │   └── 00-目录.md
    ├── 改版/                  ← 用户要求"改文件"时，改好的版本放这里
    ├── AGENTS.md              ← 说明书（App 生成并维护）
    └── CLAUDE.md              ← 一行 @AGENTS.md（Claude Code 兜底）
```

### ⭐ 铁律：**原件不动，改版另放**

**不是"禁止修改"，而是"原件永远不动"。**

用户可能确实要让 AI 帮他改文件（那是正当需求）—— 但**改的结果必须写到别处**，原件一个字节都不变。

**任何程序都不许修改／改名／删除 `原始/` 里的内容** —— 包括 **App 自己**、太极、终端 agent。

三层保证：

| 层 | 保证方式 |
|---|---|
| **结构层** | **只读区与可写区分开**（`原始/` vs `整理/`）—— 写的地方压根不是同一个目录 |
| **规程层** | `AGENTS.md` 里对 agent 写死禁令（见 4.4） |
| **实现层** | App 代码只写 `整理/`；**不提供任何删除用户文件的入口** |

> **为什么必须这么设计**：用户**不会备份**。一旦"整理"能碰到原件，那就是数据事故 —— 而且是不可逆的。
> 目录名用「**原始**」而不叫「资料」：用户看到这两个字，自然知道那是放原件的地方，不该动。

**预置规则**：
- 只在「共享工作区」模式下预置；「仅私有」模式不预置
- 目录**可删**。用户删掉后 **App 不再重建**（记一个 prefs 标记），避免像流氓软件

### 4.2 设置页卡片（把现有的「插件」卡片换成「资料库」）

> **依据**：插件入口**在太极页抽屉底部已有一份**（`TaijiScreen.kt:133` 注释："入口却在设置页，用的时候要跨页找。现放进抽屉底部"）
> ⇒ 设置页这张卡是**重复入口**，腾出来正好。

| 元素 | 内容 |
|---|---|
| 卡片标题 | **资料库** |
| 状态行 | **四态**（见下方） |
| 主按钮 | **打开文件夹**（跳到文件管理器，方便丢文件） |
| 次按钮 | **换位置**（默认工作区；可选自己已有的文件夹） |
| 开关 | **让终端 agent 自动读取**（**默认开**） |
| 说明文字（人话） | "把资料放进这个文件夹，终端里的 agent 就会自动找到它。支持各种格式。" |
| 高级（折叠） | "重新整理"（手动触发一次预编译） |

**状态四态**（"能读"和"整理好"是**两件事**，必须分开显示）：

| 状态 | 含义 | 显示给用户 |
|---|---|---|
| **未挂载** | 没设工作区，或 `原始/` 是空的 | "还没放资料" |
| **已挂载** | agent 已经能读到了（清单 ＋ 指路就绪，**机械层完成**） | "已挂载 · 12 个文件" |
| **正在整理中** | 太极在跑摘要 | "正在整理中…（3/12）" |
| **已整理** | 摘要写完（**预编译层完成**） | "已挂载 · 12 个文件（含摘要）" |

> ⭐ **关键**：没有太极时，用户看到的是**「已挂载」**而不是失败 —— 因为"挂载"是 App 做的，与太极无关。

**要求**：界面上**不出现** `AGENTS.md`／`proot`／`workspace` 这类词。

### 4.3 时机：两个钩子，不做常驻

`ProotLauncher.buildLaunchPlan()` 每次启动终端会话都会执行 —— **现成的钩子**（它现在就在这里面写太极的 `AGENTS.md`）。

| 时机 | 动作 |
|---|---|
| **启动终端会话前** | 扫描资料库（**内容或路径有变化才动手**）→ 重建 `00-目录.md` → 重写 `AGENTS.md`／`CLAUDE.md` → 分发 |
| **打开 App 时** | 只更新设置页里的"资料库状态"数字（轻量） |

**变化检测**：用「文件路径 + 修改时间 + 大小」做指纹，存进 prefs；指纹没变就整个跳过。

### ⚠️ 扫描范围（重要）

**只扫 `资料库/原始/`。**

**绝不扫整个工作区** —— 工作区里有 App 自己的目录：

```
logs/ · cache/ · agents/ · rootfs/ · opencode/     ← 都不是用户的资料
```

把它们当"资料"的后果：模型去整理缓存和日志 —— **白烧算力，摘要还会被垃圾淹没**。

**用户把文件丢在别处怎么办**（比如工作区根目录）：
- **不自动扫**
- 设置页给一条**可选提示**：「工作区里还发现 3 个文件，要加入资料库吗？」
- **用户确认后才动**（可以只移动引用，不搬文件）

### 4.4 分发内容（写给各 agent 的说明）

分发到**终端 agent 的原生路径**（与太极那份**完全不同路径**，互不干扰）：

| 目标文件（guest 内） | 给谁 | 内容 |
|---|---|---|
| `/root/AGENTS.md` | Codex／Hermes／AGY／Cursor／Copilot／Gemini… 等 25+ 工具 | **① 环境说明**（你在手机里）＋ **② 资料库指路**＋ **③ agent 的职责** |
| `/root/CLAUDE.md` | Claude Code | 一行：`@AGENTS.md` |

**为什么要写 `/root/`**：终端 agent 的**起点目录就是 `/root`**（`ProotLauncher.kt:510` 的 `-w /root`），写这里才能被自动读到。

**内容要点（三段）**：

```markdown
# 证道运行环境说明（每次对话开始前必读）

## 你的身份
你运行在用户的安卓手机上（证道 App 通过 proot 运行的 Debian）。
禁止声称「我不在手机上」「我没有文件系统」。

## 文件地图
- /workspace —— 产出与边界区……
- /sdcard —— 共享存储可读可写……
- /root —— 你的 home……

## 资料库（重点）
用户的资料放在 /workspace/资料库/原始/。**里面是原始文件 —— 用户不会整理，而且没有备份。**

- ⛔ **`原始/` 是只读区**：禁止修改、改名、删除里面的**任何**文件。一个字都不许改。
- ✅ 你的输出分两类，都只能写进 `/workspace/资料库/` 下的可写目录：
  - **摘要／索引／转换出的文本** → `整理/`
  - **用户要求修改某个原件时** → 把**完整改版**写进 `改版/<原名>（改）.txt`，**原件保持不动**
- 用户说"帮我改一下这个文件"时：读原件 → 改版写进 `改版/` → 回复里说明"**原件没动，改好的在 改版/ 里**"
- 先读 `/workspace/资料库/整理/00-目录.md` 看有什么
- 需要细节时，再读 `原始/` 里的具体文件
- **目录里还没有摘要的文件** → 读完它，把要点追加进 `整理/00-目录.md`
- 遇到 .docx/.pdf 读不了时，先用工具转成文本（pandoc 等），**转出的副本放 `整理/`**

## 能力边界
- 无 root；禁 apt upgrade；找不到文件先 ls 而不是放弃
```

> **注意**：现有太极那份 persona（`ProotLauncher.kt:379-392`）**只有太极收到**；
> 终端 agent 同样会"以为自己在电脑里"。本设计把同一段说明**也发给终端**，一次解决两件事。

### 4.5 预编译（可选加速器）：借太极的免费模型

**通道已存在**：`oc/OcRepository.kt` 通过 `opencode serve` 的 REST／SSE 与太极通话，`prompt` 可传 `{text, files[], agents[], skills[]}`。

**做法**：App 在"打开 App 时"（或用户点"重新整理"）后台发起一个**整理任务**：

> 提示词大意：读 `/workspace/资料库/` 里还没整理的文件，把每个文件的要点写进 `00-目录.md`

**必须处理的四个问题**：

| 问题 | 处理 |
|---|---|
| ⚠️ **不能干扰用户正在聊的会话** | 必须**新建一个独立的"整理会话"** —— ⚠️ **待验证**：现有 API 是否支持指定/隔离 session |
| 用户没装太极 / 太极挂了 | **静默降级**：只做清单（机械层），不写摘要。**不报错、不弹窗** |
| 免费模型限流／失败 | 失败就跳过，下次再试。**绝不阻塞用户** |
| 费用 | 用免费模型，**不花用户的钱**（这是选太极的唯一理由） |

**⚠️ 定位铁律**：**太极是"加速器"，不是"必需品"。**

> 用户对太极的定位是「不是主打，能用就行」。若把资料库**依赖**在太极上，就是本末倒置。
> ⇒ 没有太极：资料库**照样能用**（清单 ＋ 指路），只是摘要得等终端 agent 顺手补。
> ⇒ 有太极：资料库**更早**变得有条理。

## 六、边界与降级

| 情况 | 行为 |
|---|---|
| 资料库为空 | 设置页显示"还没放东西"，**不报错** |
| **用户误删了原始文件** | App **不做任何自动恢复，也不做任何自动删除**；只如实反映现状。目录整个消失 → 记标记，**不重建** |
| 用户删了预置目录 | 记标记，**不再重建** |
| 用户选了不可写目录 | 回退默认，提示一次 |
| 文件是 .docx/.pdf | 清单里列出；摘要环节标"需转换"；读的任务交给 agent |
| 太极不可用 | 静默降级为"仅清单" |
| 工作区是"仅私有"模式 | 不预置，但用户手动设置仍可用 |

## 七、验收标准

- [ ] 全新设备：装 App → 打开终端 → 工作区里**已有** `资料库/`，且里面有 `原始/`、`整理/00-目录.md`、`AGENTS.md`
- [ ] 往 `原始/` 丢 3 个文件 → 启动终端会话 → `整理/00-目录.md` 列全了这 3 个文件
- [ ] 终端里问 agent "我的资料库里有什么" → agent **能答对**
- [ ] ⭐ **整理前后，`原始/` 里所有文件逐字节不变**（哈希比对）
- [ ] 对 agent 说"帮我把原始文件改一下" → 它把改版写进 `改版/`，**原件哈希不变**
- [ ] 用户删掉资料库目录 → 重启会话 → **不被重建**
- [ ] 断网 / 太极未装 → 终端 agent **仍能**读到资料库清单
- [ ] 太极可用时 → 打开 App 后一段时间，`00-目录.md` 里**出现摘要**
- [ ] 设置页界面**不含**技术词（AGENTS.md／proot／workspace）
- [ ] 关掉开关 → 分发停止（且不删除已有文件）
