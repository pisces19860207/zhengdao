## 4. 验证矩阵（每条都要判据 + 实测回包原文）
### A. ㊽-A title 脱敏
- **A-1（不吃尾，正题）**：打开任一公网 https 页；用 execJS 单表达式注入标题：
  `document.title="订单 x?sessionid=SECRET999&email=foo@bar.com&b=2"`（**注意：含分号的多语句目前还挂（N3，㊽-B 未入库），必须拆成两条单表达式 execJS 发**）
  → 等 1~2 秒 → 打 `status`：
  判据：title 里 `sessionid=` 与 `email=` 的值都是 `***`，且 **`&b=2` 必须保留**（旧口径会把 `&` 之后整段吃掉）。
  → 再打 `snapshot`（`{"mode":"text"}`）：标题位同一判据。
- **A-2（冒号形）**：`document.title="登录 sessionid: SECRET999 ok"` → `status` 应为 `登录 sessionid: *** ok`。
- **A-3（负例/不误改）**：`document.title="百度一下，你就知道"` → `status` 的 title **逐字不变**。

### B. ㊽-C tabId 精确路由
- **B-1（精确路由）**：开 3 个标签；`navigate{"tabId":1,"url":"https://example.com/?tab=1"}`、`navigate{"tabId":2,"url":"https://example.com/?tab=2"}`；
  判据：`status{"tabId":2}` 回 `tab=2` 的 url、`status{"tabId":1}` 回 `tab=1` 的 url，**不得回落活跃标签**（这是 N4 的病根）。
  再各来一条 `click{"tabId":1,…}` / `type{"tabId":1,…}` / `scroll{"tabId":1,…}` / `snapshot{"tabId":1}` / `execJS{"tabId":1,"code":"1+1"}` → 判据：这些命令只作用在 tab1，tab2 的 `status{"tabId":2}` 的 url/title **保持不变**。
- **B-2（错误出口）**：`status{"tabId":9}` → HTTP 200 + JSON 错误 `没有这个标签：9（当前 N 个）`；`status{"tabId":"x"}` → `tabId 不是数字：x`；`status{}`（不带 tabId）→ 活跃标签正常回包。三条都要贴回包原文。

### C. ㊽-D 0 标签空态
- **C-1**：造 0 标签态（冷启动进玄览；或把唯一标签用 × 关掉 —— 第㉟刀 N5 的复现路径）→ 地址栏输入 `example.com` 点「前往」→ 判据：**自动建标签并开始加载**（旧行为：静默无反应）。回车、IME「搜索」两条入口各再试一次。
- **C-2**：仍是 0 标签态，点起始页搜索框输入同样内容提交 → 同一判据。
- **C-3（非法 scheme）**：0 标签态输入 `intent://x` 点「前往」→ 判据：**出现危险 scheme 的界面提示**（不再静默）；有标签态同一输入也要有提示。
