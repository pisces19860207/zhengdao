## 0. 为什么要做

用户原话：「有些人百年用不到某些工具。」25 个工具每轮全塞给模型 ⇒ prompt 变长、模型容易被低频工具干扰；而逐个开关是**用户手工维护**，不是「默认就收起来、需要时解锁」。

## 1. 行为（v1）

1. **分组**：给每个工具加 `group` 字段（`core` / `edit` / `browser` / `library` / `media` / `card` / `plan`）。分组表**只有一份**（放 ToolRegistry，UI 从它读）。
2. **默认可见**：`core` 与 `edit` 默认可见；其余组默认**不可见**（不是禁用——模型根本看不到）。
3. **解锁工具**：新增 `capabilities`（FREE）：无参数 ⇒ 返回「当前可见组 / 可解锁组 + 每组一句话」；带 `enable: ["browser","card"]` ⇒ 本会话内解锁，返回解锁后的组清单。
4. **生效范围**：解锁状态**按会话**持久（写 `session` 或单独小表，二选一，在报告里写清）；新会话回到默认。用户既有开关仍然优先：组被用户关掉 ⇒ `capabilities` 也不能解锁（如实回「被用户关闭」）。
5. **诚实**：模型调未解锁工具时，回「该工具组未解锁：先调 capabilities」，不静默。
6. **设置页**：工具开关区顶部加「默认只显示核心工具；低频组按需解锁」说明 + 每组的开关（与单工具开关并存），状态读同一份 group 表。

## 2. 验收（判据）

- 默认发给模型的 tools 数组 **≤ 12 个**（core+edit+capabilities），其余不出现；
- `capabilities` 在表里，且能列出组与解锁状态；
- 调 `capabilities(enable=["browser"])` 后，下一轮 tools 数组出现 browser 组；
- 用户关掉的组：`capabilities` 不解锁，返回原因；
- 新会话回到默认（默认可见组数量与首轮一致）；
- 源码门禁：tools 数组只由「可见组 ∩ 用户开关」计算，不许另起第二条过滤链；
- 纯函数：`visibleTools(catalog, settings, unlockedGroups)` 可直接 JVM 测（给 3 组用例：默认/解锁/用户关闭）。
- 全量单测 0 失败 0 错误，跳过不恶化；lint 预算不升。

## 5. 玄览本地预览（同一批的第二件）

用户口径：「只显示、不运行」「上网怎么办？没冲突吗？」——结论：**按页签类型分模式，不是全局开关**。

1. **上网页签保持现状**：联网、JS 全开、`browser_*` 工具照常。一个字节都不改行为。
2. **本地预览页签（新）**：
   - 入口：玄览页签菜单/工具（`preview_local_file { path }` 或 UI 入口，二选一；工具必须进组表）；
   - 只加载**工作区内**的本地文件（走现有守卫，越界拒）；
   - **默认断网**：该页签的 WebView 拦掉所有 http/https 请求（`shouldInterceptRequest` 返回空响应），不是靠"别点链接"；
   - **默认禁 JS**（静态 HTML/CSS/Markdown 渲染；`javaScriptEnabled=false`）；
   - 不注入 cookie、不共用登录态；不写任何网络请求；
   - 提供「源码查看／渲染预览」切换；源码档纯文本 + 复制。
3. **可选 JS 沙箱开关（默认关）**：允许该页签跑 JS，但**仍然断网**。开关文案要写明「脚本会跑、出不了网」。
4. **工具面备齐**：新增的预览工具必须登记进注册表并**有组**（`browser` 或新组 `preview`），`capabilities` 能列出；settings 页能看到。
5. **验收**：
   - 上网页签行为零变化（源码门禁：正常 tab 的 `javaScriptEnabled`/网络配置未被改）；
   - 本地预览页签：加载 html 显示，且抓不到任何 outbound http(s)（测试用假 WebViewClient 拦请求计数=0）；
   - 禁 JS 时页面脚本无副作用（页面写 `window.__ran`，读为 false）；
   - 路径越界拒；非文本/非 html 按文本处理；
   - 全新文件/改过的文件能刷新看到（不缓存旧内容）。

## 6. 工具备齐（用户点名：「工具要给抱朴备齐哦」）

- 注册表里**每一个工具都必须有组**（编译期或测试期断言：group 非空；孤儿工具直接红）；
- 默认可见集合必须覆盖抱朴干活的最小闭环：读/写/改/列/搜/浏览器读页/ask_user/update_plan/图片改写/card；**不许因为分组把核心工具藏掉**；
- `capabilities` 返回的是**全量名册**（哪些已解锁、哪些没解锁、各自属于哪组），不是只报没解锁的；
- 设置页分组开关与单工具开关并存，状态互不覆盖；测试断言「组默认 ∩ 用户开关 = 实际可见」只有一条计算链。

## 7. 许愿式编程（用户要求并入本批）

用户口径：「许愿式编程（W6）只在玄览显示，但是不运行」「工具要给抱朴备齐」「合到 56 批」。

- **能力定位**：抱朴能**写**程序/页面（write_file/edit_file 已有），产物默认落 .html／源码文件；在**玄览本地预览页签**里看（§5：默认断网＋禁 JS），**不执行、不跑 gradle、不接终端**。
- **工具备齐**：preview_local_file 归组（preview 或 rowser，二选一并写清）；capabilities 全量名册里要能看见它；提示词「你会做什么」补一条 **写程序/做页面（能写能看，不替你执行）**，与 W6 口径一致。
- **可选 JS 沙箱**（§5.3）默认关；打开也只在本页签断网跑，不获得 
un_command、不碰 rootfs。
- **验收补一条**：同一轮里「写 html → 玄览预览」两步都能从工具卡看到；预览页签里没有 shell/网络能力。
