# 格式层判据表 F1–F11（第三十九批 A 段 附录）

> 配套主文档：`docs/格式层规格-三套卡与酒馆PNG-2026-10-19.md`（下称「主文」）

## 0. 使用说明

- **断言要精确**：断言 `code` 字符串与 `level`，不要断言「message 包含某词」。话术会改，code 不会。
- **一个用例只测一件事**：N3 的四个越界值要拆成四个用例（`N3a`–`N3d`），合成一个会互相掩盖。
- **负例必须真跑红**：每条 F 都给了「改坏哪里会红」，B 段要实际改一次、看到红、再还原、`git status` 干净。
- **不许用真实卡**：所有输入来自主文 §6 的合成夹具。

### F2 · 风月省略默认值不误报

| 项 | 内容 |
|---|---|
| **建议用例名** | `fengyue_omitted_defaults_are_not_errors` |
| **输入** | J1（无 `value_type`、无 `value_configs`） |
| **期望** | ① `format=FENGYUE`；② `defaultsApplied` 排序后 == `["value_configs","value_type"]`；③ `findings` 中不存在 `field=="value_type"` 或 `field=="value_configs"` 的 `FY_MISSING_FIELD`；④ 条目按常规模式解析（`value_type` 视为 0、`value_configs` 视为空） |

| **反例（不许过严）** | 不许要求 J1 必须有 `value_type` —— 有它才怪 |

### F3 · 判不出 ⇒ 未知 ＋ 键名

| 项 | 内容 |
|---|---|
| **建议用例名** | `unknown_returns_keys_seen_not_a_guess` |
| **输入** | N2：`{"foo":1,"bar":[1,2],"baz":{"x":true}}` |
| **期望** | ① `format=UNKNOWN`；② `keysSeen == ["foo","bar","baz"]`（顺序同原文件）；③ `message` 逐字 == `认不出这个文件是什么格式。看过的顶层键：foo, bar, baz。`；④ `confidence` 不参与（不赋值或 `null`） |
| **防的坑** | 「挑一个最像的」；`keysSeen` 空；把 JSON 对象但无特征当成错误而不是未知 |
| **负例** | 在 `UNKNOWN` 分支返回 `FENGYUE` 作兜底 ⇒ 红 |
| **边界** | 顶层键超过 20 个时只取前 20；`keysSeen` 不许为空 |

### F4 · 四个越界值

拆成四个用例，**不许合并**。

| 用例名 | 输入 | 期望 code | 期望 level | 期望 field | 期望 entry.index |
|---|---|---|---|---|---|
| `fengyue_probability_zero_is_error` | N3-a | `FY_PROBABILITY_RANGE` | `ERROR` | `probability` | 0 |
| `fengyue_depth_21_is_error` | N3-b | `FY_DEPTH_RANGE` | `ERROR` | `depth` | 0 |
| `fengyue_key_region_8_is_error` | N3-c | `FY_KEY_REGION_RANGE` | `ERROR` | `key_region` | 0 |
| `fengyue_match_type_5_is_error` | N3-d | `FY_MATCH_TYPE_RANGE` | `ERROR` | `match_type` | 0 |

**共同断言**：每个变体的 `findings` 里**恰好一条** `ERROR`（其余允许 INFO）。
**防的坑**：① 只校验 `probability`，忘了位掩码；② 把 8 当成「合法但少见」；③ 把 `match_type=5` 当 WARN。
**负例**：删掉 `key_region` 的 1–7 校验 ⇒ N3-c 期待的那条消失 ⇒ 红。

> 实测提醒：这四个值在 607 条真实样本里**一次都没出现过**（`probability` 最低 30、`depth` 最高 10、`key_region` 最大 7、`match_type` 全 2）。所以只能用夹具。

### F5 · `_or_` 单字

| 项 | 内容 |
|---|---|
| **建议用例名** | `fengyue_or_single_char_is_score_assassin_risk` |
| **输入** | N4（三条） |
| **期望** | ① 第 0 条：`FY_KEY_TOO_BROAD`，`ERROR`，`field=="key"`；② 第 1 条：`FY_KEY_TOO_BROAD_AND`，`WARN`；③ 第 2 条（`水滴`/`火焰`）：**零 finding**；④ `stats.broadKeyCount == 2` |
| **防的坑** | ① 用「字节长度 == 1」判中文（`水` 是 3 字节 ⇒ 永远不命中）；② 把 `水滴` 判成单字；③ 把 `_and_` 也判 ERROR（级别错）；④ 忘了 strip 或忘了按 `@wb@` 切 |
| **负例** | 删掉单字检查 ⇒ 第 0 条无 finding ⇒ 红 |
| **边界补充**（各写一个微用例） | `"_or_ 水"`（前导空格）⇒ `水` strip 后是单字，仍 ERROR；`"_or_Ａ"`（全角）⇒ 1 码点，仍 ERROR；`"_or_e\u0301"` ⇒ 2 码点，**不报**（已知漏报，主文 §8-10） |

#### F5-b 关键词是 HTML 标签名（同属「过宽」的第二种形态）

| 项 | 内容 |
|---|---|
| **用例名** | `keyword_is_html_token_warns` |
| **输入** | J1 变体：`key="_or_div@wb@雨"`；另一条 `key="_or_span@wb@class"`（两条都不含单字） |
| **期望** | 两条各产出 `KEY_IS_HTML_TOKEN`（`WARN`，`field=="key"`）；**不产出** `FY_KEY_TOO_BROAD`（`div`/`span` 都不是 1 个码点） |
| **防的坑** | ① 把 HTML 标签名当普通词放过 ⇒ 有 HTML 的卡会被无差别触发；② 误报成 ERROR（平台处罚口径未实测，见主文 §8-22） |
| **负例** | 删掉词表检查 ⇒ 两条都无 finding ⇒ 红 |
| **叠加规则** | 若同一条既含单字又含标签名 ⇒ 单字报 `ERROR`、本条降 `INFO`，**不许两条都 ERROR**（避免一个毛病报两遍） |
| **适用格式** | 风月、酒馆（次级通道扫原文，见主文 §4.3.2.1）；Tavo 只报 `INFO` |

|---|---|

| **输入** | 同上 ＋ `detailHtml="戊"` |
| **期望** | `stats.cCount == 1`；C 类唯一一条 `EntryRef.index == 1`；条目 4 判 B（不产生 ERROR/WARN）；`stats.unjudgedCount == 0` |
| **防的坑** | 只报计数不报条号；把 B 类也算进 C |

#### F6-c 三段系统文本全缺

| 项 | 内容 |
|---|---|
| **用例名** | `trigger_class_without_system_text_is_null_not_zero` |
| **输入** | N5，`prompt/pre/post` 全缺 |
| **期望** | `stats.cCount == null`（**必须是 null**）；`stats.unjudgedCount == 3`（条目 0、1、4）；`stats.notApplicableCount == 2`；报告含话术 `3 条没判：没给系统文本。` |
| **防的坑** | **最严重的一条**：把「没数据」写成「0 条永不触发」⇒ 用户以为卡没问题 |
| **负例** | 把可判域判断（`key_region & 1`）删掉 ⇒ F6-a 的 `notApplicableCount` 变 0、`unjudgedCount` 变 4 ⇒ 红 |

#### F6-d Tavo 卡：不给 HTML 也必须判 C

| 项 | 内容 |
|---|---|
| **用例名** | `tavo_without_html_still_reports_c` |
| **输入** | J3 变体：3 条 `strategy=keyword`，`keywords` 分别为 `["甲"]`、`["乙"]`、`["丙"]`；`prompt="甲出现了"`；**不给 HTML** |
| **期望** | 条目 0 判 A；条目 1、2 判 **C**（不是未判）；`stats.cCount == 2`（**非零**）；`stats.unjudgedCount == 0` |
| **防的坑** | 把「风月的未判规则」原样套到 Tavo ⇒ C 类永远报不出来，体检主功能等于关闭 |
| **负例** | 把 `有次级通道()` 的分叉删掉（统一未判）⇒ 本用例红 |

#### F6-e 酒馆：开关关着判 C，开着判未判

| 项 | 内容 |
|---|---|
| **用例名** | `st_match_switch_decides_c_or_unjudged` |
| **输入** | J4 变体，两条：① 六个 `match*` 全 `false`；② `matchCharacterDescription=true`（其余 false）。两条 `key` 都不在系统文本里。`prompt` 给、**不给角色描述** |
| **期望** | ① 判 **C**；② 判 **未判**；`stats.cCount == 1`、`stats.unjudgedCount == 1` |
| **防的坑** | 把酒馆当成「永远无次级通道」⇒ 第②条被误判 C；或反过来当成「永远有通道」⇒ 第①条永远判不出来 |
| **负例** | 把 `有次级通道()` 里酒馆分支写成恒 `false` ⇒ 第②条变 C ⇒ 红 |

> **为什么风月要「未判」而 Tavo/酒馆的关灯条目直接判 C**：风月的「详细介绍」是**平台必有字段**，通道恒在；Tavo 的 26 字段里**没有** `match*` 类开关，通道恒无；酒馆**有六个开关**，要逐条看。这是三套格式的**结构差异**，不是口径松紧。
>
> ⚠️ 别被「卡里有 HTML」误导：Tavo 角色卡（6/27 的 `first_mes`、1/27 的 `description`）和酒馆 PNG 卡（2/4 的 `first_mes`）**都含 HTML 标签**，但那是卡的内容，能不能触发世界书取决于**扫描开关**，不是「有没有 HTML」。

### F7 · PNG 导出：CRC 与结构

| 项 | 内容 |
|---|---|
| **建议用例名** | `png_export_crc_and_structure` |
| **输入** | P1（ImageIO 现画 1×1 白图 ＋ J4 的 JSON 字符串） |
| **期望** | ① 前 8 字节 == `89 50 4E 47 0D 0A 1A 0A`；② 块序列含 `IHDR`、≥1 个 `IDAT`、`tEXt`×2（关键字分别为 `chara`、`ccv3`）、`IEND`，且 `IEND` 是最后一块；③ 每块 CRC 用 `java.util.zip.CRC32` **独立复算**（`update(type)` + `update(data)`）与文件值相等；④ `IEND.length == 0`；⑤ 原 `IHDR`/`IDAT` 字节与底图逐字节相同 |
| **防的坑** | ① CRC 覆盖范围写成「type+data+length」；② 自己实现多项式算错；③ 重编码 IDAT；④ 把 `IEND` 写成非 0 长度 |
| **负例** | 导出时把 CRC 写 0 但仍返回成功 ⇒ 读回侧复算必须拦住（F7 与 F10 联动） |
| **实测旁证** | 4 张真实卡 8 个 `tEXt` 块 CRC 全部复算通过；块序均为 `IHDR→IDAT→tEXt→tEXt→IEND` |

### F8 · PNG 往返逐字

| 项 | 内容 |
|---|---|
| **建议用例名** | `png_roundtrip_is_byte_identical` |
| **输入** | `s = "{\"z\":1,\"a\":\"\\u4e2d\",\"m\":\"中\"}"`（**故意 z 在前、含转义、含中文**） |
| **期望** | `读回(导出(s)) .equals(s) == true`；且读回的字符串长度与 `s.length()` 相等 |
| **防的坑** | ① 导出前 `parse → toString`（键顺序变 `a,m,z`）；② 用 MIME base64（插换行）；③ 用平台默认字符集（非 UTF-8 环境会乱码）；④ 解码时把 `\u4e2d` 变成「中」 |
| **负例** | 把导出改成 `JSONObject(s).toString()` ⇒ 键顺序变 ⇒ 红 |
| **加强用例** | 再加一条带 BOM 的输入 `"\uFEFF{...}"`，期望**往返仍逐字相同**（主文 §5.6 规定 BOM 不剥） |

### F10 · 非酒馆 PNG ⇒ 明确报错

**三个子用例**：

| 用例名 | 输入 | 期望话术（逐字） |
|---|---|---|
| `plain_png_has_no_card_block` | P2（无 tEXt） | `这不是酒馆角色卡：PNG 里找不到 chara 或 ccv3 文本块。` |
| `broken_base64_reports_failure` | P3 | `这是 PNG，但卡数据解不开：base64 解码失败。` |
| `payload_not_json_reports_failure` | P4 | `这是 PNG，但卡数据解不开：内容不是 JSON。` |

**防的坑**：把「没找到块」实现成 `return ""`（下游会把它当空书，静默毁数据）。
**负例**：把 P2 分支改成 `return ""` ⇒ 红。

## 4. 建议的负例清单（每条都要真跑红）

| # | 改坏什么 | 应该红在哪 |
