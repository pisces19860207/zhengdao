## 3. 小黑板工具（原 538，模型侧）

`BoardTools.kt` 三件：`BoardRules`（纯判据）＋ `BoardStore`（唯一碰盘处）＋ 两件工具。

| 项 | 定死的值 | 为什么 |
|---|---|---|
| 落点 | `<工作区>/产物/.board.md` | **点号开头** ⇒ 512 的 `ReflectionRunner.isCountedProduct` 不计入「产物 N 件」（与归因游标同口径）；临时件 `.board.md.tmp` 同口径 |
| 写语义 | **整篇替换**（空串＝清空） | append 会无限增长，也会让"上次那段"悄悄变成"这次的一段" |
| 上限 | 4096 字节（UTF-8）／ 20 行 | 超限**拒写**并提示"先删旧"，**不静默截断**（截断最坏：模型以为写进去了，下一轮读到半截） |
| 行数口径 | 换行符数 ＋ 末行没换行则 +1 | `String.lines()` 会把 `"…\n"` 数成多一行，边界值「正好 20 行」当场破 |
| 落账 | `RunLog.log("board_write: ${bytes}B 字节 / $lines 行")` | 只记长度与行数，**不记正文**（便签里可能是半成品线索） |
| 权限 | 读 R0/FREE/只读/可并行；写 R1/FREE | 便签每次一张确认卡＝把"记一笔"变成打扰；风险档照记（抽检看得见） |
| 分组 | FILES（默认**启用**、默认**不可见**） | 与 `governance_state`／`index_*` 同款：策略层 `ALLOWED` 只放 CORE/EDIT/COMPAT，B1「默认可见 ≤12」的硬卡不许破 |

## 8. 裁量与挂账（请验收方裁）

1. **工具分组＝FILES（默认启用、默认不可见）**。策略层 `ToolGroupPolicy.ALLOWED` 只放 CORE/EDIT/COMPAT，B1 又把「默认可见 ≤12」硬钉住 ⇒ 模型第一次要用便签得先 `capabilities(enable="files")` 解锁一次。
   **待裁定**：要不要把 `board_read` 加进 `defaultVisibleTools`（157 那条工具级默认可见名单，目前只有 `library_list`/`kb_search`）——那能让"读便签"永远可见。**那是政策层改动，本批没自己动**。
2. **`board_write` 是 FREE + R1（不弹确认卡）**。理由：便签是模型自己的草稿纸，每次写都弹卡等于把它废掉；风险档仍记 R1，抽检/统计看得见这条动作。若验收方认为"任何写盘都要卡"，改 `permission = CONFIRM` 一行即可。
3. **判据④的"记忆表行数不变"没能按字面验**：全仓没有 Robolectric，记忆表是 SQLite，JVM 单测开不了库。本批用两条更硬的替代：①源级——本工具族零记忆/账本写口；②行为级——写一次后**盘面净增恰好 1 件**（工作区树＋App 私有目录一起数，连"别处偷偷多写一件"也拦得住）。**证明不了"记忆表被原地改了一行"**——那条留给有 SQLite 的环境（真机/CI），本批未验，记挂账。
