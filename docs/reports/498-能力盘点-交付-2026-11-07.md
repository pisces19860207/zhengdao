## 4. 为什么五类都**不需要新页面**（C 的论证）

派工单要求「若结论是『需要新页面』⇒ 先论证为什么不能只做工具」。本单五类结论**没有一个是 C**，理由统一写在这里，便于验收时反查：

1. **界面只承担「看 / 改 / 教」，这三件事都已有承载**：看产物 → `preview_local_file`（玄览）；看批量计划 → `organize_preview`（只读预览卡，`:65-73`）；看/改工具开关 → 设置页工具组设置（`BaopuToolLabels` ＋ `BaopuSettingsScreen`）；看风险 → 确认卡（R2 / `alwaysAsk` 已有）；教 → `write_skill` / `teach_*` 与 `organize` 的 `save_recipe`。
2. **491 是最强反证**：连「导出/备份」这种最像「该有个页面」的重功能，最终都把设置页按钮**退为第三入口**、主入口给模型用工具（491 报告 §一、验收落笔「修订方向我认」）。加页面等于把已经收掉的控制面又摊开。
3. **新页面会新增一条要维护的链路**（导航、中英 strings、返回栈、状态），而 503 批刚清点出 7 件悬空模块/卡片（其中 `KnowledgeRefreshCard` 就是「后端在跑、控制面没了」）。此刻新增页面与 503 的收口方向相反。
4. **唯一可能让人想加页面的点**（日历权限、剪贴板隐私）都属于**硬红线**，按 Q5 应落在**律令层**，不是界面层；界面层只需要在既有权限卡加一个条目（`SettingsPermissionCard.kt:87`）。

⇒ 若将来有人主张「需要新页面」，须先回答：**为什么现有设置页的一行开关 ＋ 既有确认卡放不下？** 本单没有找到这样的理由。
