**为什么 conflicts/identity/openLoops 不切当日窗**（metrics-registry.md 〇节写明）：它们是**状态读数**（队列深度／当下身份／欠账集合），不是事件流——切了当日窗，昨天进的队、前天许的诺就会从读数里消失（「数变好看」的经典路）。带窗口的三段（ratios/cards）写死**当日 00:00 起**（本地日历天，`AskGovernance.dayOf` 同一把尺），跨日只报当日。

## 2. 三条写死怎么在代码里成立（530）

| 写死 | 落点 | 用例的牙 |
|---|---|---|
| 窗口＝当日 00:00 起 | `GovernanceStateTool.isToday`（`AskGovernance.dayOf` 日历天）；`dayStartMs` 给 run_log 取数壳 | `跨日只报当日_昨日行不进今日读数`（昨日 pass/card/auto_act/no_data 一律不进；见 §4） |
| 分母 0 ⇒ `no_sample`（不编 0%） | `GovernanceStateTool.rateOf`：d==0 ⇒ `no_sample`；0<d<10 ⇒ `unknown`（**METRICS.md R1 同款**：样本不足不出百分比）；d≥10 ⇒ `Metrics.decimals` 那把尺 | `分母0回no_sample_不编0`＋`率的三态_…` |
| 计数只来自账本 replay | 每段「来源」列点名的函数就是取数路；`ratios.intervention` 是全表唯一非 jsonl 源（run_log，METRICS.md §1.3 唯一真相），经装配层注入的只读查询 | 对拍脚本与工具**两条取数路**逐项相等（§3） |

## 3. 对拍怎么做的（判据：脚本与出口逐项相等）

`GovernanceStateToolTest` 里有一条**脚本**（`script()`）：它**不走**生产取数路（不碰 `DecisionLedger.read`／`AskGovLedger.replay`／`currentCanaryBand`…），只拿**账本原文**（jsonl 行、承诺 md 表、身份 json）用 org.json 独立重算六段；「出口」是 `GovernanceStateTool.run` 的返回。两者**逐项断言相等**：四率的 n/d/rate、cards 三数、gray 全量键集与每格 band/cn、conflicts 计数、identity 两格、openLoops total 与逐条 items。

夹具同时埋了三类行：今日行（正常计入）、昨日行（跨日不进当日窗、但**挂着的冲突队列照算**——状态读数口径）、已回滚行（灰度档位行被回滚 ⇒ 退缺省档；violation 的回滚行只认它指到的当日 auto_act 行）。

## 6. 边界与未做

- **不写任何账**：工具是纯读（readOnly=true、parallelSafe=true、FREE、R0）；GuardPipeline 对它没有写面。
- **零新增 UI 面**：工具在 FILES 组默认不可见，模型要用先 `capabilities(enable="files")`；没有新页面、新按钮、新开关——唯一动的是既有「抱朴工具」目录里**每个工具都必须有**的两串标签（中英，闸门测试钉着），工具本体不出现在任何默认界面。
- **`openLoops` 只出键与日期**：不猜正文、不给建议（建议是反思器的职责，236 的 `mustFollowUp` 照旧）。
- **`gray` 是档位读数不是事件计数**：506 的观察样本（canary-run 行）不在本口内，别拿它算达标率（那是 `CanaryLadder.nextBand` 的事）。
- **真机未跑**：本批全部 JVM 单测可钉的都钉了；真机侧唯一新增行为是模型多看见一个只读工具，无 UI、无写面，留验机轮抽查。
