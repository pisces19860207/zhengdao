## 0. 一句话

v1 的子 Agent 是「只读研究工」：结构上没有写通路，账只在 `sub_task` 一行、回滚没有粒度。**v2 把四件补齐**——子上下文按父预算收（≤1/3）、每子任务一张名单（写类要父在 `grant_writes` 里逐件点名，名单外/递归一律拒并落账）、子 Agent 每条账行带 `agent_id`＋`parent_id`（新表 `sub_agent_ledger`，可按子任务分组）、**子 A 成功保留产物、子 B 失败按它自己的 opId 全撤**（复用 470 保险箱，不另造快照）。

**四件落点**

| 件 | 实现（唯一处） | 数据/代码 |
|---|---|---|
| ① 上下文隔离 | `SubAgentIsolation`（`SHARE=3`、地板 512、只裁 `input`）＋ `SubAgentRunner` 开局用它 | 纯函数 |
| ② 工具白名单 | `SubAgentWhitelist.effectiveWrites/decide`；`SubTask.tools`（读）＋`SubTask.writes`（父授予的写） | **数据**（落 `sub_task` 两列） |
| ③ 账归属 | `SubAgentLedgerRow(agentId,parentId,…)`＋`sub_agent_ledger`（v23）＋`groupByAgent` | 数据 |
| ④ 回滚粒度 | `VaultSubTaskWriteGuard`（写前 `RollbackVault.stash`，终态不成功 `rollback(ByOp("sub-<子任务id>"))`） | 复用 470 |

**① 的「不含父早期原文」是怎么钉的**：测试造 50 轮父消息（每轮带唯一标记「父第 N 轮原文」），把父 token 总额喂给 `seed`，再断言子上下文里**一个「父第」都没有**、且父任何一条正文都不作为子串出现——这比「只查第一轮」更严（连最后一轮也不许漏）。

**④ 为什么能「只撤 B」**：470 的 `RollbackScope.ByOp` 本来就是「一笔动作一炉」，这里把 **opId 定成子任务 id**（`sub-<子任务id>`）。并发下两条子任务同写也互不覆盖；A 成功 ⇒ `afterTerminal` 直接返回（产物留住），B 失败 ⇒ 只按 B 的 opId 回滚。**重试仍用同一个 opId**（同一件事的两次尝试要一起撤）。

## 2. 数据模型与迁移（v23）

| 变化 | 形状 | 幂等/老库 |
|---|---|---|
| `sub_task.writes` | `TEXT NOT NULL DEFAULT ''`（父显式授予的写类，逗号分隔） | 建表时就在列里；老库走 `PRAGMA table_info` 看列再 `ALTER`（新装/升级同一条路径） |
| `sub_agent_ledger` | `agent_id / parent_id / session_id / kind / tool / ok / detail / at_ms`，`REFERENCES session(id) ON DELETE CASCADE` | `IF NOT EXISTS` ＋两条索引（按分解、按子任务） |

`BaopuDb.VERSION` 22 → 23，`onCreate` 与 `onUpgrade` 两处都挂（`applyV23Migration`）。老库升上来只多一张空表＋一个默认空串的列——**老子任务读出来 `writes=''`，正是「当时只读」的事实，不回填、不编造**。

`ok` 落 0/1（不写 `true/false` 字面），`detail` 截断 160 字（账不是日志）。

## 3. 口径与取舍（都是主动决定，不是漏做）

1. **写授权走单独的 `grant_writes`，不进 `tools`**：`tools` 是「只能收窄」的读名单；把写工具混进去，模型顺手一写就变成默许。两条口径分开，才谈得上「父显式授予」。
2. **写只落工作区根内**：越界（含 `..` 折叠）**不入库、直接拒**，并落 REJECT 账。子 Agent 不是第二个全盘写手。
3. **子任务的写不弹确认卡**：授权来自父（`grant_writes`），安全网是「写前入库＋不成功整条撤回」。这是**取舍**——有 470 兜底，但确实少了人眼前那一张卡；如果以后要卡，接 `SafetyHooks.beforeRun` 的同一条口子即可（本批不动）。
4. **重试前先撤本次尝试**（实测踩到的坑）：不撤的话，第二次尝试入库的「原件」已经是第一次改坏的字节，最后回滚只会回到**坏状态**，等于没回滚。现在 `retry()` 先 `afterTerminal` 再回队。
5. **父上下文读数用 `run_log.tokens_in`（真读数）**，不用估算；一步都没读到 ⇒ 0 ⇒ 子上下文只吃地板 512。地板是防「短会话里子 Agent 连任务都读不全」，判据①的 50 轮场景仍由 1/3 主导。
6. **名单为空时不在判定层拦**：那是 v1「用户把读工具全关了」的形状，执行层照旧按空名单拒；两层各记各的账，不混算。
