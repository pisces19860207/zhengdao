## 给人的一页话（先结论）

这颗胶囊**不是常驻聊天入口**，是「教抱朴的时候，浮在玄览页面右下角的一颗小圆钮」。平时浏览网页它**根本不存在**；一点底栏的「教它一次」它才出现，教学一结束就消失。点它向上展开一张**不超过四成屏高**的小卡，里面看的是**主界面抱朴那条会话的原样消息**，在这儿说话等于在抱朴页说话，不会另开一个聊天、不会另存一份记录。

四个悬着的问题，本定稿各钉一个答案（详见 §3）：

| 问题 | 定稿答案（一句话） |
|---|---|
| ① 加载中／全屏视频／横屏 | 加载中照常显示但不自动引用；**当前 App 根本没有全屏视频态**（先定隐藏规则、不实装）；横屏切紧凑档，胶囊尺寸不变、位置按安全区重算 |
| ② 输入法 | 半屏根**只加一次** `imePadding()`，玄览根不许加；高度上限重算为 `min(40% 可用高, 可视高 − 8dp)`，输入行 48dp 固定，可视高 < 168dp 自动收起 |
| ③ 红点 vs 决策中心 | **点红点 ⇒ 就地展开半屏出确认卡，不跳决策中心**；教学确认不进 `decisionBadge`；只给一条「去决策中心」的可选文字出口 |
| ④ 多标签 | **胶囊跟全局（同时刻恒一颗），引用取当前标签**；切标签不关半屏、不回改已发出的引用标记 |

### ② 输入法冲突（半屏 + imePadding 具体数值）

**既有事实（①，不许改）**
- `AndroidManifest.xml:103`：`android:windowSoftInputMode="adjustResize"`。
- `MainActivity.kt:265`：`WindowCompat.setDecorFitsSystemWindows(window, false)`（edge-to-edge）。
- `ui/baopu/BaopuScreen.kt:616`：抱朴页根 `Column(Modifier.fillMaxSize().imePadding())`；`ui/baopu/BaopuComposer.kt:324` 明确「imePadding 由 BaopuScreen 根统一消费，**避免双份**」。
- `ui/baopu/BaopuScreen.kt:1033`：**「不依赖 `WindowInsets.ime`（该版本 Compose 里取不到这个扩展属性）」** ⇒ 本定稿禁止用 `WindowInsets.ime.getBottom()` 去算任何数值。
- `ui/browser/BrowserScreen.kt:309`：玄览根是 `Column(modifier.fillMaxSize())`，**当前无 `imePadding()`**。

**规则（③，逐值）**

| 项 | 值 / 口径 | 理由 |
|---|---|---|
| `imePadding()` 加在哪 | **只加在半屏根，一次** | 与抱朴页同款；玄览根 Column **不许加**，否则底栏被顶飞（双份） |
| 清单 / Activity | `adjustResize` 与 `setDecorFitsSystemWindows(false)` **一个字不改**；不许改 `adjustPan` | 已就位，改了是第二条避让链 |
| 半屏形态 | **叠层 `Box`，不是 `Dialog`** | 派工单②「非新页面跳转」；`DecisionCenterScreen.kt:106` 那种 `DialogProperties(decorFitsSystemWindows = true)` 会改变 inset 行为 |
| 常态高度上限 | `min(BoxWithConstraints.maxHeight × 0.40f, 内容自然高)`，**硬顶 ≤40% 可用高** | 623 派工单①＋230-A2 硬要求 2「绝不整屏遮挡」 |
| 键盘弹起后高度上限 | `min(0.40 × 可用高, 键盘弹起后的根可视高 − 8dp)` | 8dp 是半屏底边到 IME 上沿的固定余量 |
| IME 高度怎么知道 | **不写死 dp**：靠 `.imePadding()` 让系统 inset 顶起根布局，再用 `onGloballyPositioned` / `snapshotFlow { layoutInfo.viewportSize.height }` 读**实际可视高**（`BaopuScreen.kt:1034–1041` 同款手法） | 各输入法高度不同；写死 300dp 必错 |
| 底边距 | 底栏上沿之上 **8dp**；键盘弹起时底边距 IME 上沿 **8dp** | 与胶囊同一基线，不盖底栏 |
| 最小高度 | 竖屏 **200dp**；横屏紧凑档 **168dp** | 保证「标题 44 + 消息 ≥96 + 输入 48」三行不塌 |
| 固定行高 | 标题行 **44dp**（= `BAO_RECORD_HEIGHT_DP`）、输入行 **48dp**、消息区 **≥96dp** | 复用既有档，不新造尺寸 |
| 太低怎么办 | 键盘弹起后可视高 **< 168dp ⇒ 自动收起半屏**，胶囊保留；输入草稿用 `rememberSaveable` 保住 | 宁可收起也不许把输入行压没 |
| 消息贴底 | 键盘弹出（视口变矮）且原本贴底 ⇒ `snapshotFlow` 里 `scrollToItem(last)` | 照抄 `BaopuScreen.kt:1037–1041`，不新造机制 |
| 网页滚动 | 半屏是叠层，不重建 `AndroidView` ⇒ **网页滚动位置天然不变** | 派工单② |

### ③ 有待确认时，红点与决策中心的关系

**定稿：点红点 ⇒ 就地展开半屏，在半屏里出确认卡；不跳决策中心、不切 Tab、不改路由。**

三条理由：① 623 派工单②「点开是半屏（不改页面路由）」；② 教学录制/回放进行中，跳走会丢现场上下文；③ 教学就地回答「这步对不对」与治理层「授权 / 提案 / 拍板」不是一回事，混进决策中心会污染「唯君可决」的语义（`decision_center_hint`）。

**三类确认分流表（写死）**

| 类别 | 例子 | 渲染在哪 | 落盘口 | 计数 |
|---|---|---|---|---|
| 教学就地确认 | 「这步是提交还是普通按钮？」「要不要加校验点」「从第 N 步重跑」 | 半屏内的**行动卡**：复用 `BaopuActionContainer`（`ui/baopu/BaopuContainers.kt:126`，四档容器之一，**不许新增第五档**） | 不落盘；回答走 `controller.send(text)` | **红点，不显示数字** |
| 保存成技能（写盘） | `teachDraft != null`（`BrowserScreen.kt:200`） | **仍用既有 `TeachConfirmSheet`**（`ui/browser/TeachBar.kt:81`，AlertDialog，唯一落盘口）；半屏只给一个「打开确认卡」按钮 | `teachModel.save(...)`（`BrowserScreen.kt:536`） | 红点 |
| 治理层待决 | 组授权 / 人设提案 / 采纳后队列 | 决策中心（`ui/baopu/DecisionCenterScreen.kt:99`，由 `BaopuScreen.kt:1566` 的 `showDecisionCenter` 打开） | 既有决策链 | `controller.decisionBadge`（`BaopuChatController.kt:1269–1273`） |

**红点口径**
- 红点**只在「必须你决定」时亮**（623 派工单②）：教学问答待答、校验点待判、`teachDraft` 待确认。三态优先级 `NEEDS_DECISION > THINKING > IDLE`；同时刻**只有一颗胶囊**（230-A2 硬要求 3）。
- 红点是**点不是数**：8dp 圆点、不带 `N`；**不读、不改、不合并** `decisionBadge`（该值只数 `GROUP_AUTHORIZATION` / `PERSONA_PROPOSAL` / `postAdoptionQueue` / `evolutionSuggestions`，实读 `:1270–1272`）。
- **不自动跳决策中心、不弹窗提醒**（230-A2 硬要求 4「永不靠弹窗提醒」）。

**唯一的出口（可选、显式）**：仅当 `controller.decisionBadge > 0` 时，半屏标题行下方显示一行 `labelMedium` 13sp 的「还有 %1$d 项等你决定 · 去决策中心」；**点了才**显式切到抱朴 Tab 并打开 `DecisionCenterScreen`。跨页开槽按 `BaopuIntents` 的 `peek*/consume*` 同房型（`ui/baopu/BaopuBackupScreen.kt` 内定义，`MainActivity.kt:734–748` 是消费范例：进程级单例 + 组合期读 + 消费后清槽），**不新造路由**。

**与 230-A2 橙点 `?N` 的界线**：橙点带数字属 624 阶段一的「未学会清单」（`624 派工单:17`）与 230-A2「有问题」态，**教学模式下不显示橙点**；624 阶段四把胶囊做成共用组件时，按本表优先级仲裁，仍恒一颗。623 不实现橙点。

### ④ 多标签：跟全局，引用当前标签

**定稿：胶囊是全局单例（同时刻恒 1 颗），不跟 `activeTab()` 重建；「引用本页」在发送那一刻取当前标签。**

- 源码依据：`BrowserTabManager` 是 `object`（`ui/browser/BrowserTabManager.kt:55`），`activeId`（`:75`）、`tabs()`（`:303`）、`activeTab()`（`:306`）；每标签状态在 `BrowserTabState.url/title/loading`（`:33/:36/:39`）。上限 20（`BrowserTabPolicy.MAX_TABS`）。
- 理由：会话与账是**进程级一份**（`BaopuRuntime.db / engine / memoryStore` 单例，`BaopuRuntime.kt:174/:303/:838`；`sessionId = BaopuRuntime.latestSessionId(db)`，`BaopuChatController.kt:1169`）。若胶囊跟标签，切一次标签就换一颗、最多 20 颗，直接违反 230-A2「同时刻只有一颗」，还会让教学会话分裂。
- **引用取值时机**：点发送的那一刻，读 `BrowserTabManager.activeTab()?.state`，拼 `[当前页: URL]`（623 派工单判据④），随 `controller.send(text)` 进同一会话；**已发出的历史消息里的标记不回改**（记账不回改）。
- 切标签：半屏**不自动关闭**；标题行即时换成新标签标题；引用开关状态不变；下一条消息引用新标签。
- 本地预览页签（`BrowserTabState.isPreview()`，`:181`，地址是 `local-preview://…` 假地址）：引用标记改用**显示名**、引用开关**自动置关**并给一行说明；**不许把假 URL 喂给模型**。
- 关掉最后一个标签（`active == null`）：胶囊仍在，引用自动置关，标题行显示「没有打开的页面」；**不伪造 URL**。
- 标签数上限 20 **不影响胶囊数量**（恒 1）。

## §1 收窄口径与边界（来自 623 用户裁定）

1. **只在玄览页**：`MainActivity.kt:912` 的 `BrowserScreen()` 之内；抱朴页 / 律令页 / 任何二级页**不出现**。
2. **只在教学模式**：即 `TeachBar` 的「录制中 / 回放中 / 刚保存待确认」三态（裁定记录 `:3432`）。当前代码里可观察的只有 `teachRecording`（`BrowserScreen.kt:198`）、`teachDraft`（`:200`）、`teachStepCount`（`:199`）；**回放中当前没有状态源**（见 §5.5），623 一期不实现该态。
3. **非教学模式不显示**：普通浏览时胶囊 Composable **不进入组合树**（不是 `visibility = GONE`）。负例判据⑨：普通浏览出现胶囊 ⇒ 红。
4. 胶囊里装的是**教学相关回应**（这步对不对 / 加不加校验点 / 存不存技能 / 再教一次），**不是通用闲聊**；通用对话仍在抱朴页（裁定记录 `:3433`）。
5. 触发：点底栏「教它一次」（`onTeachToggle`，`BrowserScreen.kt:501–520`）⇒ 胶囊出现并跟随录制；结束教学（`teachRecording = false` 且 `teachDraft == null`）⇒ 胶囊与半屏**一起消失、不留残影**（判据⑪）。
6. **不新增第二套会话存储**：不建 DB 表、不建 jsonl、不建第二个 `BaopuChatController`（§5）。
7. 不引第三方 UI 库；不改 `RunEngine` / 判定层 / `GuardPipeline`；不改页面路由；不占 main。
8. 与 622 分工：**622 = harness**（执行端口 / 脚本 / 校验点），**623 = 教学时的对话外壳**；与 624 分工：624 阶段四才把胶囊做成共用组件并接回放可见（`:43–48`）。

## §3 形态规格（逐项给值）

### 4.2 唯一采纳方案：把控制器上提到公共父组合

**改 3 个文件、不新增任何存储**，具体落点：

1. `MainActivity.kt`（`Surface { }` 内、`when (tab)` 之前，约 `:897`）：把 `channelEpoch` 与 `val controller = remember(channelEpoch) { BaopuChatController(context) }` 提到这一层；`:904` 改 `BaopuScreen(controller = controller, onChannelChanged = { channelEpoch++ })`，`:912` 改 `BrowserScreen(controller = controller)`。
2. `ui/baopu/BaopuScreen.kt`：删 `:178–179` 两行，改为接参；`:227 / :247 / :1524` 三处 `channelEpoch++` 改调 `onChannelChanged()`；`:384` 的 `LaunchedEffect(channelEpoch) { controller.refresh() }` 保留，改吃传入的 controller。
3. `ui/browser/BrowserScreen.kt`：`fun BrowserScreen(modifier: Modifier = Modifier, controller: BaopuChatController)`；`:309` 的 `Column` 外包一层 `BoxWithConstraints`，浮层（胶囊 + 半屏 + 遮罩）叠在这个 `Box` 内，**`Column` 自身一个字节不动**（标签条 / 页面区 / 提示条 / TeachRecordingBadge / 底栏全部原样）。

**数据方向（写死）**：半屏**只读** `controller.messages` / `busy` / `decisionBadge` / `pending*Spec`；**只调** `controller.send(text)` 与既有确认动作；**不 new** `BaopuChatController`、**不 new** `BaopuDb` / `MemoryStore` / `PendingStore`、**不建**任何 DB 表 / jsonl / 文件。引用本页只是把 `[当前页: URL]` 拼进 `send(text)` 的文本，不是一个新通道。

### 4.3 三个不采纳的备选（写清为什么，免得下一刀又绕回来）

### 4.4 旋屏边界（诚实）

MainActivity 未声明 `configChanges`（`AndroidManifest.xml:100–103`），旋屏**会重建 Activity** ⇒ 上提后的 controller 会重建一个实例。这不是「第二份存储」：底层 `db / engine / memoryStore` 是进程单例，`sessionId` 从库读回（`:1169`），消息 `refresh()` 重读（`:5538`），会话仍是同一条。故判据③「同一 controller 实例」的口径**限定为同一次 Activity 生命周期内切 Tab 不重建**；旋屏允许重建，但半屏展开态 / 草稿 / 引用开关 / 胶囊位置必须 `rememberSaveable` + SP 保住。

### 4.5 「引用本页 / 引用选区」的实装边界

- **引用本页**：现成 —— `BrowserTabManager.activeTab()?.state.url / title`（`BrowserTabState.kt:33/:36`）。
- **引用选区**：**当前无通道** —— `bridge/` 与 `browser/` 全仓 `grep getSelection / selectedText / selection` = **0 命中**（2026-11-13，①）。⇒ **623 一期只做「引用本页」**；选区留接口位：待 622 的「单一执行端口」（`bridge/BrowserCommands.kt`）收口后，加一条只读 `evaluateJavascript("window.getSelection().toString()")`，截断上限与页面快照同口径。**不许现在就假装能取选区**，也不许把整页 HTML 回灌（622 判据⑥）。

### 4.6 回放态与「2/5」读数的诚实契约

`TeachSessionUiModel`（`baopu/TeachReplay.kt`）当前**没有可观察的回放状态**；`browser_replay_skill` 走工具侧。⇒ 623 一期只认「录制中 / 待确认」，**不显示 `▶ 2/5` 这类步号**（裁定记录 `:3442` 的诚实契约：答「记住了」必须来自存储读数，没有就说没有）。回放可见与橙点 `?N` 归 624 阶段四。
