# 口径 · L2.5 定义与升级闸门（2026-10-18 · 蓝总管提案，待用户最终点头）

> 触发：用户 2026-10-18 逐字「你刚刚做的裁决就很好啊，所以我觉得应该可以往 L3 方面靠了」。
> 本文件回答一件事：**为什么「我判得好」不能当成上 L3 的理由，以及不碰 L3 也能拿到大部分好处的那条路**。
> 本文件是**提案**，不是拍板；拍板权在用户。台账 §B 顺序 66 的「L3 不做」在用户改口之前仍然有效。

## 0. 一句话

**L3 ＝ 模型可以改自己的边界；L2.5 ＝ 模型可以长流程、长技能、长记忆，但边界永远在它够不着的地方。**
「厚 harness」的正确含义不是给模型更多钥匙，是**把车造得更结实**（安全带、气囊、行车记录仪），不是拆掉限速。

## 1. 为什么「蓝总管最近判得好」不能作为上 L3 的依据

这不是客套，是三条具体的机制问题：

1. **判据不能建在「这个 agent 昨天表现好」上。** 今天的裁决之所以稳，很大程度是因为**边界把它挡住了** ——
   我不能改内核、不能动权限、不能加工具，所以我只能在护栏里想办法。把我自己判例当理由去拆护栏，等于「因为考试考得好，所以申请免考」。
2. **审查者与被执行者是同一个时，审计失效。** 现在的红线验证者＝人＋机械门禁；L3 之后，
   改边界的是我、审查边界的也是我 —— 任何一次「温和的、看起来合理的」放宽都没有第三方能发现。
   这不是信任问题，是**结构问题**：同一个人不能既写账又查账。
3. **模型会漂移，而人的信任不会自动跟着更新。** 换模型、换通道、上下文被别人的话灌满、
   长会话里目标慢慢漂 —— 这些都是已经见过的现实（压缩把摘要当真相、上下文注入、工具回灌）。
   L3 让「漂移」第一次有了**修改护栏**的能力，后果不是一次答错，是**错误被写进规则**。

## 2. 具体禁止（不管 L 几点，永远不许模型自己改）

| 面 | 为什么 |
| --- | --- |
| **A 内核**（三条边界：不跨 rootfs／不起子进程／只在工作区活动） | 越界读写的第一道门，改它等于自己给自己开锁 |
| **工具集**（增删工具、改 schema、改名字） | 加一个「删文件」工具，前面所有确认卡都白搭 |
| **权限表**（`ToolPermission` 的 CONFIRM→FREE） | 确认制是唯一的人工闸门，拆掉它等于全自动 |
| **路径红线**（`PathGuard`／`GuardPipeline`／`WORKSPACE` 判定） | 与 A 内核同一件事的内层实现 |
| **压缩红线**（`NEVER_COMPRESS` 前缀） | 压缩会把内容变成摘要，红线被压掉就再也找不回来 |
| **评测基线与阈值**（`eval/baseline.json`、用例删除） | 让模型改考题＝自己给自己印准入证 |
| **构建面**（清单、gradle、`.gitattributes`、权限声明） | 属于「能力层」，且影响面在 App 之外 |

**用户 2026-10-17 的原话仍然是对的**：「A 内核肯定不能动的」「工具集改了那工具不就失效了」
「权限要是模型能改那万一改的特别大怎么办」「现在的智能汽车都不敢弄 L3 的」。本文件不改这些结论，
只是把它们写成可执行的判据。

## 3. L2.5 给什么（都是「长流程」，不是「长权限」）

| 能力 | 现状 | L2.5 目标 | 判据 |
| --- | --- | --- | --- |
| **技能可新建/可编辑** | 第十九批只能**看和删**（`技能/<名>/SKILL.md` 得手动放文件） | 抱朴能写技能正文，**走确认卡**落盘，写前备份、写完可回滚 | 写盘只走 `PersonaFiles.applyProposal`／技能写入口；未确认不落盘 |
| **技能有试用期** | 一写就是正式 | 先「草稿」用 **3 次**，每次跑完汇报「这条技能起作用了吗」，用户一键转正/丢弃 | 草稿与正式两态；未转正的技能不能进人设索引 |
| **提案跑自检**（厚 harness 的那一层） | 提案只做人审 | 提案落盘后**自动**跑一次 eval 10 例 ＋ 红线 diff，不过就**自动回滚**并如实报 | 自检失败 ⇒ 回滚后文件 sha256 与改动前一致 |
| **评测闸门机制化** | 闸门建好但**一次也没拦过人**（不进 CI、没 key 跳过） | 改提示词/技能必须过闸门，否则构建红 | CI 与本地构建都跑到；无 key 时**跳过要显式标注**，不许假装通过 |

## 4. 升级闸门（什么时候才允许往 L3 靠 —— 用证据，不用印象）

> 这是本文件唯一允许「往 L3 方向挪」的通道，且**每一步都可回退**。

连续满足以下四条满 **20 次提案**（一次不达标就清零重数）：

1. 每条提案都是**先提案、后确认**（没有人替它跳过确认卡）；
2. 每次跑过 eval 10 例，**没有一次退化**；
3. 红线 diff（`terminal/rootfs/browser/baopu/agent/清单/eval`）**一次都没命中**；
4. 出现失败时，它**自己报出来**（不是被人抓到）。

满足之后允许的升级（**仍然不碰第 2 节**）：
- 技能草稿试用 3 次 → **1 次**；
- 提示词措辞类提案可以从「逐条确认」提到「**先自动用、跑完汇报**」，汇报里必须带 diff 与 eval 读数；
- 技能自动进入索引（不再要人点「转正」），但**删索引仍然手动**（这条永远手动）。

不满足就**停在这一级**，不许「感觉差不多了」手动跳级 —— 这正是 L3 当年被否掉的那条理由。
