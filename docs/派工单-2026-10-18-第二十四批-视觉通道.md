## 0. 一句话

附件能选了，但**模型看不到图**（`LlmMessage.content` 是纯字符串，发不出图片块）。本批把「图片真进模型」做通：**有视觉能力的通道才发图、没有就明说不发**，不许塞进去让模型瞎猜。

## 1. 现状（带行号）

| 事实 | 证据 |
| --- | --- |
| 消息体是纯字符串 | `baopu/LlmClient.kt:26 data class LlmMessage(val role: String, val content: String)`；`:205`/`:222` 都是 `put("content", m.content)` |

## 2. 规格

### 2.1 A 段（**现在就能做，不碰 `ui/baopu`**）

1. **`Provider` 加视觉能力字段**：`vision: Boolean = false`；
   - `DEEPSEEK` ⇒ `false`（DeepSeek 的 chat 接口不吃图片块，**写死并注释依据**）；
   - `BUILTIN_FREE` ⇒ `false`（未实测，**不许猜成 true**）；
   - 每加一个 `true` 必须在注释里写清「依据：哪个模型的 `input_modalities`／哪次实测」。
2. **`LlmClient` 支持多段 content**：新增
   `data class LlmMessage(role, content, images: List<String> = emptyList())`（`images` 是 `data:` URL 或裸 base64，**由调用方决定**）；
   - `images` 为空 ⇒ **走原来的字符串 content**（一字不改，防回归）；
   - 非空 ⇒ `content` 改成 JSON 数组：`[{"type":"text","text":…},{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,…"}}]`。
3. **`ContextAssembler` 组装时按能力裁图**（纯函数，必须可 JVM 直测）：
   - 入参加 `visionSupported: Boolean`；
   - `false` ⇒ **一张图都不发**，并在该消息文本末尾追加一句「（当前通道不能看图，已省略 N 张图片）」；
   - `true` ⇒ 把本轮附件的本机路径读成 base64，**单图 ≤ 2 MB、总数 ≤ 4 张、总字节 ≤ 6 MB**，超了截断并明说。
4. **不许**在 `LlmMessage` 里塞绝对路径、也不许把工作区路径发给模型（路径只在本机解析）。

### 2.2 B 段（**等 Trea 的第二十批合入后再做**，避免撞 `BaopuScreen`/`BaopuChatController`/`BaopuDb`）

5. 控制器 `send()` 接受结构化附件（`List<Attachment(relPath, isImage, sizeBytes)>`），**落库成 `part.kind='image'`**（`payload` 存相对路径；`part.kind` 是自由文本列，不需要迁移）。
6. `ContextAssembler` 从消息的 image part 取路径 ⇒ 走 2.1 的裁剪逻辑。
7. 气泡里显示缩略图（小图 96dp，点开可看大图/长按复制路径）——**只读文件，不复制、不新落盘**。

## 4. 判据

| 编号 | 判据 |
| --- | --- |
| V1 | `images` 为空时，请求体与改动前**逐字节等价**（同一份消息/工具，字符串 content 原样） |
| V2 | `images` 非空时，content 是数组，且 text 段在前、image 段在后 |
| V3 | `vision=false` ⇒ **一张图都不发**，且文本里明写省略了几张（不许静默丢） |
| V4 | 单图 > 2 MB / 超 4 张 / 总字节 > 6 MB ⇒ 裁剪并明说（有测试） |
| V5 | 视觉能力判据**从 `Provider` 读**，UI/组装层不许硬编码模型名 |
| V6 | 发给模型的 payload 里**不许出现本机绝对路径** |
| V7 | 压缩请求（`Compressor`）不得带图（压缩是减少 token，不是看图） |
