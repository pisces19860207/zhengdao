# 参考实现对拍（963）

> 适用：**触发条件（§1）命中的每一单**——移植、重写/优化、跨端对齐、口径迁移。未触发的单不强制（见 §8 边界）。
> 配套：与 873 三步（`docs/交付自查三步.md`）是**合取门**，不互替——873 管"单实现输出对不对"，本文管"两套理解是不是同一套"。
>
> 来源：2026-11-28 一单干活时自述「**Python 精确移植版完全正确——说明写入的 Kotlin 代码与心智模型有出入**」。
> 这句话暴露的不是"写错了"，而是**"脑子里的模型"与"写下的实现"不是同一个东西**：
> 实现按 A′ 写、测试也按 A′ 断言 ⇒ **全绿**，偏差被"同源"掩盖。同一套理解写的测试，抓不到这个偏差。
> 只有**独立的第二实现**（不同写法/不同语言/独立手算表）才能把它照出来。
> 本文把"外化成参考实现＋对拍＋归因"从"靠自觉"变成"靠流程"。

## 0. 名词

- **心智模型偏差**：判据/规格说按 A 算，实现按 A′ 写（少一个边界、顺序反了、单位错了、批次语义混了）；测试与实现共享同一误解 ⇒ 同源测试全绿。**同源盲区**只能靠异源实现照出。
- **主实现**：本单要交付/要改的那份实现（Kotlin/Rust/……）。
- **参考实现**：按**判据与规格**独立推导的第二实现（Python/Julia/手算表/另一算法路线），**只作验证，不作运行时依赖**（§7 R6）。
- **黄金数据**：≥20 组"输入＋期望输出"的机读对照表（§3），期望值来自**独立来源**（规格手算、独立夹具、独立工具库），**不许**从主实现的运行输出抄。
- **逐位对拍**：同一组输入分别喂主实现与参考实现，输出**逐位/逐档/逐字节**比对（§5）。
- **差异归因**：每条差异标 `实现错` 或 `意图错`（§6），不许留"没归因的差异"。

## 1. 触发条件（满足其一即走本规范）

| # | 触发 | 例子 |
|---|---|---|
| ① | **移植**（Kotlin ↔ Python/Rust/Julia 任一向） | 精确移植某个计算链到脚本侧做验证 |
| ② | **重写/优化**（同一功能换算法/换结构） | 换更快的数据结构、合并循环、下沉内核 |
| ③ | **跨端对齐**（App 与 CI/工具链算同一件事） | App 内判分 vs CI 评测脚本、App 内构建读数 vs 工具链读数 |
| ④ | **口径迁移**（判据/表/模块搬家） | 943 把表搬进 manifest、954 搬模块——搬家前后口径必须逐位等价 |

**联动**：954（Rust 下沉）与 922（科学层）一类"双实现对拍"按本规范执行。

## 2. 四件必交（缺一件＝未完成）

### ① 独立参考实现（不同源）

- **从判据/规格出发写**，不从主实现源码翻译：
  - **不许**逐行翻译主实现（同语言同结构照抄＝把主实现抄一遍，F1/R1 判红）；
  - **不许**复用主实现的常量表、结构镜像、命名映射（抄表＝抄实现）；
  - 写参考实现期间**不对照主实现源码**（先按规格推导完，再进入对拍阶段）；
- **不同源**的合格形态（满足其一）：
  1. **不同语言**（Kotlin ↔ Python/Julia/Rust 互换）；
  2. **不同算法路线**（同语言但走另一条数学/数据路线，如查表法 vs 解析式）;
  3. **独立手算表**（人工按规格逐档推的对照表）；
- 主实现里**规格没写**的行为，参考实现不许"顺手照抄"——对拍阶段暴露为差异，按 §6 归因（通常落 `意图错` 或规格缺口）；
- 交付报告必须写一节"**为什么算独立**"：语言/路线/数据来源三条里占哪条、实现顺序如何保证没先看答案。

### ② 黄金数据（≥20 组，含六类边界）

- **数量**：≥20 组"输入＋期望输出"（○ 设定，见 §9）；
- **六类边界各 ≥1 组**（○ 设定）：

| 边界类 | 造法 |
|---|---|
| **0** | 零值/空集合/空输入 |
| **负** | 负值输入；该域定义上无负值时，用"越下界"替代并在表里注明 |
| **极大** | 该域量纲的上界（最大里程/最大容量/最大索引） |
| **极小** | 该域量纲的下界（最小正数/最小步长） |
| **退化** | 结构退化：单元素、重复键、自相交、零向量、只有一个档位等 |
| **并列** | 排序/取最值/去重遇到相等键：**并列必须按既定 tie-break 口径逐位核对**，不许"取哪个都行" |

- 期望值来源必须独立（规格手算/独立夹具/独立工具库），**不许**拿主实现的输出当期望值——那是把答案抄进题目；
- **容差在造表时一并钉死**写进口径（§5），不许跑完对拍再挑容差；
- 机读存放（JSON/CSV/表格）随参考实现放在 `tools/` 或 `docs/`（§7 R6），每组标注边界类与期望值来源。

### ③ 逐位对拍

- 同一组黄金输入分别跑主实现与参考实现，输出**逐位/逐档/逐字节**比对：
  - 整数/档位/枚举/文本：必须完全相等；
  - 浮点：默认按**位模式**比较；口径里声明了等效判据（如 1e-9 相对差）就按口径，**判据要提前钉，不许事后挑**；
  - 多字段输出逐字段比，不许只对拍"汇总值"；
- **逐位一致** ⇒ 直接出读数；**有差异** ⇒ 差异**逐条列出**（输入组号、主实现值、参考实现值、涉及字段），一条不许少——对拍器/夹具自身的 bug 先修好重跑，不算归因出口（§6.3）。

### ④ 差异归因（`实现错` / `意图错`）

每条差异二选一（细则 §6）：

- `实现错` ⇒ **改主实现**，并给回归夹具（进主实现自己的测试）；
- `意图错` ⇒ **同批改判据并留旧文**（§6.2，对照 829/888 留痕口径）。

## 3. 判据（R1–R6）

| # | 判据 | 可机验形式 |
|---|---|---|
| R1 | 参考实现与主实现**不同源**（不许同语言同结构翻译） | 报告有"为什么算独立"一节：语言/路线/数据来源占哪条＋实现顺序说明 |
| R2 | 黄金数据 ≥20 组且含六类边界（0/负/极大/极小/退化/并列） | 机读表行数 ≥20；六类标记各 ≥1；每行有期望值来源列 |
| R3 | 对拍输出**逐位一致**，或差异全部有归因 | 读数表：N 组比对结果；差异清单每条标了 `实现错`/`意图错` |
| R4 | 有 `意图错` 时**同批改判据并留旧文** | 判据文件里旧口径原文可查（改前/改后并列），私有侧 ERRATA 或单内有更正块；引用旧口径的测试同批更新清单 |
| R5 | 参考实现**自带测试**（防"参考实现也是错的"） | 独立 runner 跑通（如 `python -m unittest`），黄金数据回放＋独立断言，读数进报告；不接 Gradle 测试水位 |
| R6 | 参考实现**不进交付包** | 只进 `tools/` 或 `docs/`，文件头标 `reference-only`；`app/src/main` 与 assets/res/jniLibs 无命中；APK 产物清单无参考实现文件 |

## 5. 对拍流程（六步）

```
第 1 步  钉独立预期   从判据/规格把关键行为写成可推导的表述；规格没写的先记"规格缺口"，不许边看主实现边补
第 2 步  写参考实现   按 §2① 独立推导；自测先行（R5）
第 3 步  造黄金数据   ≥20 组含六类边界（§2②）；容差此刻钉死进口径
第 4 步  跑主实现    同一组黄金输入喂主实现，取完整输出
第 5 步  逐位比对    按 §2③ 比对；差异逐条进清单
第 6 步  归因与处置  §6；报告按 §7 回填
```

与 873 三步的关系：触发了本规范的单，873 三步照做（完整输出/双侧变异/夹具门槛）；
参考实现自身也要按 873 第二步做**可接受/可拒绝双侧变异**——否则"参考实现也是错的"没人拦（R5 的深一层）。

## 6. 差异归因细则

### 6.1 `实现错`

主实现与判据/规格不符：

1. **改主实现**（不是改参考实现迁就它）；
2. 该差异组转成主实现的回归夹具（含门槛两侧，对照 873 第三步）；
3. 复跑对拍到逐位一致。

### 6.2 `意图错`

黄金数据与主实现**都按旧口径一致地"错"**——错的是判据/规格本身：

1. **同批改判据**：新口径本批生效，不许"下次再说"；
2. **留旧文**（对照 829/888 口径）：
   - 旧口径**原文不删不改**——判据文件按「改前原文＋改后原文＋生效批次」并列留痕（829 §三的"改前断言原文/改后断言原文"格式）；
   - 同时在**私有侧 ERRATA 或本单「旧口径存档」节**追加更正块（ERRATA 纪律：只能追加，不许回改原文）；
   - 引用旧口径的测试/文档**同批更新**，报告里列清单（哪几条、改了哪一档）；
   - 状态升迁要有证据（888 口径：只有真改到位且有 `文件:行` 证据才算已改）；
3. 复跑对拍到逐位一致（对的是**新口径**的黄金数据）。

### 6.3 两种不许算归因出口的情形

- **对拍器/夹具自身 bug**（两边都对、比对脚本错了）：修好重跑，重跑前不产生任何归因结论；
- **浮点容差事后放宽**：容差没在造表时钉死 ⇒ 本轮对拍作废，先补口径再重跑（防"调容差调到绿"）。

## 7. 参考实现的落地位置与标记

- **只进** `tools/`（机读脚本/黄金数据，随仓走但不进构建）或 `docs/`（手算表类）；
- 文件头一行标记：`reference-only：验证用参考实现，非运行时依赖，不进交付包`；
- **不进** `app/src/main`、assets、res、jniLibs、rust 交付产物——交付包（APK/AAB）内容清单里不得有参考实现文件；
- 参考实现的测试用其自身语言的 runner 独立跑（如 `python -m unittest`），**不接 Gradle 测试水位**、不动 detekt/lint 预算；
- 参考实现**不作为任何运行时依赖**：主实现不许 import/加载/读它（只作验证）。

## 8. 边界

- **不要求所有单都做**：只在 §1 触发条件命中时做；纯 UI/纯文档/纯裁定单不触发；
- 参考实现只作验证，**不作运行时依赖**；
- 与 954（Rust 下沉）、922（科学层）联动：那些"双实现对拍"按本规范执行；
- 仓内已有"逐字对拍"先例（571 法典 md↔代码常量逐字对拍）——本规范把它推广成通用门；
- 本规范**不替代** 873 三步；两者是合取门。

## 9. 证据等级自曝（硬规三）

- 「≥20 组」「六类边界各 ≥1」「浮点位模式比较」等阈值与形态均为 **○ 约定（这是设定，无实证阈值依据）**；
- 「同源测试抓不到同源误解」的机理是本仓 2026-11-28 实录（一单自述移植版全对而 Kotlin 与心智模型不符）＋ 835/873 的同源断言教训，属 **A1 仓内可复现观测**；
- 档位/容差的具体数字永远随口径走，改口径走 §6.2 留痕。
