## 一、这张表为什么长这样

素材的主体功能被客观数过一遍：**过半条目在写「不许这样写」，不是在写「是什么」**。
而 AI 写偏的根因不是不认真，是三条结构问题——其中最要命的一条是**极值坍缩**：
语料只记录「值得写」的值，写常态没人看，写极端才有张力 ⇒ 训练分布的右尾被截断后又被当成常态。
医学文献恰好相反，它记录**全部样本**，包括无聊的中间值。

所以：

| | 医学文献的局限 | 语料污染的局限 |
|---|---|---|
| 偏在哪 | 样本偏临床、测量条件不一、总量小 | 只剩「值得写」的值，无测量条件、无分布概念 |
| 错的方向 | **精度不足**（区间宽） | **方向错**（系统性偏高、偏极端） |
| 对引擎 | 够用：给分布＋区间就能跑 | 不能用：给的是偏差点值 |
| 能不能修 | 能（标误差、扩样本） | 不能（只能整个不用） |

**结论落到一条工程纪律：方向只能从文献取，所以本表只收分布与区间；精度差可以标误差，方向错了修不回来。**
这也解释了为什么本表拒绝点值——点值正是语料交给引擎的东西。

## 二、收数四条规矩（判据①②的口径）

1. **只收区间／分位／阈值端点／量表枚举／定性方向**。出现「可直接赋给某个角色的身体读数」这种点值字段 ⇒ 红。
2. **无来源不收**。来源形如「节｜文件:行区间」，指回私材可对照行号；每条必须同时带证据等级，缺一拒收。
3. **表外不外推**。分位表没给的分位不许插出来再当事实用——外推就是编数，装载器直接拒。
4. **均值与 SD 是「分布的参数」，不是「角色的取值」**。判据③ 要求用它们换算分位，所以它们必须在场；
   下游要一个具体角色的数，只能**按分布抽样**或**按分位取档**，不许把任何端点当默认角色值抄。

单位口径：长度只存 cm（`660` 的 `FactSource` 以 mm 存储，换算由装载器做，两处不并记）。

## 三、证据等级与四类参数（判据①的分母）

| 标记 | 含义 |
|---|---|
| ✅ | 已核原文 |
| ◐ | 临床共识（未逐条核原文） |
| ○ | 工程假设 |
| ✗ | 虚构设定 |

**继承口径（要说清，不然会误读）**：✅ 是上游报告作者的核对结论，665 原样继承并把出处写进
`sourceDetail`；本单按派工单 §三「不引入新的外部数据抓取」**没有独立复核原文**。
所以这里的 ✅ 含义是「上游已核＋出处可追」，不是「665 复核过」。

| 参数类 | 例子 | 来源 | 标记 |
|---|---|---|---|
| 分布参数（采样） | 长度、周长、潜伏期、不应期 | 文献均值＋SD | 可标注 |
| 阈值参数（事件） | 硬度分级边界、抽样上限、提示触发线 | 临床量表 | 可标注 |
| 速率参数（积分） | 充血上升时间常数、温度回落速率 | **文献基本没有**，只能人定 | **必标 ○** |
| 约束（硬逻辑） | 无刺激 ⇒ 充血不升；越勒越烫为非法 | 逻辑，不是数据 | 无需标记 |

**诚实结论**：文献只覆盖前两类。状态内核的准确描述是**「分布有据、动力学是设定、约束是硬逻辑」**，
不吹「医学级仿真」。承认这一点比假装全科学可信。

## 五、两条修正（v0 → v0.1，判据④⑤）

### 修正一 · 长度右端点那条：从「禁止」改成「可存在＋必须标极少见＋不得作默认值」

旧口径「禁止出现十八厘米」偏严，且偏得很典型：**它把「极罕见」当成了「不存在」**。
真实情况是那个长度约在正态右尾千分之几的位置（`rarity` 字段给的是 **1/600**，
换算依据约 1/609，见 `fb.length.threshold_rare_length_marker`）。

- `existence`: 可存在
- `rarity`: `1/600` ← 判据④ 断言这个字符串
- `not_default`: `true` ← 判据④ 断言这个布尔
- `advisoryRequired`: 必须显式标注极少见

**为什么这么改**：禁令修不好方向性偏差，只会把存在性个案逼成禁写；
真正管用的是「写它就必须同时写它有多罕见」，外加抽样口径本身不往那儿去。

### 修正二 · 直径那条：把「抽样上限」和「存在性上限」拆成两件事

旧口径 `直径上限 5.0` 过松——它的 z 值约 +3.7，随机抽样里约 1/8,600，
**等于把一个万分之一的位置当天花板，而且还允许写**。
但直接收紧到「不存在」也是错的：**拍摄与上传是强选择事件**，
「随机抽一个男性超过它的概率」和「被拍到的那批里它的比例」不是同一个问题。

于是拆成三条阈值＋一条带（数值都在 json，本处只点名）：

| id | 管什么 | 口径 |
|---|---|---|
| `fb.diameter.threshold_default_sampling_cap` | **默认抽样上限** | 判据⑤ 断言它就等于报告修正后的那个端点 |
| `fb.diameter.threshold_advisory_uncommon` | **提示线一** | 到达即必须写「少见、需适应」 |
| `fb.diameter.threshold_extreme_upper` | **提示线二**（旧上限位置） | 不禁用，越过默认上限到这里必须附「极罕见＋硬度不足」 |
| `fb.diameter.band_extreme_case` | 两条上限之间的带 | `notBanned: true` ＋ `advisoryRequired` |

**为什么硬度必须跟着来**：这不是设定，是可以推的——白膜能承受的张力有上限，
同样上限下半径越大、可维持内压越低，而硬度主要由内压决定。所以**大是有代价的**，
`fb.girth_diameter.erectile.hardCouplingReference` 记了方向与出处，
**系数与公式不在本表**（派工单 §三：状态机与判定归 658／660／655）。

## 八、与 649 资料包的引用契约（判据⑥）

`facts.json` 是**唯一真源**。649 的片——尤其是 `computable: stats` 那一类（尺寸／时长／频率）——
**只存 `factRef`，不许回填任何数值、区间端点或分位读数**。可引用值：`anchors[].id`、
`anchors[].bands[].id`、`anchors[].thresholds[].id`、`fiction.items[].id`。

规矩出处：裁定记录 2026-11-15「stats 只能给区间：区间＋来源，源里没统计就不给」。

现实状态（不含糊）：649 现有包**还没有 stats 片**（无 `computable` 列、片类只有
method／observation／example／preference／fiction）。所以本轮是**契约先行**：
建 stats 片时按本契约填 `factRef`。判据⑥ 的实测读数（含把数值回填进片里的负例）在交付报告 §三。

另外：`739` 的「夸大必须同时带稀有度与来源 id」这条，稀有度与 id 都从本表取——
`thresholds[].rarity` 给稀有度，`thresholds[].id`／`anchors[].id` 给来源 id。

## 九、下游取数契约（660／658／669）

1. **只经取值口读**，业务码不许写分布字面量。660 现行实现 `FactsFromMd` 是全仓唯一允许出现字面量的地方，
   `FactsFromJson` 接上后换实现、调用点一行不动。
2. **要值就抽样或取分位**，别问「默认值是多少」。`samplingRule.pointReadAllowed` 是 `false`；
   问「这个角色的常态长度」⇒ 从 `fb.length.erectile` 的分布按分位取档，不要问本表要一个数。
3. **表外拒收**：`extrapolationAllowed` 是 `false`。缺 P90 就去补来源（G-5），别插值了事。
4. **阈值是边界，不是取值**：`thresholds[].bound` 用来决定「要不要附提示语」，不用来生成角色。
5. **方向性约束优先于数值**：勒压 ⇒ 温度不升反降、无刺激 ⇒ 充血不升、M 与 E 是两个变量——
   这三条写成耦合符号，别写成提示词里的「禁止」。数值不来自语言，权重里那条因果图就没有入口。
6. **体验不在本表**：主观感受归角色设定与用户偏好，叙事写法归写法令。引擎给的是可观测量之间的约束关系，
   把体验塞进引擎等于让机器编感受。
7. **虚构要标出来**：`fiction.items[]` 三项在包内 `kind=fiction`、`reality=fictional`，
   引擎打 `fantasy` 标记、不做守恒校验；**诚实标注必须保留**，虚构是设定，不是错误。
