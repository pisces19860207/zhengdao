## 2. 规格必须覆盖的内容

### 2.1 认脸（判定算法，含优先级与冲突裁决）

- 输入是文件路径（`.json` / `.png`）。
- **先看 PNG 签名** `89 50 4E 47 0D 0A 1A 0A` ⇒ 酒馆角色卡；再在 `tEXt` 里找 `chara`（v2）/ `ccv3`（v3）。
- 再看 JSON 顶层键：`world_book`（网络平台）/ `_comment`+`world_book`（网络平台模板）/ `entries` 数组（Tavo）/ `entries` 字典（酒馆原生）/ `{kind,id,name,updatedAt,data}`（Tavo 角色卡）/ `{kind,id,name,updatedAt,entries}`（Tavo 正则/预设）。
- **必须写清**：两条规则同时成立时谁赢（例如顶层既有 `world_book` 又有 `entries`）、都判不出时输出什么（「未知」＋看过的键名清单，不许猜）。
- 网络平台**省略默认值**的坑要写进算法：缺 `value_type`/`value_configs` ⇒ 补 `0`/`[]`，**不得**因此判成别的格式或缺字段。

### 2.2 体检（字段级 + 语义级，逐条给判定算法）

- 字段级：`probability` 1–100、`depth` 0–20、`key_region`/`value_region` 1–7、`match_type` ∈ {2,3}、酒馆 `entries` 键为整数且 `key` 是**数组**、Tavo 元素要带 `keywords`/`content`。**缺字段与取值越界要分开报**。
- 语义级三件，每条都要给出**算法与边界**：
  1. **关键词过宽**：风月 `key` 的 `_or_` 分支里出现单字关键词 ⇒ 判「积分刺客」风险。要写清：如何切分 `_or_`/`_and_`/`@wb@`、什么算「单字」（一个汉字？一个字母？数字？）、大小写与空格如何处理。
  2. **永不触发**：给定系统文本（提示词/前置词/后置词），逐条判 A（命中系统文本）/ B（只被详细介绍 HTML 命中，HTML 没给 ⇒ 标「未判」）/ C（永不触发，**必须报出且计数非零**）。要写清：命中判定是子串还是词边界、`key_region` 位掩码怎么参与（`key_region=3` 只扫系统文本与玩家输入，AI 正文不算）、没给系统文本时**不许**报 0。
  3. **同名/同键冲突**：同一本书里 `key` 完全相同且 `key_region` 重叠 ⇒ 提示可能互相压制。要写清「重叠」怎么算。

### 2.3 酒馆 PNG 规格（按字节写清）

- PNG 结构：签名 / `IHDR` / 若干块 / `IDAT` / `IEND`；`tEXt` 块布局 = 长度(4B 大端) + `"tEXt"` + 关键字 + `\0` + 文本 + CRC(4B)。
- 关键字 `chara`（v2 规范）/ `ccv3`（v3）；文本 = **base64(JSON)**。
- `tEXt` 只能放 Latin-1 文本；base64 是 ASCII ⇒ 可行；要写明**不许**用 iTXt/zTXt 的理由或例外。
- CRC = CRC-32（PNG 多项式 0xEDB88320，初值 0xFFFFFFFF，最终异或 0xFFFFFFFF），覆盖「类型 + 数据」，**不含长度**。
- 插入位置：`IHDR` 之后、`IDAT` 之前（或按规范允许位置），并说明为什么。
- **往返判定**：导出再读回，JSON **逐字相同**（键顺序、中文、转义都不许变）——这条要写成不可放宽的验收。
- **不覆盖**：目标已存在 ⇒ 拒绝；源图不许改一个字节。

### 2.4 合成夹具设计（**绝对不许收录真实卡**）

- 为 F1–F11 每条判据设计**合成输入**：JSON 用代码里能拼出来的最小样例（写明字段与期望结论），PNG 用字节数组现拼。
- 明确写出：仓库是**公开的**，真实卡／世界书（尤其成人内容）**一个字节都不许进仓库或测试资源**；样本目录只读。
