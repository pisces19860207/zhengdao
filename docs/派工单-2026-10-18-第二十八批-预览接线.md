## 0. 一句话

A 段把槽造出来了，但**没有任何调用方**（这是我立的规矩：不许为测试造死接口）。B 段就是接线：
**抱朴把「一条回复的正文」渲成卡片 → 放预览槽 → 用玄览打开 `http://127.0.0.1:<port>/p/<uuid>` 给你看。**

## 1. 规格

1. **入口只有一个**：抱朴抽屉里加一项 **「预览这条回复」**（desc：「把最近一条回复渲成一张卡片，在玄览里看」），
   点了才渲 —— **不许**自动渲、不许后台预渲（省电、省内存，也避免槽被占满）。
2. **渲什么**：把**最近一条 assistant 文本回复**转成一个极简 HTML（标题＋正文，`.md` 里的代码块按 `<pre>` 包一下就行），
   **不引 markdown 库、不做样式框架**；CSS 内联，深色/浅色用 `prefers-color-scheme` 各一套。
3. **怎么渲**：`PreviewSlots.put(html)` ⇒ 拿 url ⇒ `BrowserHolder.pendingUrl = url; requestBrowserTab()`（与第二十一批「搜索进玄览」同一条路），
   然后切到玄览页。
4. **槽满/起不来要说话**：`put` 返回失败（端口全占）⇒ 一行提示「预览服务起不来（端口被占）」，**不许静默什么都不发生**。
5. **清理**：离开抱朴页不主动清槽（槽有 LRU 上限 8），但设置页给一行「清空预览缓存」（调 `remove/clear`）。

## 3. 判据

| 编号 | 判据 |
| --- | --- |
| R1 | 渲染是**纯函数**：`replyToHtml(markdown: String, title: String): String`，JVM 直接测（不碰 Android） |
| R2 | HTML 里**必须转义** `<`/`>`/`&`（回复里可能有 `<script>`，渲成卡片时不许变成可执行内容） |
| R3 | 入口只在抽屉，点了才渲（源码级：不在 `LaunchedEffect`/`init` 里调 put） |
| R4 | 打开走 `BrowserHolder.pendingUrl` ＋ `requestBrowserTab()`，**不许**自己 new 一个 WebView |
| R5 | `put` 失败有提示（不必测端口占满，但要有失败分支且走同一句文案） |
| R6 | 中英 strings 对称 |
