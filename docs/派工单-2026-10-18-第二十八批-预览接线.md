## 1. 规格

1. **入口只有一个**：抱朴抽屉里加一项 **「预览这条回复」**（desc：「把最近一条回复渲成一张卡片，在玄览里看」），
   点了才渲 —— **不许**自动渲、不许后台预渲（省电、省内存，也避免槽被占满）。
2. **渲什么**：把**最近一条 assistant 文本回复**转成一个极简 HTML（标题＋正文，`.md` 里的代码块按 `<pre>` 包一下就行），
   **不引 markdown 库、不做样式框架**；CSS 内联，深色/浅色用 `prefers-color-scheme` 各一套。
3. **怎么渲**：`PreviewSlots.put(html)` ⇒ 拿 url ⇒ `BrowserHolder.pendingUrl = url; requestBrowserTab()`（与第二十一批「搜索进玄览」同一条路），
   然后切到玄览页。
4. **槽满/起不来要说话**：`put` 返回失败（端口全占）⇒ 一行提示「预览服务起不来（端口被占）」，**不许静默什么都不发生**。
5. **清理**：离开抱朴页不主动清槽（槽有 LRU 上限 8），但设置页给一行「清空预览缓存」（调 `remove/clear`）。

## 5.6 追加二（2026-10-18 19:1x · **先做这个，CI 红等它**）· J5 两个用例端口顺序敏感

CI（Linux）红在这两条，**是测试自己对端口状态有隐式依赖，不是产品缺陷**：

```
PreviewServerTest > J5_第一个候选被占_自动顺延到下一个 FAILED   java.net.BindException at :238
PreviewServerTest > J5_全部候选被占_put 明确失败并说清原因 FAILED java.net.BindException at :262
```

**真因**：两个用例先自己 `bind` 住 7000–7900 来模拟「被占」，且为了判据严格设了 `reuseAddress = false`。
JUnit 方法顺序按**方法名哈希**排，Windows 与 Linux 的 JVM 排序不一致 ⇒ 在 Linux 上这俩排在「起过监听」的用例之后，
**上一个用例遗留的监听/TIME_WAIT 还粘在 7000**，Linux 语义下没有 SO_REUSEADDR 就许不许复用 ⇒ 自己的 `bind` 先炸。

**修法（只许动测试，一行产品代码都不许碰）**：

1. 两个 J5 用例开头：`PreviewServer.stop()` 之后加 `Thread.sleep(150)`（或等 accept 线程退出的有界轮询）；
2. 占位改成**有界重试** `bindBlocker(port)`：最多 3 秒、每 150ms 一次、`reuseAddress = false` **保持不变**
   （**绝不许**为过测试把它改成 true —— 那等于把「被占就顺延」这条判据废掉）；
3. 3 秒还占不上 ⇒ `Assume.assumeNoException("环境：候选端口被外部占用", e)` **跳过**，
   并在报告里写「本次 J5 未实测」，**不许**当绿过；
4. 顺带核一遍 `PreviewServer.start()` 的候选循环：每个候选的 `BindException` 必须被吞掉继续下一个（L93-106 现看着对，核完在报告里确认）。

**白名单**：`app/src/test/java/com/example/zhengdao/preview/PreviewServerTest.kt` **一个文件**。
**红线**：`preview/**` 产品代码零改动（`git diff --stat <基线> HEAD -- preview/` 必须为空）。

**判据**：J7.1 两条 J5 在你本机连跑三遍全绿；J7.2 产品代码零改动；J7.3 若走到 Assume 分支，报告必须写明。
