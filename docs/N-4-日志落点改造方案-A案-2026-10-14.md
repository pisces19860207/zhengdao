# N-4 方案（A 案）· 运行日志落点改造 ＋ 显式导出

> 决策：用户 **2026-10-14** 逐字「那就按你推荐的 A 做吧」。
> 现状依据：第 2 期只读审计 + 我的三方核验（N-4 = 真）。
> 落码位置：并入**第⑩批 A**；**须压在⑨刀合并之后**（本方案会改中英 `strings.xml`，与⑨刀底栏改版撞车）。

## 一、问题（现状）

- `app/src/main/java/com/example/zhengdao/rootfs/RunLog.kt:91-98` 的 `dir(context)` **公共区优先**：`Store.logsDir(context)` = `/storage/emulated/0/Download/证道/logs/`（`terminal/Store.kt:57` `PUBLIC_ROOT`、`:109` `logsDir`）。→ 任何拿到「所有文件访问权限」的 App 都能读。
- 写进去的内容含**私有绝对路径**（`oc/OcManager.kt:777-780`）与**异常原文**（`OcManager.kt:488/592/627/766/835`、`terminal/SessionManager.kt:303/306`、`TerminalActivity.kt:1229/1231/1505`）。不含口令（核实过：口令只进 `Authorization: Basic` 头与 `serve.log`）。
- `RunLog.kt:230-235` 还把**每一行**镜像进 logcat（`#5（2026-10-09）` 的刻意设计），release 也一样。

## 二、改法（A 案）

1. **落点改私有**：`RunLog.dir()` 改为 `File(context.filesDir, "logs")`（`cacheDir/runlog` 兜底语义取消，统一到私有 `filesDir`）。
   - 旧公共区日志**不删不动**（`migrateLegacy` 只做「公共区老日志 → 私有」的**复制**，且不改写原文件）；公共区从此不再新增日志行。
2. **落盘前脱敏**：`RunLog.log()` 里新增私有 `redact(line)`，规则：
   - `/data/user/0/<包名>`、`/data/data/<包名>`、`context.filesDir` 绝对路径 → `<私有目录>`；
   - `Authorization: Basic …`、`server password…`、`passwd=…`、`token=…` → `****`；
   - **保留** `/storage/emulated/0/Download/证道/…`（用户可见路径，不属隐私，且排障要它）。
3. **logcat 镜像改 debug-only**：`RunLog.kt:235` 的 `Log.i("zhengdao", line)` 包进 `if (BuildConfig.DEBUG)`；注释同步改成新口径。「拿不到 context 时进 logcat」那条（`:219-224`）保留（失败可见优先）。
4. **设置页新增「导出日志」**（`ui/SettingsHelpActivity.kt` 日志区，与「只留最近 3 份」并列）：
   - 串接 `filesDir/logs/` 下的日志（最新一份 + 归档）→ 过一次 `redact()` → 经 `ACTION_CREATE_DOCUMENT`（SAF）由**用户选保存位置**并命名 `证道日志-<yyyyMMdd-HHmm>.txt`；
   - 中英 strings 各加 4 键（标题/说明/成功/失败），键数必须仍相等（现 759/759）；
   - 文案口径：「日志存在应用私有目录；需要给开发者看时点这里导出」。
5. **门禁**（新增 `app/src/test/java/com/example/zhengdao/rootfs/RunLogPrivacyGateTest.kt`）：
   - `RunLog.kt` 源码里**不得**再出现 `Store.logsDir(`（防回退真门禁，别只 grep 文本就算数：断言 `dir()` 的实际返回路径在 `filesDir` 下）；
   - `redact()` 行为：`/data/user/0/com.example.zhengdao/files/home/.hermes/config.json` → 输出不含 `com.example.zhengdao`；
   - `redact()` 保留公共区路径与时间戳；
   - logcat 镜像被 `BuildConfig.DEBUG` 守卫（行为断言：release 变体下不写入 logcat）。

## 三、代价与取舍（写清，别事后当 bug）

- **插数据线直接捞日志这条便利没了** —— 这是刻意的：取证改走「设置页显式导出」，用户按下导出＝一次知情动作。
- 代价：**App 起不来就导不出来**。缓解：① debug 构建仍镜像 logcat；② `KeepaliveArchive` 抓 logcat 的机制不变（下一轮启动把死前那几十行存成 `logcat-boot-*.txt`，仍落私有区）；③ 帮助页文案说明「起不来时用带日志的 debug 包」。
- 公共区里**已有的**历史日志保持可读（不迁移、不改写、不删除）。

## 四、验收

- `:app:compileDebugKotlin` ＋ 全量串行单测（`--offline --max-workers=1 --rerun-tasks`）读数；
- `git diff --stat`（不许顺手改无关文件）；
- 真机：① 帮助页导出一次日志，用文件管理器能看到导出文件、内容无 `/data/user/0/...`；② `Download/证道/logs/` 不再新增文件（旧文件仍在）；③ release 包下 `adb logcat | grep zhengdao` 无业务行（可选手验）。
