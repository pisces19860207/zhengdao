## 1. 先纠一个口径（写进规格，别写成假话）

**「合到一起」不能让模型碰不到。** 模型今天根本改不了代码 —— 它没有「写 APK 源码并重编译」那条工具通路。
能通到内核的只有两条：① 提案机制（写人设/技能文件）② 配置面（工作区/阈值/通道，现在只有用户能改）。

所以抽 Kernel 的真实价值是四条，报告里只许这么写：

1. **单一真相源**：一处改，所有引用跟着变，不会再出现两套口径；
2. **改动可见**：谁动内核，`git diff` 一眼看到（从"翻五个文件"降到"看一个文件"）；
3. **门禁可扫**：`KernelGuardTest` 能断言「这些常量不许在别处重复定义、不许被赋值、每条只有一处来源」；
4. **可挂规则**：以后写「这属于内核，模型不可提案」有地方挂。

**安全性仍来自「模型没有那条通路」**，不是来自模块划分 —— 这句话要原样留在 `docs/KERNEL.md` 顶部。

## 3. 怎么抽（最小改动，不做大重构）

1. 新建 `app/src/main/java/com/example/zhengdao/baopu/kernel/BaopuKernel.kt`：
   - `object BaopuKernel`，里面按七组分 `object`（`Data`／`Exec`／`Tools`／`Auth`／`Budget`／`Egress`／`Gate`）；
   - 只放**常量与纯判据**，不放 I/O、不放 Compose、不依赖 Android 类（能进 JVM 单测）。
2. `RunRules.kt` **保留旧名做委托**（`const val MAX_STEPS = BaopuKernel.Budget.MAX_STEPS`），
   这样 `agent/**` 里几十处引用**一行都不用改**，风险最小；下一批再清理。
3. `ContextAssembler.kt`：`COMPRESS_THRESHOLD`／`NEVER_COMPRESS` 改成引用 Kernel（**行为零变化**）。
4. `GuardPipeline`／`RootfsDelta`：只把「边界判据的数值」挪进 Kernel，判定逻辑**原地不动**。
5. `WebViewEngine.allowedSchemes`：**等 qoder 刀 4 合入后再并**（浏览器线正在改），本批先不碰；
   在 `BaopuKernel.Egress` 里先留一个 `TODO(刀4后并入)` 的注释位，**不许**造第二份常量。
6. 配置留痕：用户改**内核项**（工作区、压缩阈值、通道）时写一条 `RunLog`，格式
   `[kernel] 工作区改为 <路径>（原 <旧路径>）`。设置页在这几项下面加一行小字「改这里会记日志」。

## 4. 判据

| 编号 | 判据 |
| --- | --- |
| K1 | `BaopuKernel` 里**不含** Android import、不含 I/O（源码级断言：无 `android.`／`java.io.`） |
| K2 | 七组各有一个 `object`，且每组至少一个常量或纯判据（不许空壳） |
| K3 | **唯一来源**：`MAX_STEPS` 等常量在 `app/src/main` 里只允许两处出现 —— Kernel 定义处 ＋ `RunRules` 的委托处；别处再写字面量就红 |
| K4 | `RunRules.MAX_STEPS == BaopuKernel.Budget.MAX_STEPS`（值相等，且是 `const val` 委托，JVM 可直接断言） |
| K5 | 行为零变化：全量单测读数与基线一致（用例数不变），`assembleDebug` 通过 |
| K6 | 内核项变更能留痕：改工作区 ⇒ `RunLog` 里出现 `[kernel]` 一行（用一个假 prefs 单测验） |
