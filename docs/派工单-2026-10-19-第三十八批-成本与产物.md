## 0. 用户原话与边界

- 成本：「显示『本轮累计』吧，点击后展开就是每轮可以吗？现在的成本可见是怎么排的就按那个展开显示就好了。」
- 产物：「产物为什么不能在APP里直接点击查看啊？就是那些json、txt什么的，其他的文本就不用了，那些太重了。」

⇒ **口径**：
1. 跑马灯里只放**本轮累计**一行；点开才是**每一步**的明细（排布照 `run_log` 那套：步骤／入／出／耗时）。
2. 产物**只做文本**（json／txt／md／csv／yml／yaml／log／html），**在 App 内只读查看**；图片、二进制、超大文件一律不做（太重）。
3. 两件都**不许**引入存储权限、不许把文件内容写进数据库、不许改引擎预算与守卫。

## 1. A 段 · 成本可见（跑马灯一条 ＋ 点开看每步）

**现状（先读懂，别重复造轮子）**：`RunEngine` 每步都拿到 `LlmUsage`（入／出／思考／缓存命中／未命中），已由 `persistUsage` 写进 `run_log` 五列；**但壳层拿不到它**——所以界面上一个数都没有。

**做法**：

1. 引擎加一个**回调出口**（形制照 `AskUserTool.sink`）：
   ```kotlin
   /** 每步拿到 usage 就回调一次；null 表示这一步真没读到（不是 0）。 */
   var onUsage: ((LlmUsage) -> Unit)? = null
   ```
   在 `persistUsage` 里调它（**同一处**，别另起一条链）。**注意线程**：`persistUsage` 在引擎线程上跑，回调里只许改 `mutableStateOf`（Compose 状态可以跨线程写），不许读盘、不许起线程。
2. 控制器（`BaopuChatController`）持有本轮累计：
   - 新开一轮时清零（放在用户发消息那一段，和 `introspectionNote = null` 同一处节奏）；
   - 收到 `onUsage` 时累加（入／出／命中缓存），并更新一个 `mutableStateOf`；
   - 另存一个**每步列表**（步骤号、入、出、耗时 ms）给展开用。
3. 顶栏跑马灯（`BaopuScreen` 的 `noticeItems`，与「这次学到／已压缩」同一个 `BaopuNoticeTicker`）**加一条**：
   - `label` = strings 的「本轮用量」；
   - `body` = 累计一行 ＋ 每步明细（每步一行），**沿用 `run_log` 明细的列**：`第 3 步 · 入 12.3k · 出 2.1k · 4.2s`。
   - **没有读数就不加这一条**（`usage` 全空 ⇒ 不出，别显示 0）；
   - 数字格式：`< 1000` 直接原样，`≥ 1000` 用 `k` 保留一位（如 `8.0k`）；不要用 `String.format` 依赖区域设置（全仓有门禁）——用整数运算自己拼。
4. 字符串中英各加（键名自定但要成对）：`本轮用量`／`入`／`出`／`缓存命中`／`第 %1$d 步`。

## 2. B 段 · 产物可点开（只文本、App 内只读）

**做法**：

1. **收集**：引擎里已经有「这一轮真写成功过哪些路径」的现成机制（`VerifyTargets.pathsOf(...)` 与 `verifyTouched`，收尾闸在用）。复用它，**只收**：
   - 写/改/搬（目标）成功的路径；
   - 扩展名白名单：`json txt md csv yml yaml log html`（大小写不敏感）；
   - 读一下前 8 KB：**含 `\u0000`（二进制）或文件 > 512 KB ⇒ 不收**；
   - 同一路径去重，保持写入顺序；每轮最多列 8 个（超了只列前 8 个并标「还有 N 个」）。
2. **展示**：回复气泡下方（或这条回复的步数汇总行下面）一行「产物」小片：`文件名的最后一段`；点一片 ⇒ 弹 **只读查看器**：
   - 等宽字体、可竖滚、可横向滚动（长行不折断可选，最简单是不折行＋横向滚）；
   - 顶部显示相对路径与字节数；底部「复制全文」与「关闭」；
   - **上限**：最多读 200 KB / 3000 行，超出就截断并在顶部写明「只显示前 N 行（共 M 行）」——**不许把 5 MB 的 txt 一次读进 Compose**；
   - 查看器**只读**：源码里不许出现 `writeText`/`delete()`/`renameTo`（用源码级用例钉住）。
3. **不做**：图片/PDF/docx 预览、外部 App 打开（Intent）、分享。用户明确「其他的太重了」。

## 3. 判据

| 编号 | 判据 |
|---|---|
| A1 | 有 usage 的一轮 ⇒ 跑马灯多一条「本轮用量」，累计=各步之和（用例：三步 100/200/300 ⇒ 600） |
| A2 | 点开详情 ⇒ 每步一行，行数与步数一致，步骤号从 1 连续 |
| A3 | usage 全空（null）⇒ **不出**这一条（不是显示 0） |
| A4 | 新开一轮 ⇒ 累计与每步列表清空（不跨轮累计） |
| A5 | 数字格式纯函数可测：`999`→`999`，`1000`→`1.0k`，`12345`→`12.3k`；不依赖区域设置 |
| A6 | 回调里没有读盘/起线程（源码级：`onUsage` 的实现体里没有 `File(`/`Thread(`/`Dispatchers`） |
| B1 | 白名单扩展名 ⇒ 出现在产物行；非白名单（jpg/zip/bin）⇒ 不出现 |
| B2 | 512 KB 以上、或前 8 KB 含 NUL ⇒ 不收（用例各一条） |
| B3 | 点开 ⇒ 只读查看器显示与盘上逐字一致（含中文、换行、制表符） |
| B4 | 超过 200 KB / 3000 行 ⇒ 截断且有「只显示前 N 行」 |
| B5 | 同路径写两次 ⇒ 产物行只出现一次；最多 8 个 |
| B6 | 查看器无写盘路径（源码级） |

## 4. 负例（每条都要真跑出红）

1. 累计改成「只取最后一步」 ⇒ A1 红。

4. 去掉大小上限 ⇒ B2 红。
5. 查看器里加一行写盘 ⇒ B6 红。
