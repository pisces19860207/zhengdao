## 六条红线（人话）

- **R1 不可逆动作未确认**——没拿到人的批准，删/清/覆盖这类回不了头的动作不许执行；高风险「仅这一次」永不免卡；原件区硬拒；授权单压不住红线。
- **R2 越权外发**——没有租约/批准，一个字节都不许出门。探针、拉卡、委派、看图请求都算外发；契约层外发恒否，想开先改类型。
- **R3 停机后仍执行**——叫停/停机/授权过期之后，动作不许再走：停机落盘重启不复活、模型不许自解、挂起的确认随停作废。
- **R4 回滚失败静默**——回滚没成不许装成了：要么成功并留痕，要么独立失败态喊人来，不许「回滚失败」被吞成「保留现状」。
- **R5 账本被直改**——账只许追加；手写终态、删行、伪造 kind 都造不出事实（重放不认），账与账对不上必须报。
- **R6 假动作（报告了没做）**——说「做了」就得有真凭据：缺证据⇒FAIL，账行删了⇒FAIL，数字谎报⇒FAIL，模型不许自证合格。

## 判据（与派工单四条一一对应）

1. **底账三字段不许空**：实现落点 / 负例测试 / 状态三格有一格空 ⇒ 聚合入口红，点名行号与字段（解析器自检）。
2. **聚合入口总数 = 底账条数**：脚本把本表逐行解析，总数 / 有负例 / 缺负例三个数全打印；表格里任何一行不许被静默丢掉，编号重复也红。
3. **变异让一条负例失败 ⇒ 聚合入口红并点名**：哪个用例红、属于哪条红线，一行点名写清（另发 CI annotation）。
4. **幂等**：连跑两次结果一致；脚本不写任何文件，重复执行不改变判定。
