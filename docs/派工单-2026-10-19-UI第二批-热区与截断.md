## 0. 背景与证据（基线 `81573a13`）

2026-10-19 UI/UX 评审把「点不中的小热区」和「卡片静默截断」列为两批实改。设计稿里的数字有两处要按本次复核修正：

- 抽屉「＋」不是 20dp：`BaopuDrawer.kt:320` 是 `.size(28.dp).clickable{}.padding(4.dp)`，clickable 在 padding 外 ⇒ **实际热区 28dp**。
- 「朗读」按钮写死 `height(28.dp)`（`BaopuMessageList.kt:601`），但 Material3 `TextButton` 可能自带 `minimumInteractiveComponentSize` 把触摸扩到 48dp ⇒ **先确认，再决定改不改**，不要为了凑数把本来合格的改成 48。

## 1. 热区（目标：可点目标 ≥48×48dp，视觉尺寸不变）

| 位置 | 现状（基线） | 改法 |
|---|---|---|
| 附件缩略图「×」 | `BaopuComposer.kt:318` `ATTACH_REMOVE_DP = 28.dp`；`:376` Box 直接 clickable | 外面套 48dp 命中容器（内部 28dp 圆保持原样）；若 48dp 会盖住缩略图点击区，停下来报告取舍，不许静默缩小 |
| 抽屉「⊕ 在此工作区干活」 | `BaopuDrawer.kt:171` `.size(24.dp)` 直接 clickable | 外套 48dp 命中盒；**不要**把整行改成「在此干活」——行的点击语义是「切到这个工作区」，两者不能混 |
| 抽屉「＋ 选文件夹」 | `BaopuDrawer.kt:320` 实际热区 28dp | 外套 48dp 命中盒，视觉 `＋` 不变 |
| 顶栏跑马灯 | `BaopuNoticeTicker.kt:37` `TICKER_HEIGHT = 16.dp`，`Text.clickable` 只有 16dp 高 | 在顶栏那一行内把可点盒做到 **48dp 高**（文字视觉仍 16dp，滚动参数不动）；不得把顶栏撑高 |
| 消息「朗读」 | `BaopuMessageList.kt:601` `height(28.dp)` | **先确认** M3 最小触摸目标是否已把热区扩到 48dp：已达标 ⇒ 报告「不改」；确实只有 28dp ⇒ 改成 ≥48dp（视觉可仍 28dp） |

**纪律**：视觉尺寸、颜色、圆角、图标一个字不换；只扩大命中区。若某处 48dp 会与邻近动作重叠、导致误触，**停下来在报告里写清**，不要自己发明「整行可点」这类改语义的方案。

## 2. 静态截断（不许静默，必须显性计数 + 可展开）

| 位置 | 现状（基线） | 改法 |
|---|---|---|
| 记忆候选卡 | `BaopuMemoryCard.kt:39` / `:103` 两处 `take(3)`，超出无提示 | 仍显示 3 张，但加「还有 N 条」入口；点开看全量、再点收起（两个区块各自独立状态） |
| 技能提案卡 | `BaopuSkillCard.kt:98` 只显示正文「最后一行非空」；`proposals.forEach` 无上限 | 每条提案显示**标题（技能名）＋可读摘要**，长内容可展开；列表超过 3 条折叠为「还有 N 条」 |
| 计划卡条目 | `BaopuPlanCard.kt:177` `maxLines = 1` + `Ellipsis`，无展开入口 | 条目至少两行或加「展开」入口；展开状态按条目记，不改变 done/doing/todo 的判据 |

- 计数文案：新增 **1 个键** `baopu_more_items`（中：「还有 %1$d 条」/ 英：「%1$d more」）；展开/收起复用现有 `common_expand_arrow` / `common_collapse_arrow`，不要新造第二套。
- 两个 strings 文件必须同步；不许顺手改别的文案。
