## 1. P1-7 · WebView 在组合期构造

**现状**：`BrowserScreen.kt:84` `val engine = remember { BrowserHolder.obtain(context) }` —— `obtain` 里会 `new WebView(app)`；项目自己在 `BrowserTabManager` 注释里记过「WebView 构造是本类唯一已知会间歇卡死（≥100s）的点」⇒ 在组合期做，首帧卡死/ANR 风险。

**改法（行为要求）**：
- **不得**在组合期直接 `BrowserHolder.obtain(...)`；改为在 `LaunchedEffect(Unit)` 里取（跑在主线程、但已过首帧），或用等价的「首帧后再构造」方式。
- 构造完成前显示一个轻量占位（进度/空态均可），**不要白屏**；构造完成后界面要能正常重组出第一个标签与地址栏。
- 注意 `BrowserTabManager.tabs()` / `activeTab()` 的可观察性：如果延迟 `obtain` 后首建标签不会触发重组，必须显式处理（例如把 tabs/active 纳入可观察状态或构造后触发一次刷新），并在报告里写清怎么保证。
- 所有后续使用 `engine` 的地方（`DisposableEffect`、`AndroidView`、`tryNavigate` 等）都要处理「构造前为 null」；不许 `!!` 硬取。

**测试**：源码门禁——`BrowserHolder.obtain(` 不得出现在 `remember {` 里，必须出现在 `LaunchedEffect`（或等价首帧后入口）；负例改回 `remember` ⇒ 红。真机可选：冷启动进玄览，首帧不卡、标签正常出现。

## 2. P1-8 · `pendingUrl` 只消费一次

**现状**：`BrowserHolder.pendingUrl` 是普通 `@Volatile var`（`:44`）；`BrowserScreen.kt:142` 用 `LaunchedEffect(Unit)` 只消费一次。⇒ 已经停在玄览 Tab 时，终端点链接写入 `pendingUrl`，组合不会重跑这个 effect，链接整条丢失。

**改法（行为要求）**：
- 让 `pendingUrl` 变成**可观察状态**（例如 `mutableStateOf<String?>(null)` 或等价的 state/flow），写入后已组合的 `BrowserScreen` 能收到；
- 消费改成 keyed effect（如 `LaunchedEffect(BrowserHolder.pendingUrl)`）或 collect；消费后置 null 防重复加载；
- 终端/外部写入方（`TerminalActivity`、`BaopuPreview` 等）的调用签名若无需改就保持不动；不要新造第二套「待打开 URL」通道。
- 注意 effect 在置 null 后会再跑一次（空操作），不要因此重复 `openExternal`。

**测试**：源码门禁——`pendingUrl` 必须是可观察状态（不得再是裸 `@Volatile var`），`BrowserScreen` 的消费 effect 不得再以 `Unit` 为 key；负例改回 `LaunchedEffect(Unit)`/裸 var ⇒ 红。真机可选：停在玄览时在终端点链接 ⇒ 玄览立刻开新标签；连点两条不丢。
