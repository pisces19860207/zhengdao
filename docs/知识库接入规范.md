# 知识库接入规范

> **适用**：证道终端的 agent（Claude Code / Hermes / AGY CLI 等）
> **版本**：2026-10-09　**状态**：草案
> **一句话**：给 agent 挂私人资料，**不需要数据库、不需要改 APP** —— 一个目录 + 一份 `AGENTS.md` 就够了。

---

## 一、为什么是这个方案

证道终端里的 agent 是**命令行程序**，读文件是它们的本能。所以「知识库」的正确形态不是数据库，而是**文件**。

而「文件」要能被**不同厂商的 agent** 都认出来，靠的是一个已经成型的事实标准：

**`AGENTS.md`** —— 一个纯 Markdown 文件，放在目录里，agent 会自己读。

截至 2026-10，这个标准的实际情况：

| 项 | 事实 |
|---|---|
| 托管方 | Agentic AI Foundation（Linux Foundation） |
| 采用规模 | 60,000+ 开源仓库 |
| 原生支持的工具 | 25+ 个：Codex、Cursor、GitHub Copilot、Gemini CLI、Jules、Aider、Zed、Warp、goose、opencode、Factory、Devin/Windsurf、JetBrains Junie、Amp、RooCode、Kilo Code、Antigravity、**Hermes** 等 |
| 命名 | 无 frontmatter、无必填字段，就是 Markdown |
| 发现规则 | **就近优先**：子目录里的 `AGENTS.md` 覆盖父目录的；agent 导航进某个目录时会**渐进发现**它 |

**唯一的例外是 Claude Code** —— 它读 `CLAUDE.md` 而不是 `AGENTS.md`。解决办法见第六节。

> **结论**：写 `AGENTS.md` 覆盖绝大多数 agent；Claude Code 用一行软链兜底。这是**投入最小、覆盖面最大**的方案。

---

## 二、放哪里

agent 运行在 proot Debian 环境里，能看到这几个目录：

| guest 路径 | 手机真实路径 | 说明 |
|---|---|---|
| `/workspace` | `Download/证道`（或你自定义的工作区） | ⭐ **agent 产出区，推荐把知识库放这里** |
| `/sdcard` | 手机共享存储 | 全量可读，适合放只读资料 |
| `/root` | 证道私有目录 | agent 自己的配置（`~/.claude`、`~/.hermes` 等） |
| `/opt/zhengdao` | `Download/证道` | 证道公共区（脚本／缓存／日志） |

**推荐位置**：

```
手机存储 / Download / 证道 / 知识库 /
```

这样 agent 在 `/workspace/知识库/` 就能看到它。

---

## 三、知识库长什么样

```
知识库/
├── AGENTS.md          ← 必需。说明书：这里是什么、有什么、怎么用
├── 00-总目录.md        ← 建议。给人看的索引（按需求查的路线表）
└── ……你的内容          ← Markdown 最佳（纯文本的 .txt 也行）
```

**大知识库要分层**：每一层放各自的 `AGENTS.md`。agent 走到哪一层，就读到那一层的说明 —— 这比塞一份巨大的总说明更好，也省 token。

---

## 四、`AGENTS.md` 写什么

它是"**给 agent 的说明书**"，不是给人看的介绍。写**可执行的规则**，不写口号。

参考模板：

```markdown
# AGENTS.md —— 我的知识库

> 如果你是被指派来用这份知识库的 agent，先读完本文件再动手。

## 这是什么
（一两句：内容是什么、干什么用的、面向谁）

## 目录地图
（列出目录结构，每个目录一句话说明里面是什么）

## 怎么检索
- 按关键词搜：grep -rn "关键词" .
- 每个条目以 `## N. 标题` 分节

## 内容边界（别搞错）
（哪些内容在这里、哪些不在；不在的要去哪找）

## 红线
（绝不要做的事：不要改内容、不要外传、不要放进代码仓库…）
```

**要点**：
- 先写"这是什么"和"目录地图" —— 这两节价值最高
- 一定要有"**红线**"一节 —— 负向约束能防住最贵的错误
- 保持更新 —— 过时的 `AGENTS.md` 会**主动误导**每个读它的 agent

---

## 五、agent 怎么找到它

`AGENTS.md` 的发现规则是**就近 + 渐进**：

- agent 在某个目录**启动** → 读该目录（及 git 仓库向上）的 `AGENTS.md`
- agent **中途导航进**某目录 → 渐进发现该目录的 `AGENTS.md`，当场注入

所以：

| 情况 | 结果 |
|---|---|
| agent 的工作目录就在知识库里面 | ✅ 自动读到 |
| agent 只是**路过**读了知识库里一个文件 | ✅ 渐进发现（Hermes、Codex 等支持） |
| agent 的工作目录在别处，且从不进知识库 | ⚠️ **读不到** —— 需要"指路" |

**证道的实际情况**：终端 agent 的起始目录是 `/root`，**不在** `/workspace` 里。所以要让它知道知识库存在，有两个办法：

1. **对话里说一句**（最简单）：
   > 工作区有份知识库在 `/workspace/知识库/`，先读它的 `AGENTS.md`
2. **写进 agent 的启动规则**（一劳永逸）：把同样的意思写进该 agent 的原生上下文文件 —— 路径见下节

## 六、各 agent 认哪个文件（2026-10 调研）

| agent | 原生上下文文件 | 是否原生读 `AGENTS.md` |
|---|---|---|
| **Hermes** | `.hermes.md` / `HERMES.md`（最高优先级）、`AGENTS.md`、`CLAUDE.md`、`.cursorrules` | ✅ 原生（且支持**渐进式子目录发现**） |
| **Codex**（OpenAI） | `AGENTS.md` | ✅ 原生（参考实现） |
| **Gemini CLI / Jules**（Google） | `AGENTS.md` / `GEMINI.md` | ✅ 原生 |
| **Antigravity**（Google，即 AGY） | `AGENTS.md` | ✅ 原生 |
| **Cursor** | `AGENTS.md`、`.cursor/rules/*.mdc` | ✅ 原生 |
| **GitHub Copilot** | `AGENTS.md`、`.github/copilot-instructions.md` | ✅ 原生 |
| **opencode** | `AGENTS.md` | ✅ 原生 |
| **Aider / Zed / Warp / goose / Amp / Devin / Junie / RooCode / Kilo Code** | `AGENTS.md` | ✅ 原生 |
| **Claude Code** | `CLAUDE.md` | ❌ **不原生读** |

### Claude Code 的兜底办法（二选一）

```bash
# 办法一：软链（推荐）
ln -s AGENTS.md CLAUDE.md

# 办法二：写一个瘦 CLAUDE.md，让它 import 进去
echo '@AGENTS.md' > CLAUDE.md
```

> ⚠️ Claude Code 在只有 `AGENTS.md`、没有 `CLAUDE.md` 时，会**静默地**一条项目指令都不加载 —— 所以这个兜底必须做。

## 七、格式要求（踩过的坑）

| 要求 | 原因 |
|---|---|
| 纯 Markdown / UTF-8 | 所有 agent 都能读 |
| **不要用数据库**（SQLite 等） | agent 读文件是本能，读数据库要先装工具 —— 多一道坎 |
| 单个 `AGENTS.md` **不超过约 150 行** | 太长 agent 会略读，重点被淹没 |
| 大库分层，每层放自己的 `AGENTS.md` | 就近优先，按需加载，省 token |
| 不要放二进制/图片当主体 | agent 读不了 |

---

## 八、隐私

- 知识库是**你的私人数据**，放在 `/workspace` 或 `/sdcard` —— 那是**设备本地**，不会上传到任何地方
- 证道仓库里**只发布代码**，用户数据不在其中
- ⚠️ 唯一要守的：**不要**把私人知识库放进 APP 的代码目录（`assets/` 等），那样才会跟着仓库公开

---

## 九、现状说明（2026-10-09）

证道目前**已经**在给「太极」页签的 OpenCode 写一份 `AGENTS.md`（内容是一份"身份 + 目录地图 + 能力边界"的说明）。
**终端的 agent 目前还没有**收到类似文件 —— 也就是说，终端侧的"指路"需要你自己做（按第五节的两种办法之一），或者等证道后续支持。

## 附：一份最小可用的例子

```bash
# 1. 建目录
mkdir -p "/sdcard/Download/证道/知识库"

# 2. 放内容（你自己的资料）
cp -r /path/to/your/notes/* "/sdcard/Download/证道/知识库/"

# 3. 写说明书
cat > "/sdcard/Download/证道/知识库/AGENTS.md" << 'EOF'
# AGENTS.md —— 我的知识库

这是一个私人资料库。需要用的时候，先读本文件。

## 目录地图
- `01-设定/` —— 世界观与角色设定
- `02-规则/` —— 可复用的规则与模板
- `00-总目录.md` —— 按需求查的路线表

## 怎么用
- 按需抽取，不要整库加载
- 关键词搜索：grep -rn "关键词" .

## 红线
- 不要修改本库内容
- 不要外传
EOF

# 4. Claude Code 兜底
ln -s AGENTS.md "/sdcard/Download/证道/知识库/CLAUDE.md"
```
