## 1. 桥（浏览器桥）的裁决 —— 你问的那件事

**先给结论：不该撤，但它现在的包装是过时的，要改。**

**事实（我核过代码与台账）**：

- 桥 = App 内一个 HTTP 端点，`127.0.0.1:14080`，口令进 `Authorization: Basic browser:<token>`，**默认关**、只在设置页显式打开；
- 11 条命令：`status / snapshot / navigate / click / type / scroll / newTab / activeTab / closeTab / screenshot / execJS`；
- **抱朴根本不走它**——`git grep "BridgePolicy|14080"` 在 `baopu/**` 里 **0 命中**；抱朴的浏览器能力是**进程内**直调 `BrowserHolder`／`BrowserCommands`；
- 台账第 117 行：桥做过真机 E2E（401/403/405/413、scheme 白名单、口令打码、端口不撞 14000 全过），当时认定「**终端的眼睛**成立」；
- 设置页文案现在写着「抱朴（内置 OpenCode）不接这条桥」——**这句已经过时**（抱朴早就不是 OpenCode 了）。

**所以**：桥的用户不是抱朴，是**终端里那些可安装的 agent**（hermes / opencode 之类）。它们跑在 guest 里、够不到 App 的进程内 API，**桥是它们唯一的眼睛**。撤了＝终端 agent 瞎。

**但它有两处真缺陷，正好削弱「眼睛」**（已在接线审计里）：
1. `snapshot` 的 `selector` 参数被**静默忽略**（`BrowserCommands.kt:268` 自认预留）⇒ agent 以为只看了一块，实际拿整页；
2. `screenshot` 返回 1×1 占位 PNG ＋ 给的是 rootfs 侧路径（挂刀 4）。

**建议处置（三件，不打乱任何线）**：
- ① **文案改对**：把「抱朴不接这条桥」改成「抱朴用它自己的进程内通道；这条桥是给终端里的 agent 的」；设置页把「能做什么 / 不能做什么」写清（现在已经有风险提示，补一句能力清单）。
- ② `selector` 修掉（实现或从 Schema 删掉并回「暂不支持」）——归 **D 批**。
- ③ 加一个「一键自检」：设置页给一条可复制的 `curl -s -u browser:<token> http://127.0.0.1:14080/bridge/v1/status`，点一下就知道通不通。**这条最省用户力气**。

> 如果你就是想撤：可以，但必须同时决定「终端 agent 还要不要看网页」。要 → 不能撤；不要 → 撤，并把相关文档/文案一起清掉。**别留半截。**
