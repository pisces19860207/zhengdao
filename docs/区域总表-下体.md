## 一、三层各管什么（规范节）

| 层 | 数量 | 机读落点 | 谁在读它 | 不许用它做什么 |
| --- | --- | --- | --- | --- |
| 区 zone | 13 | `anatomy-zones.json` 的 `zone_id` | 731 状态机、660 形体、790 方位可达 | 不当呈现分组用 |
| 组 group | 7 | `SubzoneGroup`（`SubzoneIds.kt`） | 人读与呈现分组、775 表内自洽校验 | 不进任何对象级判定 |
| 子区 subzone | 14 | `SubzoneId.code` | 727 撞击落点、804 覆盖位图、867 组合表、875 外观 | 不单独当判定单位 |

**一句话规则：判定用 `zoneId`，呈现用 `group`，施力／敏感／质地用子区 `code`——三者永不互相顶替。**

三条补充口径（都是踩过的坑）：

1. **三层不是树，是三种投影。** 组不装在区里，区也不装在组里：龟头组横跨 `glans` 与 `corona`
   两个区；反过来说 `shaft` 一个区落三个子区。按「父—子」去理解迟早写出错的遍历。
2. **组不参与对象级判定。** 731／790／660 都不读 `group`。775 的「龟头比柱身光滑、色档更深」确实按组比，
   但那是**静态表的自洽校验**（同一张表里别自相矛盾），不是给某个角色下判定。
3. **空表 ≠ 没有子区。** `SubzoneId.ofZone(x)` 返回空表，意思是「775 没给这个区定子区」。
   13 区里 5 个区没有子区（`raphe`／`scrotum`／`testis`／`cord`／`mons`），
   不是它们「没有内部结构」，也不是「下游可以随手补一个」。

## 二、corona 的标准答案（887 定死，不许只留一个字段）

```text
zoneId = corona    ← 13 区里单列的一区（龟头冠自成一区）
group  = 龟头       ← 解剖归类（冠部属于龟头）
code   = corona    ← 14 个子区之一
```

为什么两条都得留：

- **只留 `zoneId=glans`**（把冠并进龟头）＝改写 13 区。连坐三处：731 的区级账、660 的区实例、
  804 的「冠与沟永不合并」。这是改口径，不是改注释。
- **只留 `group`**（把冠降成纯呈现用语）＝ 727／867 按 code 取「冠部」时找不到判定单位，
  只能猜。
- **`code` 与 `zoneId` 恰好同名，是「一区一子区」的自然结果**（`sulcus`／`frenulum`／`radix` 同理），
  不是把两层并成一层：`apex` 的 code 与 zoneId 就不同（`apex` / `glans`）。
  code 改名仍会打断 804／727／867 的引用，与 zone 无关。

## 五、两组「组」不是同一个东西（读代码前先看这段）

| 名字 | 在哪 | 取值 | 回答什么问题 |
| --- | --- | --- | --- |
| `SubzoneGroup`（**本页的组**） | `state/subzone/SubzoneIds.kt` | 龟头／冠状沟／系带／柱身／根部／尿道口／包皮 | 这块地方**解剖上属于谁** |
| `RegionGroup`（**804 的面组**） | `state/prepuce/PrepuceCoverage.kt` | 龟头／冠／沟／系带／尿道口／柱身 | 这张皮**盖住了哪个面** |

同名的坑：**corona 在 804 里是独立一组（冠），在本页里归龟头组**——两边都对，因为问的不是同一个问题。
804 必须把冠与沟分开，否则「退至冠后」这一档判不出来（804 判据⑤：不许出现「冠沟」组）；
本页要的是解剖归属，冠就是龟头的一部分。⇒ 读 `SubzoneRefs` 里「CORONA 组」那句话时，
指的是 **804 的 `RegionGroup`**，不是本页的 `group`。
