## 2. 规格（只做三条）

### 2.1 `EvalGateTest` 跳过时把话说清

`assumeTrue` 的消息里必须出现 **「未跑」** 二字，例如
`"未跑：缺 ZHENGDAO_EVAL_KEY —— 进化门禁本次未实测（这不是失败）"`。
理由：跳过在报告里只是个 `skipped` 计数，光看数字分不清「本来就没有 key」和「有人把门拆了」；
消息是唯一能留在测试报告里的证据。

### 2.2 新建 `tools/check-eval-baseline.py`（只读校验）

- 入参 `--base <commit>`；
- 用 `git show <base>:eval/cases.json` 与工作区的 `eval/cases.json` 比，再比 `eval/baseline.json`；
- **判红（退出码 1）**：
  1. **用例被删**（旧 id 集合里有、新集合里没有）；
  2. **用例总数变少**；
  3. **基线阈值被改松**（`passRate` 调低、`avgSteps` 调高、`cases` 调小、`passing` 名单变短）；
- **判绿（退出码 0）**：只加用例／阈值收紧／`recordedAt`、`note` 这类元数据变化；
- 输出**一行中文结论**（例：`✅ 评测基线未放松：10 → 11 例，passRate 1.0 → 1.0`）；
- **只读**：任何 `open(..., "w")`／`write_text`／`os.remove` 都不许出现（判据 E6）；
- 解析 JSON 用 `json` 模块，**不许按行 grep 统计**（本仓踩过：按行统计把「某条缺字段」误判成「格式错乱」）；
- 房型照抄 `tools/check-baseline-refresh.py`（`argparse` ＋ 调 `git` ＋ 一行结论 ＋ 退出码）。

### 2.3 接进 CI

`.github/workflows/ci.yml`：在 `testDebugUnitTest` **之前**加一步
`python3 tools/check-eval-baseline.py --base "$BASE"`（`BASE` 与 `check-baseline-refresh.py` 那步同一写法、同一个变量）。
**顺序写死**：校验必须排在跑测试之前，否则测试已经烧完分钟数才发现基线被改松。
