## 四、★ 为什么要切成两个文件（这是本次最重要的一步）

P2 方案第六节列了三处**本机无法验证**的点。项目纪律是"不确定就标不确定、禁止用推测把空白填满"，
所以做法是：**把能测的部分全部挤进纯函数，剩下的单独圈出来**。

| 层 | 文件 | 本机可测 | 覆盖 |
|---|---|---|---|
| 纯逻辑 | `KnowledgeBaseSummarizer.kt` | ✅ 22 例 | 提示词拼接、完成判定、JSON 解析、清单回写幂等、权限闸门、文案 |
| 落盘 | `KnowledgeBase.writeSummaries()` | ✅ 由上面覆盖 | 原子写、`.bak`、空内容拒绝 |
| 调用编排 | `KnowledgeBaseSummarizerRunner.kt` | ❌ **需真机** | HTTP、轮询、超时、会话清理 |

⇒ 真机出问题时，可以先确定**不是纯逻辑那一半的错**，排查范围直接减半。

## 五、⚠️ 真机验收清单（合并后请跑一遍）

### 5.1 先验那三个"未验证点"（约 10 分钟，**必须先做**）

| # | 验什么 | 怎么看 |
|---|---|---|
| 1 | **新会话有没有默认模型** | 点「重新整理」后看日志：若无 `资料库摘要：任务没发出去（HTTP 4xx/5xx）` ⇒ 没模型，需要在建会话后再 `POST /api/session/{id}/model` |
| 2 | **"答完了"判定要几轮** | 正常应是 2~3 轮轮询（约 3~5 秒）出结果。若总要等到 180s 超时 ⇒ 文本一直在变（比如流式 token 逐步追加），把 `SETTLE_ROUNDS` 调大 |
| 3 | **权限请求会不会挂死** | 看日志有没有 `资料库摘要：自动拒绝了一个权限请求`。若**一条都没有却超时** ⇒ 说明它卡在别处，需要把 `/api/permission/request` 的原始响应打出来 |

### 5.2 功能验收

- [ ] 太极**没开**时点「重新整理」⇒ 日志一行「太极没在运行」⇒ 清单照常生成，**不报错**
- [ ] 太极开着、`原始/` 放 3 个 txt ⇒ 点「重新整理」⇒ 约 5~10 秒后设置页状态变成
      「已挂载 · 3 个文件（**含摘要**）」
- [ ] 打开 `整理/00-目录.md` ⇒ 有 `## 文件摘要` 一节，3 个文件都有摘要，
      **且仍在 `## 给 AI 的提示（重要）` 之前**
- [ ] ⭐ 摘要**内容对不对**：随便挑一个文件核对，摘要说的和文件里讲的是同一件事
      （如果摘要写的是**用户自己的提问**，那就是 E-062 那个 bug 复发了，请立刻反馈）
- [ ] ⭐ `原始/` 里所有文件 **sha256 逐字节不变**
- [ ] 太极的**历史会话列表里没有多出临时会话**（跑完会 `DELETE`）
- [ ] 连点两次「重新整理」⇒ 第二次日志「上一轮还在跑」，不会起两个任务
- [ ] 中途杀掉 App ⇒ 重开设置页**不会永远显示「整理中」**（`BUSY_STALE_MS` 5 分钟自愈）
- [ ] 终端里问 agent「我的资料库里有什么」⇒ 能答对（P0 遗留项，顺便验）

### 5.3 断网 / 异常

- [ ] 断网点「重新整理」⇒ 摘要静默失败（只有日志），**清单照旧可用**
- [ ] 太极开着但模型故意报错 ⇒ 同上，状态回到「已挂载 · N 个文件」（不含摘要）

## 六、已知限制（如实列出，不是遗漏）

| 限制 | 说明 |
|---|---|
| **`.docx` / `.pdf` 不参与摘要** | 只能给文件名级提示。正文提取属 **P3**（`TEXT_EXT` 白名单控制） |
| **一次最多 40 个文件** | `MAX_FILES_PER_RUN`。超出的下一轮再来（不是漏，是有意的） |
| **每个文件只喂 1200 字** | `READ_BYTES_PER_FILE`。防长文档把上下文撑爆 |
| **不做自动/定时跑** | 只挂在「重新整理」上。自动化等免费模型的不限流情况确认后再谈（P2 方案第八节） |
| **临时会话会短暂出现在太极列表** | 跑完即 `DELETE`；若进程被杀可能残留一条（下次手动删即可） |
| **摘要可能不准** | 已在清单里写明「仅供快速定位，**细节请读原文件**」 |

**代码层（零风险）**：

```bash
git revert <P2 的提交号>
```

**运行时（不用改代码）**：

`原始/` 与用户数据不受任何影响。
