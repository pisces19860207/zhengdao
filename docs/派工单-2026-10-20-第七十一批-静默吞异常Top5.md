## 1. 五条（逐条：失败时要有声音）

### ① 技能审计行写失败被忽略
- 位置：`baopu/SkillStore.kt:196`（`SkillAudit.record(...)` 返回值）/ `baopu/SkillAudit.kt:39`。
- 现状：`record` 返回 false 被忽略；KDoc 说「由调用方 log」，调用方没做。
- 改法：`if (!SkillAudit.record(...)) RunLog.log("技能审计行写入失败：op=… target=…")`；不要因写审计失败而回滚技能写盘（保持现语义）。

### ② `MemoryStore.write` 失败只是静默 false
- 位置：`baopu/MemoryStore.kt:166`。
- 现状：写失败返回 false，调用方（记住这条）没亮出来，用户以为记住了。
- 改法：至少在本方法内 `RunLog.log("记忆写入失败：id=… reason=…")`；不打印记忆正文。调用方 UI 提示**不在本单**（controller 在飞），报告里标「待下一批」。

### ③ `Store.adoptDir` 源目录不可读静默放弃
- 位置：`terminal/Store.kt:163`。
- 现状：`?: return 0`，迁移静默放弃，旧数据滞留无提示。
- 改法：`return 0` 前补 `RunLog.log("迁移源不可读，跳过（src=…）")`；返回值/行为不变。

### ④ `BrowserCommands` 主线程 latch 超时静默 null
- 位置：`bridge/BrowserCommands.kt:185`（同文件 `:145` 同款已有日志）。
- 现状：超时返回 null，无日志，两处漂移。
- 改法：照 `:145` 补一条 RunLog（含 command/耗时），返回 null 语义不变。

### ⑤ `KnowledgeBase.copyRawInto` 单文件失败静默 continue
- 位置：`terminal/KnowledgeBase.kt:264`。
- 现状：单文件复制失败静默 continue，调用方只看到成功数，不知道漏了失败数。
- 改法：统计 `failed`，结束时 `RunLog.log("资料复制：成功 N，失败 M（首个失败：…）")`；若现有返回类型可带失败数，就返回 `Pair/Result` 并同步调用方与测试；**不改成功项的复制行为**。
