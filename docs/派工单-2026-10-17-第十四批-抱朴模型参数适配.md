## 0. 一句话

抱朴的「工具箱」和「协议」都够用，拖后腿的是**给模型分配的舞台还按小模型量**：窗口回退到 128k、OpenAI 分支根本不发 `max_tokens`、模型侧思考一个字都不处理。本单只改这三个参数层的东西，不动任何工具逻辑、不动确认制、不动续跑。

## 2. 范围（三段，按顺序做）

### A 段 · 窗口与输出上限（P0，收益最高）

1. `ContextAssembler.kt:112` 的 `DEFAULT_WINDOW_TOKENS` 改 `1_048_576`；`:158` 的回退逻辑保留（元数据优先）。
2. `Provider.kt` 加一个 **DeepSeek 官方预设**（照 `OPENAI_COMPAT` 的结构）：`baseUrl = https://api.deepseek.com/v1`、`model = deepseek-flash`、`contextWindow = 1_048_576`、`maxOutput = 393_216`。**只加预设，不改任何现有预设的值。**
3. `LlmClient.kt` 请求体补 `max_tokens`：取 `provider.maxOutput`；OpenAI 分支 `null` 回落 `8192`，Anthropic 分支 `null` 回落 `4096`（替换写死的常量引用）。

### B 段 · 用量与缓存（可追溯）

4. 请求体加 `stream_options: {"include_usage": true}`（**仅 OpenAI 兼容分支**）。
5. SSE 层把最后的 `usage` 解析出来，落进 `run_log`：`prompt_tokens` / `completion_tokens` / `reasoning_tokens` / `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`。列不存在就做幂等迁移（`ALTER TABLE ... ADD COLUMN`，参照 `BaopuDb` 现有 v3 迁移写法）。
6. `stream_options` 或 `usage` 缺失时**不许报错**：记 `null`，界面照常。

### C 段 · 思考深度（四档）

7. `Provider.kt` 加 `reasoningEffort: String? = null`（或等价枚举）；DeepSeek 预设默认 `high`。
8. 请求体按预设发 `reasoning_effort`（**只发这个字段名**，禁发 `effort` / `max_reasoning_effort`）。
9. 设置页加「思考深度」一栏，四档：关（`none`）／低（`low`）／高（`high`，默认）／最高（`max`）；副标题写明「机械活选低、复杂整理选最高；关掉省 token 但复杂任务会变笨」。
10. SSE 接 `delta.reasoning_content`：**只累计字数**（供设置页显示「本轮思考约 N 字」），**正文不许混进 `content`，也不许进对话历史**。

## 5. 负例（交付前自己造红，再改回绿）
