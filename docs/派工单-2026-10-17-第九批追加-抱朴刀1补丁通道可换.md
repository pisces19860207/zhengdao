## 1. 要交什么（四件事，不许加戏）

### 1.1 `provider` 从硬编码挪到可改的地方

最小实现，二选一，**都不引新依赖、不建新表、不动 `baopu.db` 表结构**：

- **(a) 设置页里加一段「抱朴通道」**：从 `Providers.all()` 里选一个 + 填 API Key，存进既有的设置存储，`BaopuRuntime.provider()` 读它；
- **(b) 抱朴页里加一颗「换通道」小按钮**：弹 bottom sheet，列出 `Providers.all()` 三项 + 自定义 `baseUrl`，选完即生效。

落哪个由你判断并说明理由。**硬约束三条**：

1. `RunEngine` / `BaopuChatController` 的调用点不许改（`BaopuRuntime.provider()` 仍是唯一入口）；
2. 默认值仍是 `Providers.BUILTIN_FREE`（第一次装起来就有个能点的默认）；
3. API Key **不进日志、不进库、不进崩溃上报**（`run_log` 里只许出现通道 id）。

### 1.2 失败要说人话，并且能降级

1. 通道调用失败（403 / 429 / 超时 / 空回包）时，把**服务端原文前 300 字**写进 `run_log.err`——现在这一列在真机里是空的，我拿不到第一手错因，这一件是硬要求。
2. UI 上给一句人话 + 一颗「换通道重试」。
3. 连续失败达到 `CHANNEL_BREAK_THRESHOLD`（已存在，接上即可）⇒ 标记该通道不可用，**自动尝试下一个已配置且有 Key 的通道**；一个都没有 ⇒ 走 `ask_user`（照设计三档降级的口径，不许抛异常）。

### 1.3 不许为了过判据改判据

- `Providers` 的默认值、通道列表、错误号，一律不许为了「让蓝总管那边好过」而改。
- 免费通道不通这件事**不要藏**：它就是当前真实状态，UI 该说「这个通道不可用，换一个」。

### 1.4 红线照旧，一条都不许碰

`AndroidManifest.xml`、`app/build.gradle.kts`、`build.gradle.kts`、`settings.gradle.kts`、`gradle/libs.versions.toml`、`res/**`（含 `values*/strings.xml`）——全部零改动。若确需新增文案，**只许加 `baopu_*` 新键**，不许改既有键的值。
