## 一、P3 要解决什么

P0 的清单、P2 的摘要，对 **`.docx` / `.pdf`** 都是"知道有这个文件，但不知道里面写了什么"
（施工图第 336 行原话：`清单里列出；摘要环节标"需转换"；读的任务交给 agent`）。

**P3 就是把这个"需转换"从"推给 agent"改成"App 自己干"** —— 用户不该为了用资料库去装 pandoc。

---

## 二、★ 为什么拆成 P3a / P3b（这是本次最重要的判断）

`docx` 与 `pdf` 看起来是"同一件事的两个格式"，实际上**难度差一个数量级**：

| | `.docx` | `.pdf` |
|---|---|---|
| 本质 | **一个 zip**，正文在 `word/document.xml`（结构化 XML） | **字形画在坐标上**的指令流（不是"文字"） |
| 能不能零依赖 | ✅ **能** —— JDK 自带 `java.util.zip` 就够 | ❌ 不能 —— 必须有 PDF 解析库 |
| APK 代价 | **0** | 引入 PDFBox-Android，**体积明显增加** |
| 抽取质量 | 稳定（就是 XML 文本） | 看 PDF 怎么生成的，**经常抽出一堆乱码/断行** |
| 扫描版（图片） | 不存在这个问题（docx 里文字就是文字） | ❌ **任何库都救不了**，要 OCR —— 量级完全不同 |
| 本机可验证 | ✅ **可以**（纯文件解析，见第四节） | ⚠️ 抽取质量要在真机上用真实 PDF 试 |

⇒ **结论：`docx` 现在就做（P3a）；`pdf` 单独立项（P3b），且建议先明确"扫描版不做"。**

## 三、P3a（`.docx`）· 已实现

### 落点（只有两个文件，且都不碰核心）

| 文件 | 改动 |
|---|---|
| `terminal/DocxTextExtractor.kt` | **新增**：纯逻辑，`ByteArray → String`，**零第三方依赖** |
| `terminal/KnowledgeBaseSummarizerRunner.kt` | `readHead()` 多一个分支：`.docx` 走抽取 |

### 铁律落点（一条都不能破）

| 铁律 | 怎么守的 |
|---|---|
| **原件不动** | 抽取**只读** `.docx` 字节，从不写回；产物不落盘（P3a 不出正文文件，只喂给摘要） |
| **写入者唯一** | 没有任何新写入路径 —— 摘要仍由 `KnowledgeBase.writeSummaries()` 落 `整理/` |
| **原子写** | 同上，复用 P2 的落盘 |
| **尊重用户删除** | 无关（不建目录） |

> 📌 **为什么 P3a 不把正文存成文件**：多一份正文副本 = 多一处要维护、要清理、
> 可能和原件不同步的东西。当前需求（让摘要与 agent 看懂）**只要把正文喂进上下文**就够。
> 将来若发现 agent 反复要全文，再考虑落 `整理/正文/`（那是另一个决定，不顺手做）。

### 实现要点（每条都对应一个会出错的地方）

1. **只解 `word/document.xml`** —— zip 里还有 `word/media/*`（图片常几 MB）。
   全解 = 白白读一堆图。**真机实测：3.1 MB 的 docx（含 3 MB 图片）9 ms 抽完。**
2. **标签名精确匹配，不用前缀** —— `w:tab` / `w:tbl` / `w:tc` / `w:tblPr` **全以 `w:t` 开头**。
   用 `startsWith("w:t")` 会把表格结构当正文取出来（正文混进一堆标签）。
   *已写成回归用例 `表格结构不能被当成正文取出来`。*
3. **手写扫描，不用 DOM** —— `document.xml` 动辄几 MB，DOM 会建整棵对象树（手机内存吃不消）。
4. **空白收敛** —— 段落之间留一个空行（Word 里本来就该分开），段内多空格压成一个。
5. **三层容错都不抛异常**：不是 zip / 没有 document.xml / XML 结构怪异 ⇒ 返回**空串**
   （不是 null），调用方据此退回"只给文件名"。
6. **大小上限** `MAX_DOCX_BYTES = 40 MB` + 条目解压上限 32 MB（防 zip 炸弹）。

### ⚠️ 明确不做（如实列出）

- **旧版 `.doc`（97-2003 二进制格式）** —— 不是 zip，解不了。`canHandle()` 明确返回 false。
- **`.docx` 里的图片 / 批注 / 修订痕迹** —— 只取 `<w:t>` 正文文字。
- **公式（OMML）/ 文本框（drawing）** —— 不在 `<w:t>` 里，会丢。

## 四、P3a 的验证（**这次能在本机测全**）

### 4.1 单测：14 例，全绿

| 类别 | 覆盖 |
|---|---|
| 基本提取 | 段落断行、多 run 拼接、制表/强制换行、空文档 |
| 实体 | `&amp;` 等 5 个具名实体 + 十进制/十六进制数字实体 + **认不出的实体原样保留**（不吞字） |
| ★ 回归 | 表格结构不被当正文、带属性的 `<w:t>` 能取到字 |
| 空白 | 连续空行收敛 |
| 容错 | 空字节、非 zip（改了扩展名的文本）、zip 里没 document.xml —— **都不抛** |
| 性能 | 塞 8 MB 不可压缩图片当干扰项，仍只取正文 |
| 判定 | 扩展名大小写、`.doc`/`.pdf`/`.txt` 明确 false |

> 测试数据在**测试里现造**（用 `ZipOutputStream`），不往仓库塞二进制样本 ——
> 测的是**我们的解析逻辑**，不是某个 Word 版本的兼容性。

### 4.2 端到端：用真实结构的 docx 跑过一遍（**已做，临时探针**）

用 Python 造了一个与真实 Word 输出同构的 docx（含 `[Content_Types].xml`、`_rels/.rels`、
`word/document.xml`、3 MB 不可压缩假图片），实测输出：

```
耗时 9 ms，长度 73
证道资料库测试文档
这是第一段，含符号：a & b <c>.
这句被拆成两段run。
表格单元格A
表格单元格B
制表 后面
强制换行后
```

⇒ 段落、run 拼接、实体还原、表格单元格、制表、强制换行 **全对**；
**9 ms** 证明"只解 document.xml"确实没去碰那 3 MB 图片。（探针已删，临时文件已删。）

### 4.3 还差什么

- ⚠️ **真机上用"用户真实的 Word 文档"再试一次**（本次用的是同构样本，不是真 Word 导出的）。
  验证点：① 能抽出正文 ② 摘要里带上 docx 内容 ③ 原件 sha256 不变
- ⚠️ P2 那三条前置验证仍未跑（与 P3 无关，但都在同一条链上）

## 五、P3b（`.pdf`）· 方案（**代码未写**）

### 5.1 为什么现在不写

三个环节**本机验不了、且代价不明确**：

| # | 未定的事 | 影响 |
|---|---|---|
| 1 | **引哪个库、APK 变大多少** | PDFBox-Android（Apache-2.0）是主流选择，但**没在真机上量过体积增量** |
| 2 | **抽取质量** | 真实的用户 PDF（扫描件、双栏论文、表格）抽出来是什么样，**只能拿真实文件看** |
| 3 | **是不是"看起来能跑但其实没用"** | 若用户资料多是**扫描版 PDF**，任何库都抽不出文字 ⇒ 白做 |

⇒ 按项目纪律（`AGENTS.md`：「不确定就标不确定」「禁止用推测把空白填满」）**先不写**。

### 5.2 做之前必须先回答的一个问题

**「用户的 PDF 里，有多少是扫描版（图片）？」**

- 若是**文字版**为主 ⇒ PDFBox 值得引
- 若是**扫描版**为主 ⇒ **PDFBox 无用**，要做的是 OCR（量级完全不同，**建议明确不做**）

**建议**：真机上先跑一个只读探针，对用户现有的 PDF 做一次"能不能抽出文字"的统计，
**用数据决定要不要引库** —— 别先写代码再发现抽不出来。

### 5.3 若确定要做，步骤（草案）

```
1. app/build.gradle.kts 加 PDFBox-Android（先量 APK 体积增量，>2 MB 要重新权衡）
2. 新建 PdfTextExtractor.kt —— 与 DocxTextExtractor **同款接口**（ByteArray → String）
   ⚠️ 它**不是**纯函数（依赖第三方库），所以单测只能测"我们包的那层"（超时/异常/截断）
3. KnowledgeBaseSummarizerRunner.readHead() 多一个 .pdf 分支
4. 真机验收：抽 10 个真实 PDF，人工核对准确率；明确记下"扫描版抽不出"的占比
```

### 5.4 P3b 想清楚了但不打算做的

- **OCR**（扫描版）—— 另立项目，不在资料库范围内
- **PDF 内嵌图片提取** —— 同上
- **加密 PDF** —— 直接跳过（返回空串，退回只给文件名）
