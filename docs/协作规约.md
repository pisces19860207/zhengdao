## 3. 铁律（五条）

1. **先同步，再动手。** `python tools/zd.py preflight` 或手工
   `git fetch origin && git rev-list --left-right --count origin/main...HEAD`，
   **左侧必须是 0**。落后就别写代码 —— 你看到的代码不是大家看到的代码。
2. **先查重，再动手。** 用功能关键词搜全部历史，并读 `docs/FEATURE-LEDGER.md` §2（现役功能）
   与 §3（**已被拍板删除**）。**§3 里的东西不许复活**，除非用户再次明确要求。
3. **不在主工作树上直接改。** 一个 agent 一个分支 / 一个工作树（`git worktree add`），做完再合。
   *例外*：**集成本来就该在 main 上做** —— 允许在 main 上做 `merge --no-ff`（钩子会放行带 `MERGE_HEAD` 的合并提交）。
4. **不许 force push、不许改写 main 历史、不许删别人的分支或 tag。**
5. **推 `main` 前先想三秒。** 推 main 会触发一次完整的 CI（含 30–90 分钟的 RootFS 构建与发版），
   同一 ref 的新推送会 `cancel-in-progress` 掐死前一次 —— 别把别人正在等的构建掐了。

## 4. 标准流程（开工 → 交付）

```powershell
# 0) 环境（本机 ExecutionPolicy = Restricted，必须带 -ExecutionPolicy Bypass）
cd C:\Users\guoli\AndroidStudioProjects\zhengdao

# 1) 体检 + 查重（一条命令搞定，见 §5）
python tools\zd.py preflight -k <功能关键词> -p <你打算新增的文件>

# 2) 开自己的分支/工作树（不在 main 上改）
git switch -c feat/<功能名>            # 或
git worktree add ..\zhengdao-wt-<名> -b feat/<功能名> origin/main

# 3) 干活；中途随时 python tools\zd.py doctor

# 4) 提交（pre-commit 三道闸会自动跑；被拦 = 你做错了，不是钩子坏了）
git add <具体文件>                     # 别用 git add -A
git commit -F <UTF-8 文件>             # 中文提交信息走 -F，避免 PowerShell 编码坑

# 5) 集成：在「主工作树」上合并，不要在分支里 merge main
#    （合并进 main 的提交由钩子放行；集成本来就发生在 main 上）
git -C ..\zhengdao merge --no-ff feat/<功能名>

# 6) 推之前先在本地构建/跑测试，再推
git push origin main
```

**给派活的人（用户）**：可以让 agent 自己开分支干活；**合并进 main 与 push 建议由一个人（或一个 agent）统一做**，
否则两个 agent 同时推 main 必然互相掐断 CI。

## 5. 工具：统一入口 `tools/zd.py`

三个主体理论上可以用同一套工具（纯 Python 标准库，无需安装依赖；Windows 上 `python tools\zd.py …` 即可）。

| 命令 | 作用 | 退出码 |
|---|---|---|
| `python tools\zd.py preflight -k 关键词[,关键词] -p 路径 [--max-behind N] [--no-fetch]` | 五段：同步远端 → 工作树地图 → 我在哪/落后多少 → 关键词反查 → 复活检测 → 结论 | 0 可开工 / 1 有阻塞 / 2 不在仓库 |
| `python tools\zd.py doctor` | 13+ 项环境与仓库体检（钩子是否装且一致、keystore 指纹是否等于 build.yml 期望、build.yml 能否解析、关键文档是否齐全…） | 0 全好 / 1 有 ✗（`！` 只是提醒） |
| `python tools\zd.py install-hooks` | 把 `tools/hooks/*`（强制 LF、去 BOM）装到共享 `.git/hooks/` | 0 / 1 |
| `python tools\zd.py hooks-status` | 库里钩子 vs 已装钩子逐字节比对 | 0 一致 / 1 不一致或未装 |

历史脚本的去向：
- `tools/agent-preflight.ps1`、`tools/install-hooks.ps1` **保留，但只当 Windows 壳**，功能以 `zd.py` 为准。
- `tools/hooks/pre-commit` 是 POSIX sh（git 在 Windows 上也用自带的 sh 跑它），**不要**改成 ps1。
- `.py` 脚本一律 UTF-8 **无 BOM**；`.ps1` 里的中文**必须带 BOM**（Windows PowerShell 5.1 否则按 cp936 读成乱码）。

## 6. 边界：谁都不许做的事（除非用户当面拍板）

| 禁区 | 为什么 | 现在靠什么挡 |
|---|---|---|
| 在 `main` 上直接提交（合并提交除外） | 主工作树是集成用的，在途改动会被别人冲掉 | `pre-commit` 闸 1 |
| 直接改别人正在用的工作树目录 | 那是人家的私有区 | 约定 + 工作树地图（preflight 会列） |
| 复活 `docs/FEATURE-LEDGER.md` §3 里被拍板删掉的功能 | 实锤发生过（ApiKeyStore） | `pre-commit` 闸 3（复活检测）+ 台账 §3 |
| 把密钥/令牌/keystore 写进仓库 | 会永久留在历史里 | `.gitignore`（含 `.ci-debug.keystore`）+ 约定 |
| 删改 `docs/ERRATA.md` 里已发布的结论 | 那是"当时的事实"，删了就没人知道曾经错在哪 | 约定：**只能追加更正块**，不许回改原文 |
| force push / 改写 main 历史 / 删别人的分支或 tag | 会连带毁掉别人的在途工作和发布记录 | 约定（没有技术闸） |
| 为了"让 CI 变绿"而改业务代码 | 实锤发生过（删除被撤销） | 约定：**CI 变绿不是需求**，见 `docs/ERRATA.md` E-017 |

**例外唯一入口是用户**：用户明确说了，才做；并把"这是用户拍板的"写进提交信息。
