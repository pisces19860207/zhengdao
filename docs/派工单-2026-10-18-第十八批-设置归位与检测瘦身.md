## 2. 规格

### 2.1 A 段：抱朴设置归位

1. 新建抱朴自己的设置页（建议 `ui/baopu/BaopuSettingsScreen.kt`，用与抽屉一致的三组结构），把下列**整块搬进来**（含状态读取、保存、提示文案，不要只搬 UI）：
   - `baopu_tools_card`（工具开关；免费档的 `read`/`bash` 两个别名按 §2.1-4 处理）
   - `baopu_params_card`（模型参数）
   - `baopu_effort_card`（思考深度）
2. 抽屉「抱朴设置」**直达**这个新页；`SettingsDataActivity` 里**删掉这三块**。
3. 设置 Hub 与「终端与资料」页里**不再出现任何抱朴项**（判据里用 grep 断言 strings 不再被那两页引用）。
4. 免费档的 `read`／`bash` 两个兼容别名：**要么在两处都列出并可开关，要么只读展示「由通道决定」**——二选一，交付报告写明；**不许继续"模型看得见、用户管不着"**。
5. 「思考深度」旁边加一句提示：**只有 DeepSeek 通道会带上这个参数**（其余通道选了不生效）。

### 2.2 B 段：agent 检测瘦身（口径统一）

适用于**所有**「列出多个 agent/工具并逐个显示检测状态」的界面（首页 agent 卡、`SettingsEnvActivity` 的环境检测，两处都改）：

1. **只保留 Hermes**。其它 agent（Claude Code、AGY CLI、Codex 之类）**不再出现状态行**。
2. **检测通过的不显示**——列表里看不见"正常"的条目。
3. **缺失的合并成一行**，带一个**红叉 ✗**（文案例如「缺 2 项」）；点开才列出具体缺什么。
4. 全部正常 ⇒ **整个区块不出现**（不显示"一切正常"，也不留空壳）。
5. 检测本身（`HermesEnv` 那套）**不许删**，只改展示；判据要能造出「缺一项」的假状态。

### 2.3 C 段：定位文案（只改字，不动排版）

- 首页与「关于」页里，把抱朴描述成**自研 harness**（"自带 agent 运行时，不依赖外部 CLI"这类意思，具体文案你定，中英各一条）。
- **不许**改布局、不许加新卡片、不许动 tab 顺序。

### 2.4 D 段：操作卡归位（只挪位置，不重做视觉）

> 用户 2026-10-18 逐字：「**现在抱朴的对话方式的那个方向不是正常的方向和确认那个卡的位置太高了，不像是手持式设备的操作方式。**」
> 这是**结构问题不是审美问题**（拇指够不到 ＋ 对话区被挤扁），所以放在本批做；配色/字号/间距仍然一律不动。

**现状（证据）**：`ui/baopu/BaopuScreen.kt:257-330` —— 会话状态条、自省便签、待过目记忆卡、记忆候选卡、问人卡、**确认卡**、压缩条、资料库提示、提示词小框**全部排在消息列表之上**（列表在 `:331`，输入框在 `:343`）。

要求：
1. **凡是「要用户动手」的卡**（确认卡、问人卡、待过目记忆卡、记忆候选卡）移到**输入框正上方**，紧贴输入框；翻消息时**不跟着滚走**。
2. **纯展示类**（压缩条、资料库提示、提示词小框、自省便签）留在原处**或**并进会话状态条——二选一，交付报告写明选了哪个、为什么。
3. 同一时刻多张卡 ⇒ **只展开最上面一张**，其余折成「还有 N 张」一行，点开才展开（手机上不许一屏堆三张卡）。
4. **不许**改卡片内部结构/配色/字号；**不许**新增底部弹层或抽屉组件；只用现有 Compose 容器。
5. **键盘弹出时卡片仍须在输入框上方可见**（用现有 `imePadding`／`navigationBarsPadding` 组合，报告写明用哪个、实测哪一版）。

#### 2.4.1 对话区贴底跟随 ＋「回到最新」（用户 2026-10-18 补充口径）

> 用户逐字：「**对话方式最新的信息应该是在输入框的上方，之前那个小设计挺贴心的（就是回到最新那个）。**」

**现状（证据，两条都实锤）**：
- `ui/baopu/BaopuMessageList.kt:198` 只是一个 `LazyColumn`，**没有 `rememberLazyListState()`、没有滚底 `LaunchedEffect`、没有 `reverseLayout`** ⇒ 新消息/新步骤追加在视野之外，得自己往下划。
- 「⬇ 回到最新」的字符串**还在**（`res/values/strings.xml:497-498` `taiji_back_to_latest` / `taiji_back_to_latest_desc`），但**全仓零引用** —— 重建抱朴页时丢了。用户记得的「贴心小设计」就是它。

要求：
6. **贴底跟随**：进入会话、发出消息、收到新内容（含步骤行/计划卡）、操作卡出现 ⇒ **自动滚到最新**，最新内容始终紧贴输入框上方。
7. **「⬇ 回到最新」浮标**：只在「被手动划上去、且不在底部」时出现（有新内容时带一个小圆点或条数）；点一下回到底部并清标记。**复用 `taiji_back_to_latest` / `taiji_back_to_latest_desc`**，不许新建重复文案。
8. **上翻期间不许被自动滚动打断**：只有「已贴在底部」时才跟随；用户正往上读，就不许抢。
9. 跟随/浮标的判据一律走**纯函数**（与 `roundCollapsed` 同风格），JVM 可直测。

## 5. 负例（自己造红再改回绿）

1. 把「健康不显示」改回「全列」⇒ **J5 必红**。
2. 把缺失项拆成多行 ⇒ **J6 必红**。

4. 把确认卡挪回消息列表上方（恢复 D 段之前的顺序）⇒ **J8 必红**。
5. 把"上翻不抢"改成"永远跟随"⇒ **J11 必红**。
