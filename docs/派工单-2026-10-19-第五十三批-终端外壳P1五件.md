## 1. P1-4 · 环境未装时 `fallbackActive` 恒 false

**现状**：`TerminalActivity.kt:621` 的 attach 分支无条件 `fallbackActive = false`；`:712` 冷启动分支却用 `started.isFallback` 决定标题。`SessionManager.isFallback` 全仓只写不读。⇒ 环境未装、会话是系统 shell 时，重进终端顶栏显示「Debian 13.7」，启动命令打进系统 sh。

**改法**：attach 分支改成 `fallbackActive = SessionManager.isFallback`；标题同样按 `fallbackActive` 选「证道 — 系统 shell（环境未安装）」/「证道 - Debian 13.7」；`promptInstallOnce` / `injectPendingAutocmd` 等后续判断自然跟当前值走。

**测试**：源码门禁——attach 分支必须读 `SessionManager.isFallback`，标题必须按 `fallbackActive` 条件化；负例改回 `false` ⇒ 红。真机可选：未装环境进终端再退出重进，顶栏不得再写 Debian。

## 2. P1-5 · ResMonitor 按「下标」对齐 CPU 采样

**现状**：`terminal/ResMonitor.kt:70-81` 两次 `pids.mapNotNull { ticksOf(it) }` 得到两个 list，按 `take(min)` **下标对齐**；窗口内进程退出/新增会错配，末尾 `coerceAtLeast(0)` 把错配负值压成 0%。

**改法**：改成 **pid → ticks** 两侧 map，只对**交集 pid** 求差、逐 pid `coerceAtLeast(0)` 后求和；抽纯函数（例如 `internal fun cpuDelta(t0: Map<Int, Long>, t1: Map<Int, Long>): Long`）给 JVM 直测。RSS 仍按当前 pids 求和。

**测试**：map 顺序打乱、进程中途退出、pid 复用/负差三组；旧下标实现必须在这组用例上红。负例：把实现改回 `take(n)` ⇒ 红。

## 3. P1-6 · 系统文本菜单「粘贴」仍在主线程写 pty

**现状**：`TerminalActivity.kt:1400` `onPasteTextFromClipboard` 直接 `runCatching { SessionManager.write(text) }` 在主线程；同文件已有后台通道 `pasteText(text)`（`:1066`，走 `TerminalPasteWriter` + `pasteExecutor`）。`onPasteRequest`（`:247`）已改走它，这条漏了。

**改法**：`onPasteTextFromClipboard` 里 `if (text.isNotEmpty()) pasteText(text)`，删掉直接 `SessionManager.write`；失败提示沿用 `pasteText` 现有路径（后台回调回主线程）。

**测试**：源码门禁——该回调内不得出现 `SessionManager.write(`，必须调 `pasteText(`；负例改回直写 ⇒ 红。真机可选：贴一大段文本，界面不 ANR。

## 4. P1-9 · 热启动 `onNewIntent` 不读 `open_terminal`

**现状**：`MainActivity.onNewIntent`（`:374` 附近）只 `handleBaopuShortcut(intent)`；`open_terminal` 只在 `onCreate` 读（`:257`），再经 `ZhengdaoApp(startInTerminal=...)` 用 `LaunchedEffect` 拉起 `terminalIntent(...)`（`:450` 附近）。⇒ App 已在栈里时点「回到终端」通知无效。

**改法**：`onNewIntent` 里读 `intent.getBooleanExtra("open_terminal", false)`；为真则 `startActivity(terminalIntent(this, null, null))`（与冷启动那条 `LaunchedEffect` 同一入口、同一 flag，不新造第二条终端路由）。注意保留 `setIntent(intent)` 与 `handleBaopuShortcut(intent)`，不要重复收到旧 intent 时反复拉起。

**测试**：源码门禁——`onNewIntent` 必须含 `open_terminal` 与 `terminalIntent(`；负例只留 `handleBaopuShortcut` ⇒ 红。真机可选：App 在前台/后台点保活通知「回到终端」⇒ 终端被带到前台，返回栈正常。

## 5. P1-10 · 首页空态判据挂着已不存在的 `opencode`

**现状**：`ui/HomeScreen.kt:1121` `if (agents.none { it.id != "opencode" })`；`opencode` 已不在 agent 目录/列表中（只在 `AgentProcesses` / `CacheCleaner` 出现）⇒ 条件退化为「列表为空」，首帧空表就闪「清单拉不到」。

**改法**：改成 `if (agents.isEmpty())`（语义就是空态）；不新增兜底文案。若担心首帧闪，可按 §B 77 原审计只改判据；是否延迟显示另议。

**测试**：源码门禁——不得再出现 `it.id != "opencode"`；负例改回 ⇒ 红。可加一条纯函数/空表用例。
