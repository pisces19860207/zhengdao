## 0. 这一批要交什么（一句话）

让抱朴**拿到一个文件就知道它是哪套格式、能不能用、哪里会出事**，并且**能把卡导出成酒馆 PNG、再读回来**。

## 1. A 段 · 认脸（`CardFormat`）

**输入**：一个文件路径（`.json`／`.png`）。**输出**：判定 ＋ 依据 ＋ 置信度（高/低）＋（PNG 时）内嵌 JSON。

判定表（照底稿 §1，一条不多一条不少）：

| 特征 | 判定 |
|---|---|
| 顶层有 `world_book`（数组） | 风月AI |
| 顶层有 `_comment` ＋ `world_book` | 风月AI（平台下发的模板本体） |
| `entries` 是**数组**，元素含 `keywords` / `content` / `injectionPosition` | Tavo 世界书 |
| `entries` 是**字典**（键是数字 uid），元素含 `keysecondary` / `disable` / `order` | SillyTavern 原生 |
| 顶层是 `{kind,id,name,updatedAt,data}` | Tavo 角色卡 |
| 顶层是 `{kind,id,name,updatedAt,entries}` | Tavo 正则／预设 |
| 文件是 `.png`（PNG 签名 `89 50 4E 47 0D 0A 1A 0A`） | 酒馆角色卡；再找 `tEXt` 块 `chara`（v2）／`ccv3`（v3），base64 解出 JSON |

**必须处理的坑**：
1. **风月会省略 `value_type` / `value_configs`**（607 条里只有 94 条带）⇒ 解析时**自补默认** `value_type=0`、`value_configs=[]`，**不许**当成缺字段／判成别的格式。
2. 酒馆的开关是 **`disable`（反义）**；风月/Tavo 是 `enable`/`enabled`（正写）。别互相套。
3. `key_region` / `value_region` 是**风月独有**的位掩码：`key_region` 1 系统 / 2 用户 / 4 AI；`value_region` 1 提示词 / 2 前置词 / 4 后置词；可相加（1–7）。
4. 判不出来 ⇒ 返回「未知」＋ 你**看过的键**（前 20 个键名），不许猜一个最像的。

## 2. B 段 · 体检（`CardCheck`）

**输入**：认脸结果（＋调用方给的提示词/前置词/后置词文本，可缺省）。**输出**：问题清单（每条：级别／条号／字段／一句话＋证据）。

**字段级**（三套各自的口径）：
- `probability` 必须在 **1–100**；`depth` 在 **0–20**；`key_region`／`value_region` 在 **1–7**；
- 风月必填：`key`／`value`／`group`／`sort`／`enable`／`match_type`（`match_type` 只认 2=关键词 / 3=正则）；
- 酒馆：`entries` 的键必须是整数 uid、`key` 必须是**字符串数组**（不是一整个字符串）；
- Tavo：元素要带 `keywords`／`content`。

**语义级三件（这批的价值就在这里）**：
1. **关键词过宽**：风月 `key` 里 `_or_` 模式下出现**单字**关键词（如 `_or_水@wb@火`）⇒ 报「积分刺客」风险（平台会下架＋清积分）。
2. **永不触发**：给定了系统文本（提示词/前置词/后置词）时，逐条判「有没有能命中它的词」——
   - A 类：命中系统文本；
   - B 类：只被「详细介绍 HTML」命中（HTML 没给就标「未判」）；
   - C 类：**永不触发**。**C 类必须报出来，且计数要能显示**。
   机制提醒：`key_region=3`（系统+用户）只扫系统文本与玩家输入，**AI 自己写的正文不算**——这就是「前置词从直白改成文雅，74 条里 28 条整组失效」那件血案的成因。
3. **同名/同键冲突**：同一本书里 `key` 完全相同且 `key_region` 重叠 ⇒ 提示可能互相压制。

**空值纪律**：没给提示词就不许判「永不触发」（标「未判」），**不许把「没数据」写成「没问题」**。

## 3. C 段 · 酒馆 PNG 导出与读回（`CardPng`）

**导出**：内部卡（JSON 字符串）→ PNG。
- 找一张底图（调用方给；没给就用**内置 1×1 白图**），在 `IHDR` 之后插入 `tEXt` 块：关键字 `chara`，内容＝`base64(JSON)`；
- 每个块的 `CRC32` 必须按 `java.util.zip.CRC32` 算（**零依赖**，不许加库）；
- **绝不覆盖**源图：默认另存 `<原名>-card.png`，目标已存在就拒绝并说清。

**读回**：PNG → JSON。
- 只读 `tEXt` 里的 `chara`／`ccv3`，base64 解码；解不出/没有块 ⇒ 明确报「这不是酒馆角色卡」，不许回空 JSON 冒充成功。

**往返判据**：导出再读回，JSON **逐字相同**（键顺序也不许变——用原始字符串，不要 parse 再 dump）。

## 4. D 段 · 工具接线（两个，别多）

| 工具 | 权限 | 行为 |
|---|---|---|
| `card_inspect` | **FREE** | 参数 `path`；返回认脸结果＋体检清单（纯文本报告，20 行内）；只读 |
| `card_export` | **CONFIRM** | 参数 `path`（源 JSON）、可选 `base`（底图）；导出 PNG，回执给相对路径；不覆盖 |

- 两个工具的 `description` 都**不许报工具名**给用户看（人设已有「别报工具名」口径）；描述里说清「只读」「不覆盖」。
- 注册进 `ToolRegistry` 时按现有分组成员（读与找 / 写与改 里挑合适的），**工具总数会变**——`ToolRegistrySwitchTest` 里的计数要同步改。
