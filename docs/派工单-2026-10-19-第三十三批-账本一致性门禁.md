## 0. 为什么派这个（别跳）

这仓库的账是**文档账**：`docs/FEATURE-LEDGER.md`（台账）＋ `docs/ERRATA.md`（错误台账 `E-1xx`）＋ `docs/派工单-*.md`。
漂移已经真实发生过两次，都是我在对账时**人工扫**出来的：

1. 2026-10-16 对账：`§B-补` 表头的 🔴 与行内「已于 2026-10-11 修并销账」互相矛盾 —— **同一行自己打自己**；
2. 2026-10-18 修账（E-157／E-159）：编号、交叉引用、"已并/未并"的 commit 短号全靠手写，**没有任何机器校验**。

人工扫一次的代价是半小时以上，而且扫完下一次还会漂。本批只做机器能判的那几条，**不重写任何账**。

## 1. 交付三件

### A 段（主体）· `tools/check-doc-ledger.py`

纯 Python 3 标准库（**零新增依赖**，与既有 `tools/check-*.py` 同款）。默认只报告、退出码 0；`--strict` 有发现即退出码 1。

五条检查（每条都要能指名 **文件:行号** 与人话原因）：

| 编号 | 检查 | 判据 |
| --- | --- | --- |
| D1 | ERRATA 的 E 号**唯一** | `docs/ERRATA.md` 里所有 `## E-1xx` / `### E-1xx` 标题，重复即报 |
| D2 | E 号**无空洞** | 最小号到最大号之间必须连续（缺号＝有人删了行或跳号，要报出来让人解释） |
| D3 | **引用可查** | 全仓 `docs/**/*.md` 里出现的 `E-1xx` 引用，都必须能在 ERRATA 找到对应标题（例外见 D5） |
| D4 | **commit 短号可达** | 台账 `§B-交付记录` 与派工单里出现的 7–40 位十六进制短号，`git cat-file -e <sha>^{commit}` 必须成功（**只查 git 里真有的**，不联网） |
| D5 | **例外要留痕** | 已知不查的引用／不连续的号，一律写进 `tools/doc-ledger-allowlist.txt`，一行一条 `判据-具体值 # 理由`；**allowlist 里的条目若已经不再触发，也要报**（否则烂账永远清不掉） |

补充硬要求：

- 只读：脚本**不许**改任何文件（没有 `--fix`，不要做自动修）；
- 输出前缀固定（方便 CI 摘）：`[doc-ledger] <判据> <文件>:<行> <原因>`；
- 结尾一行汇总：`[doc-ledger] 检查 D1–D5：N 条发现`；
- 路径一律用**正斜杠**（E-027 的教训：Windows 反斜杠会污染输出与正则）。

### B 段（必做）· 接进 CI

`.github/workflows/ci.yml` 里 **紧挨既有的 `check-native-so.py` / `check-so-provenance.py` 那两个步**加一步：


### C 段（必做）· 首跑如实报

- 在 `main` 上先跑一次 `--strict`，把**首跑的真实发现条数**写进报告；
- 首跑若有存量问题：**照实报，不许为了让门禁变绿去改 docs/**（那些账是我的，本批一个字都不许改）；
  允许的处理只有两种 —— ① 确有存量、且我事后认可 ⇒ 临时进 allowlist 并说明；② 我改账 ⇒ 门禁自然变绿。
- **不许放宽判据**（例如"E 号允许不连续"）来换绿色。

## 2. 红线（碰了即返工）
