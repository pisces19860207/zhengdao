## 1. P1-1 · 流式回答期间点停止不被检查

**现状**：`RunEngine.kt` 的 `RoundOutcome.Text` 分支（`is RoundOutcome.Text ->`，约 `:857`）直接 `persistUsage` → 收尾闸 → `persistAssistantMessage` → `settle(..., RunState.DONE, "Done")`；`stopRequested` 只在循环头 `:777` 与工具批 `:909` 检查。⇒ 用户在流式回答时点停止，回答照出、日志记「正常完成」。

**改法**：在 `Text` 分支**第一行**先判 `stopRequested`：
- 为真 ⇒ **不记 DONE**；`settle(sessionId, stepCount, RunState.ABORTED, "Aborted")` 并 `return`；
- 已收到的正文可以保留（推荐 `persistAssistantMessage` 后 ABORTED，让用户不丢已出的字）或不落库——二者选一，在报告里写清；**不许**再走 `emitLearnCardIfDue()` / 计划未勾提示 / `settle(DONE)`。
- 边界如实写：真正「中途掐断网络流」在 §B 78 P2-5（`LlmClient` 的 Call 取消），不在本单；本单只保证**状态与日志不撒谎**。

**测试**：源码门禁——`Text` 分支内 `stopRequested` 检查必须在 `settle(...DONE)` 之前；负例删掉检查 ⇒ 红。若能把「收到 Text 且 stopRequested」抽成纯函数并测更好。

## 2. P1-2 · 坏 JSON/坏参数走「网络失败」通道，整轮中止

**现状**：`streamRound` 里 `is ToolCallCodec.DecodeResult.Bad -> RoundOutcome.Failed(decoded.error)`（约 `:1164`）；`Failed` 分支会 `consecutiveChannelFailures++`、可能切通道/熔断并 `settle(ABORTED)`。⇒ 模型一次参数错就把整轮判成通道坏，三次还熔断。

**改法**：
- 新增 `RoundOutcome.BadArgs(val error: String, val text: String = "")`（或等价），`DecodeResult.Bad` 返回它，**不要**再复用 `Failed`。
- 循环里单开分支：
  - **不** `consecutiveChannelFailures++`、**不**切通道、**不**熔断；
  - 把错误原文**回灌进历史**（例如 `HistoryMessage(ROLE_ASSISTANT, "工具调用参数不是合法 JSON：…；请修正参数后重试")`），让模型下一轮能改；
  - **同一步重试最多 1 次**（新增常量或复用现有计数，别死循环）；第二次仍坏 ⇒ 如实收尾（`ABORTED` + 一句人话），不谎称 DONE；
  - 该轮 `usage` 若拿得到，照常 `persistUsage`。
- 判据：模型坏参数一次不再导致「整轮中止/通道熔断」；错误对模型可见、对用户可见（notice 或落库）。

**测试**：`ToolCallCodec` 的 Bad 分类有纯函数/现有测试可加；循环层至少加源码门禁（`BadArgs` 分支不得出现 `consecutiveChannelFailures++` / `channelDecision` / `settle(...DONE)`）＋ 一条假事件驱动的行为用例（若现有测试基建允许）。负例：把 `BadArgs` 改回 `Failed` ⇒ 红。

## 3. P1-3 · 换通道 `continue` 仍会 `stepCount++`

**现状**：`RUN` 循环头 `:803` 每圈 `stepCount++`；换通道分支 `:989` 注释写「重跑同一步，不涨步数」，但 `continue` 回到 `:777` 后会再执行 `:803` ⇒ 每次换通道白烧一步预算。

**改法**：加一个 `var reuseStep = false`：
- 循环头：`if (reuseStep) reuseStep = false else stepCount++`（并同步 `_step.value`/`persistStep` 的取值）；
- 只在换通道分支置 `reuseStep = true` 后 `continue`；
- 其他 `continue`（收尾闸重跑等）保持原语义，别顺手改。
- 注意 `persistStep(sessionId, stepCount, "Switched", …)` 仍用当前步，不要写成新步。

**测试**：源码门禁——换通道分支必须置 `reuseStep` 且循环头有对应分支；行为级：假通道连续失败两次，断言最终 `stepCount` 不因换通道额外增加（若引擎测试成本高，至少做纯函数/源码门禁并说明）。负例：删掉 `reuseStep` ⇒ 红。
