## 0. 一句话

第十九批给了「封卷时提炼一句索引」，但技能正文**只能靠用户手动放文件**。本批让抱朴**能自己写技能**（走确认卡、写前备份、可回滚），并把**评测闸门**从「建好从没拦住人」变成「真拦」。这两件是 L2.5 的地基：**先会写，先拦住写坏的**。

## 2. 规格

### 2.1 技能可新建 / 可编辑（A 段）

1. **写入口只有一个**：新建 `baopu/SkillStore.kt`（房型照 `PersonaFiles`），只做三件事：
   `writeSkill(scope, name, body)` / `readSkill(scope, name)` / `deleteSkill(scope, name)`。
   - **写前备份**：同名文件先复制成 `<名>.SKILL.md.bak-<时间戳>` 再写（与 `write_file` 的 `.baopu-bak` 同口径）；
   - **不删**：`deleteSkill` 本批**不许实现**（删除永远手动，第十九批 §2.5 口径不变）；
   - **落点**：沿用 `SkillRules.projectSkillDir/globalSkillDir`，**不许**另起目录。
2. **必过确认卡**：写技能走 `PersonaProposal` 之外的**新提案形态**（正文是文件，不是人设行）——
   建议 `SkillProposal(scope, name, body, reason)`，确认卡上显示：**技能名／落点（全局/项目）／正文前 200 字／字数／备份文件名**；用户点「保存」才落盘。
3. **人给人看**：写完立刻把索引行一并提案（复用 `SkillRules.addIndexLine`），**索引与正文是一件事**，不许只写文件不写索引（那样模型读不到它）。
4. **回滚**：设置页技能卡每行加「恢复到上一版」（用 `.bak-*`），恢复也要确认卡。

### 2.2 技能试用期（A 段附带，3 次）

- 技能文件头加一行元数据（**纯注释行，不改格式**）：`<!-- status=draft uses=0 -->`；
- 草稿技能**不进人设索引**（模型默认看不到），只在设置页可见，标注「草稿」；
- 每次用户手动用它（设置页「用这次」按钮）或抱朴在确认后使用一次 ⇒ `uses+1`；
- `uses >= 3` ⇒ 设置页出现「转正」按钮；转正＝把索引行提案进人设（第十九批同一条路）。

### 2.3 评测闸门机制化（B 段）

1. `EvalGateTest` 改成**两态**：有 key ⇒ 真跑 10 例；**没有 key ⇒ 显式跳过（`Assume`）并在报告里标注「本次未跑闸门」**，不许静默通过。
2. **构建面接入**：改 `app/build.gradle.kts`? **不行**（红线）⇒ 换个法子：新增一个**只读校验任务**的替代方案——
   `tools/check-skill-proposals.py`（仓库根 `tools/` 已有先例）检查「本次改动是否碰了 `eval/baseline.json` 或删了用例」，
   由 CI workflow 调；本地则由 `docs` 里写死的**提交前人工清单**兜底。**CI workflow 的改动在本批白名单内**（`.github/workflows/*`）。
3. **不许**为了让闸门绿而改 `eval/baseline.json`（这条写成判据）。

### 2.4 平台机制归纳（C 段 · **只立骨架，不做完整闭环**）

用户想的是「抱朴自己摸索风月AI 这类平台的填写方式并写成技能」。本批**只做骨架**，因为完整闭环依赖玄览读页（刀 4）＋视觉通道：

- 新增**一种技能类型**：`平台机制`。正文固定四段：
  1. **平台/页面**（URL ＋ 抓取时间）
  2. **字段清单**（字段名 ＝ 页面上的字面文案 ／ 类型 ／ 必填否 ／ 取值样例）
  3. **实测状态**：每条字段标 `已实测` 或 `未实测·推断`（**推断必须带验证方法**）
  4. **殊途同归**：这张平台与已记录平台的**同构字段**（例：两个平台的「前置词/提示词」是同一个东西）
- **不许编**：字段名必须来自页面原文（`browser_snapshot` 的可见文字）或用户口述；抓不到的写「未获取」。
- C 段只交：这种技能类型的**模板 + 校验器**（缺段/缺实测标注 ⇒ 拒绝保存）＋ 一个**手写样例**
  （把今天讨论的「风月AI 配置页五件套」写进去，作为第一条平台机制技能）。
