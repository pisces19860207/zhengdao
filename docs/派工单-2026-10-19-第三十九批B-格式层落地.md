## 0. 这张单要交什么

照 A 段规格把三件事落成纯逻辑 Kotlin，并接线两个工具：

1. `CardFormat`：认脸（判定＋依据＋置信度；PNG 时解出内嵌 JSON）
2. `CardCheck`：体检（字段级 ＋ 三条语义级）
3. `CardPng`：导出／读回（`chara`/`ccv3` tEXt 块，`java.util.zip.CRC32` ＋ `java.util.Base64` 零依赖）
4. 工具接线：`card_inspect`（**FREE**，只读）／`card_export`（**CONFIRM**，不覆盖）

**不做**：三套互转、任何渲染/预览（玄览是另一条线）、改用户样本。

## 1. 实现要求（照规格，逐条对齐）

- 三件都是**纯函数/纯逻辑**：`baopu/card/` 下新增 3–4 个文件；**零第三方依赖**（只许 JDK 的 `java.util.zip` / `java.util.Base64` / `javax.imageio`）。
- **正文/数据只有一个真相**：认脸结果、体检输入、导出的 JSON 都走同一个数据类；**不许**为读/写各拼一份。
- 认脸：先 PNG 签名，再 JSON 顶层键；判不出 ⇒ 「未知」＋看过的键名清单（前 20），**不许猜**。
- 风月省略 `value_type`/`value_configs` ⇒ 补 `0`/`[]`，不得因此报缺字段。
- 体检：字段级与语义级分开输出；每条带**条号/字段/一句话证据**；没给系统文本 ⇒ `未判`，**不许报 0**。
- PNG：块顺序、`tEXt` 布局、CRC（类型+数据，不含长度）按规格写；**往返逐字**是硬判据；导出**绝不覆盖**源图。
- 工具：`card_inspect` 源码里不许有 `writeText`/`delete`/`renameTo`；`card_export` 无覆盖路径；两个 `description` 都说清「只读」「不覆盖」；注册进 `ToolRegistry` 后**工具总数会变**，`ToolRegistrySwitchTest` 计数同步改。

## 2.1 追加判据 F12–F16（2026-10-19 蓝总管实测 27 张 Tavo 卡 ＋ 4 张酒馆 PNG 后追加）

> 来源：`Tavo MCP` 逐张 `character_get` 聚合 ＋ 本机 4 张酒馆 PNG 逐块解析（只统计结构，未取内容）。
> 完整读数见台账 `#119`。这两套卡的 `extensions` 里都长期躺着酒馆生态的字段，**丢了不会报错，只会「看起来一样、打开不一样」**。

| 编号 | 判据 |
|---|---|
| **F12** | `extensions.world`（字符串，酒馆与 Tavo 都有）指向的世界书**能不能对上**：Tavo 用资产名精确比对；酒馆没有名册 ⇒ 标「未判」。对不上报「世界书链接可能失效」，**不擅自改**。 |
| **F13** | `extensions.regex_scripts`（酒馆与 Tavo 都有）与**独立 regex 资产**比对：`findRegex`＋`replaceString` 都相同 ⇒ 报「重复」；`scriptName` 相同但内容不同 ⇒ 报「同名不同体」。 |
| **F14** | `extensions.tavo.theme`（**仅 Tavo**）：卡内自带一份主题快照（含 `display_mode`/`bubble_display_type`/`status_bar`/`spec`）。与会话当前主题不同 ⇒ 报**信息级**提示「这张卡自带外观」；`spec` 缺失/认不出 ⇒ 忽略该子项并告知，**不许当错误拦下**。 |
| **F15** | 酒馆 PNG 的**双包装**：老 v2 顶层字段（实测 `avatar/chat/create_date/creatorcomment/description/…`）与 v3 的 `data` **并存**。读取一律取 `data`；**写回时顶层键集合必须原样保留**（往返判据扩展到顶层键）。 |
| **F16** | 酒馆 PNG **内嵌 `character_book`**（实测 3/4 张有）与外部世界书同名 ⇒ 报冲突并列出两边的 `name`，不自动合并、不自动覆盖。 |

**类型宽容（不是可选项）**：实测 `talkativeness` 有 **float 与 str 两种**（酒馆卡 float×1／str×3；Tavo 全是 str `"0.5"`）、`delayUntilRecursion` 有 **bool 与 int 两种** ⇒ 解析器**不许按单一类型断言**，未知类型按「原样保留＋体检提示」处理。

**无损铁律**：`extensions` 里**认不出的键一律原样保留**（读→改→写不许重建对象）；这条比上面五条判据都重要——它是「往返不丢东西」的根。

### 2.2 追加判据 F17–F18（CCv3 独立 Lorebook／CHARX；规格 §12）

| 编号 | 判据 |
|---|---|
| **F17** | `{spec:'lorebook_v3', data:{entries:[{keys…}]}}` 与「裸 Lorebook（顶层直接 `entries:[{keys…}]`）」都要判成 **CCv3 Lorebook**——**不得**判成 Tavo 世界书（两者都是 `entries` 数组，靠元素字段区分：`keys/enabled/insertion_order` vs `keywords/content/injectionPosition`）。 |

### 2.3 追加判据 F19–F20（统一内部模型；规格 §14）

规格 §14 给了族谱与最小内部模型（**卡与正则同源；世界书是三条血统＋CCv3 交换格式；风月没有卡，走 `FengyueWork`**）。B 段照它实现：

| 编号 | 判据 |
|---|---|
| **F19** | 解析结果必须携带来源血统（`vendor`/`dialect`）与原始 `raw`；同一输入两次解析得到相同血统（确定性）。风月内容**不许**塞进 `Card` 类型。 |
| **F20** | 写回**只写原文件本来有的字段**；`raw` 里存在但内部模型不认识的键必须原样回写（round-trip 后 JSON 键集合不变；ST 的 `disable` 不许被写成 `enabled`）。 |

**负例追加**：把 ST `disable` 统一成 `enabled` 后写回 ⇒ F20 红；把风月世界书当 `Card` 解析 ⇒ F19 红。

### 2.4 追加判据 F21–F22（命名／激活策略／关键词语法；规格 §15）

**命名硬规定**：代码与判据文本里一律用 **`WEB`**，不写平台名（平台是灰色地带，不锚死一家）；枚举写 `WorldbookDialect.WEB`。

| 编号 | 判据 |
|---|---|
| **F21** | `WEB` 关键词语法：全角分隔符、分隔符旁空格、空 token、首尾残留、`_or_`/`_and_` 混用、整串含分隔符字形却未切分 ⇒ 报 `KEYSEP_BROKEN`（严重）并计入 **C 类（永不触发）**；报告里回显切分出的 token 列表。 |
| **F22** | 激活策略按 dialect 判：`constant`／`probability`／`sticky·cooldown·delay`／`match*`／`group*` **只在该 dialect 存在时才检查**；拿 A 家的字段判 B 家 ⇒ 直接红。 |
